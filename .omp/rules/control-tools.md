## OMPdesk control tools

### Overview and safety
- Switch: Settings › Tools & extensions › OMPdesk control tools, pref `agentControl`, default **on**. Contract `src/shared/agent-control.ts`, schemas `tools.ts`, app seam `host.ts`, skill `resources/omp-builtin/skills/ompdesk/SKILL.md`.
- **Where the service lives (batch H3/H4a, 9g–9k)**: the rules and tool bodies run in the Rust core (`native/ompdesk/crates/core/src/agentctl/`: `service/` the tools, `journal/` the files, `rules/` mail, custody, pickup, auto-close and tab-close, `runtime/` what the host did over the service's own state, `app/` `ompdesk_app`). Every later bullet that names `service.ts`, a `#method`, or a file of the old TypeScript service (the journals, the mail, custody, pickup, auto-close and tab-close rules, `ompdesk_app`'s catalog, settings, guard, channels and schema) means the Rust module named beside it (the TypeScript twins are deleted; `#method` names are the Rust functions' snake_case names, `agentctl/service/{sessions,messages,work}*`). One close rule: `rules/tab_close.rs` decides every agent close, and main's release only asks again whether the page now holds unsaved Files edits. `app-control-test-rig.ts` is the TypeScript `AppControl` kept as the parity rig of `app-control.test.ts` (no production caller). `service.ts` is main's seam and typed client: `AgentControlHost` (what the core asks of main, and the snapshot it reads: the open tabs and their windows, the switches, summaries, who opened what, tombstones, the language's texts) and `AgentControl` (one `agentControl.open|call|close` instance over a `CorePort`; a core that started again is opened again by the next call). Main pushes the snapshot when it observes a change (the pool's activity, the preferences, summaries, deleted sessions, outside callers) and before every call; every answer carries it. `host.ts` keeps what reads the pool, windows, preferences, the remote link or Electron: the snapshot builder, the spawn, git, cards, schedules and app ports as the core's asks. **The runtime** (`runtime/`, opened with the service when `host.runtime` is given; `AgentControlHostDeps.sweepMs`) owns the sweep of the opened sessions (`SWEEP_*`: one `autoClose` pass 1 s after activity, every 10 s for every opener), the work board's review settle and push (`REVIEW_SETTLE_MS` 400 ms; main sends the frames to the windows), the redelivery of reports (`mail-outbox`) and messages still owed, and a routine's wake-up (`wakeSession`: main reaches the session, the core keeps the mail and follows the turn). Tests: `service.test.ts` and `host.test.ts` run against the real core (their waits are shortened through `tuning`, as the TypeScript tests moved fake timers); the Rust modules carry the pure rules' tables captured from the TypeScript.
- **Full control** (the user's decision): Settings › Tools & extensions, first row "Give agents full control of OMPdesk" / "에이전트에게 OMPdesk 모든 권한", pref `agentControlFull` (`AGENT_CONTROL_FULL_PREF`), default **on** (`agentControlFullEnabled`: only a stored `false` is off). While on, **no control tool or app action raises an `[OMPdesk]` card**: the `always` set (deletes, MCP/plugin install, sign-in starts, proxy, mobile web on, pairing, update apply, quit), a foreign session delete, Autopilot release or main targets, every power pref. It implies `agentControlApprove` and `agentControlManage` (`host.ts` resolves both as `full || stored`; their Settings rows show checked and disabled). The catalog action `agent_power.set` (`fullOnly`; `FULL_CONTROL_PREFS`/`FULL_CONTROL_SETTINGS` in `agentctl/app/guard.rs`, the terminal-omp wiring through ai-memory's own channel; memory and learning have no switch) lets an agent change the agent-power switches, this one included. Every action is still journaled and toasted with undo where one exists. Kept whatever it says: an agent never answers an `[OMPdesk]` card, secrets/tokens/passwords are never readable, git safety (no force push, Autopilot's guard bans destructive git), OS security prompts (UAC, TCC). Its tooltip names the risk (prompt-injected content can make an agent delete data or install code). **Every card rule below applies only while full control is off.** Pinned by `shared/agent-control.test.ts`, `app-control.test.ts` (`always` actions card-free when on, `agent_power.set` refused when off), `service.test.ts`, `host.test.ts`, `AgentControlRow.test.tsx`, and the on/off cases of `e2e/agent-app-control.e2e.ts`, `e2e/agent-control.e2e.ts`, `e2e/agent-review.e2e.ts`.
- **Every power on by default, no setup** (the user's decision). The switches `agent_power.set` exposes all resolve on while unset: `agentControl`, `agentControlFull`, `agentControlManage`, `agentControlApprove`, `pstack`, `ecc`, stock `computer.enabled` (OMPdesk's held default on, `.omp/rules/models-accounts.md` Held stock defaults) and stock `tools.approvalMode` (stock's default `yolo` already means no approval card; no held default, since Autopilot's own `yolo` override would clear one). Only a stored `false` (or another mode) is off, so a person's opt-out is kept.
  - **One-time migration for existing installs** (`src/main/agent-power-migration.ts`, run from `prefsStore()` in `index.ts` right after `migrateRetiredPrefs`, before any window or omp starts): pref `agentPowersMigrated` holds the version that ran (`AGENT_POWERS_MIGRATION_VERSION`, 1). Per-call cards for consequential actions stay when full control is off (the `always` set, a foreign delete, release or main targets); `credentials.read` and `cards.answer` stay `never`.

Once every permission is granted or asked, focus events spawn nothing (`#settled`). The retired `macPermissionsAsked` is deleted. - **Subagents have no control tools** (stock registers host tools on the RPC session only; `host_tool_call` carries no caller id). `e2e/real-agent-control.e2e.ts` checks it (`NO_TOOL`, no tab opens). A subagent can run the `ompdesk` CLI through bash and then acts as an outside caller, under the same rules and cards.
- **No count or rate caps** (the user's rule; none in `src/main/agent-control`): any number of sessions, messages, schedules and Autopilot runs. Only a self-send is refused. Provenance ("opened by you") is main-owned state, never read from text or tool args; it survives a relaunch (`#openedBy` adds every tab whose `host.parentOf` is the caller: the pool's `openedBy`, else the tab holding `openedBySession`).
- Session tools touch no accounts, settings or permissions. **Deleting a saved session the caller did not open** (`ompdesk_session_stop delete:true`) always raises one confirmation card (stock extension-UI `confirm` via the calling tab's omp, bridge `agent_control.confirm`, title prefix `[OMPdesk]`, so it survives a reload and reaches a paired device), whatever "Let agents manage other sessions" says, because a delete cannot be undone. Stopping or closing a session it did not open raises the same card only while that switch (`agentControlManage`, **default on**: `agentControlManageEnabled` in `shared/agent-control.ts`, only a stored `false` is off) is off. Sessions it opened itself need none, delete included.
- Closing a resting session's tab (not busy, no open ask, not in the person's view, no draft or prompt of theirs since: `ControlTab.looked`/`userTouched`) raises no card whoever opened it. Each close is journaled as one quiet `ompdesk.mail` note in both sessions **only once the tab is confirmed gone** (`#journalClose` runs after `close_tab` (`agentctl/service/sessions/stop.rs`)/`#deleteWhenIdle` returned), so a kept or held-back close sends no "Closed" note. The closed session's own line is best effort (its omp has exited).
- **A session the person typed into, or one the caller did not open that is in the person's view, is stopped, closed or deleted only in a turn the person's own message started**, so an agent never does it on its own initiative while a person's typed request still can. **A session the caller opened is never held back because the person looks at it** (the owner's rule): stop, close and delete go through in any turn, and none is kept as a pending cleanup; one the person typed into keeps the rule, since their own words are in it. One predicate decides, `needs_person_turn(tab, own)` in `agentctl/rules/tab_close.rs` (`userTouched`, or `looked` and not `own`): `#stop` applies it before the card and again right before the close or delete, and `tab_close_step` applies it to a close nobody cleared (auto-close, a failed open's cleanup, Autopilot's source tab). The auto-close pass is no caller's request and still keeps a tab the person looks at (`auto_close_decision` `looked-at`, the renderer's `autoCloseHeld`) until a later pass finds it unseen. It decides from turn provenance, never text: `AgentControl::stop` asks the caller's omp (`agent_control_turn` → bridge `agent_control.turn`, `resources/gui-bridge/turn-origin.ts`) whether the main agent's current run was started by a prompt main said a person typed (`typed_prompt`: a window's or the phone page's prompt in `ipc.ts`, a paired device's in `remote/host-services.ts`; never an agent's wrapped message, Autopilot's prompts, a schedule or a relaunch's continuation). The bridge reads it at the run's start (prompt messages between `agent_start` and the first answer): a user message whose whole text a typed note names makes it the person's, a report mail that wakes the session does not, a run with no prompt (stock's retry) keeps the one before, a steer or follow-up never changes it. Refused otherwise for stop, close and delete, with the reason in the error; an outside caller, an omp that cannot answer and a failed request count as not the person's. A close `#stop` let through also releases a paired web page's tab the person is at (`tab_close_step(tab, cleared)`); unsaved Files edits still keep it. Pinned by "in a turn the user's own message did not start" (own and looked, own and typed, not own and looked) and the person/agent-turn cases in `service.test.ts`, `bridge-turn-origin.test.ts` and `bridge-turn-origin-stock.test.ts`.
- **A refused cleanup is kept and told once**, so finished sessions do not stay open unnoticed; the rule above is unchanged. `#refuseInUse` (the one refusal for stop, close and delete, re-checks included) adds the call to `PendingCleanups` (`agentctl/journal/pending_cleanups.rs`, `<userData>/agent-pending-cleanups.json`, newest 200): caller (its session file), target session file and tab id, action, time. A caller that is no tab (the control socket) keeps nothing. When main hears the person typed a prompt to the caller (`ipc.ts`: the IPC channel and `personsPrompt`, the same word `noteTypedPrompt` goes by; never the text) and the caller runs no turn, `AgentControl.personTyped` takes its list and sends one quiet `ompdesk.mail` note (`triggerTurn: false`, so it is in context ahead of that prompt's turn) with the exact `ompdesk_session_stop` call per entry; entries whose tab closed since (unless a delete of a still-saved session was asked) or whose call later went through (`#stop` drops it) are left out. A prompt joining a running turn starts none, so the list waits; a note the omp could not take puts the list back. Told once, never nagged; a call refused again is kept again. Pinned by "a cleanup refused while the person was in the session" in `service.test.ts`.
- **Arguments written as JSON text are read as what they spell**. `looseArgs` (`tools.ts`, run by `#dispatch` before the strict `ARGS` parse, for every tool and nesting) walks the tool's JSON schema: where a field takes no string, a string spelling a boolean, a number, or object/array JSON becomes that value; a text field keeps it, and text that spells nothing the field takes still fails. An invalid-arguments error names each field's path. `reopen` with `folder` is refused only when the folder differs from the one the session worked in (`folderKey`). Pinned by "arguments a model wrote as JSON text" in `tools.test.ts` and the open case in `service.test.ts`.
- **A bound the parser enforces is in the schema.** `maximum`/`minimum`/`maxLength` sit on the JSON schema property, and the description says the number. Pinned by "the schema states the bounds the parser enforces" in `tools.test.ts`.
- **A stale `before` cursor restarts from the newest page** (`#read`, `#readStored`): a live tab's cursor is stale once the session wrote one more message (`stale_cursor`, `local/sessions.ts`), and a saved read's index is none of a live tab's (and the reverse). Either read answers its newest page with one line saying the cursor named no current page. Pinned by "answers a cursor the session has outgrown" in `service.test.ts`.

### Memory and idle release
- **No agent work ever waits for memory** (the owner's order). There is no memory admission: an agent's open or message, a scheduled run or wake and a relaunch's continuation start at once, on every computer. A paired older host's `memoryWait` tab event is not in `TabEventMessage`, so `devices.ts` drops it unread; an older device's `tab.startNow`, `tab.memoryWaitedOn` or `host.memory.status` gets the unknown-method answer, which it reads as an older host. Agent processes run at lower scheduling priority (`agent-priority.ts`, nice +10 / BELOW_NORMAL, inherited by their children).
- **The memory watch** (`src/main/memory-watch.ts`, started in `index.ts`) reads every `SAMPLE_MS` = 5 s, only for idle release: the OS's reading and the process list, both read by the core process (`native/ompdesk/crates/core/src/memory/`, methods `memory.reading` and `memory.processes`; `memory-sampler.ts` is their client and counts a failed or late answer, `SAMPLE_TIMEOUT_MS` = 4 s, as no sample). macOS: one `sysctl` for `kern.memorystatus_vm_pressure_level` and `kern.memorystatus_level` % of `hw.memsize`, and one `ps -axo pid=,ppid=,rss=`. Windows: `GlobalMemoryStatusEx`'s available physical memory, warn/critical under 10 %/5 % of RAM, and a Toolhelp32 snapshot with each process's `K32GetProcessMemoryInfo` working set (`crates/core/src/sys.rs`; no WMI). A test launch reads `OMP_GUI_TEST_MEMORY` (JSON file: totalGb, availableGb, pressure) every `OMP_GUI_TEST_MEMORY_MS` instead; a Playwright launch without one reads ample memory.
- **A quiet session gives its omp back while memory is short** (`src/main/idle-release.ts`; the owner's goal: many sessions without weight, no slower and nothing lost). The memory watch asks it each sample; it acts only while the OS reports memory short **now** (pressure warn or critical, or under `RESERVE_FRACTION` = 15 % of RAM available; never a growth prediction, which would release sessions with memory free), so while memory is fine no session waits for its omp to restart. A tab may go when the pool reads it quiet (`SidecarPool.#quiet`: this computer's own ready tab on a saved session, shown in no window, split pane or device, opened by the person (an agent's child closes by itself); no turn, compaction, ask, plan, draft, retry, continuation, sign-in or pending restart) and its omp has started no process (an eval worker holds eval state; a job, daemon or MCP server is live), continuously for `IDLE_RELEASE_QUIET_MS` (5 min); the largest tree goes first, one per sample. `SidecarPool.releaseIdle` checks again, asks stock's `isSettled` (no queue, background job or delivery that could wake it), checks once more, then `SidecarManager.sleep()` stops the omp as a restart does and the tab reads `asleep`: it starts again on its session file when shown or messaged, as a restored tab does, rows painted from the tab's transcript snapshot meanwhile; a prompt sent while it starts waits for ready (`installTabReadyGate`). One `memory release` line in `gui-runtime.jsonl` per release (`memory release kept` when the pool's checks refused). Tests: `idle-release.test.ts`, `sidecar-pool.test.ts` "SidecarPool releaseIdle", `e2e/idle-release.e2e.ts` (fake omp: kept while fine, released when short, a shown tab and one with a working background subagent kept, a sidebar click shows its rows within 1 s and the same transcript after restart, a next turn answers).
- **On Windows the tab's pid is a launcher, not the omp**: `SidecarManager` spawns bun's `omp.exe` shim, or cmd.exe for an `omp.cmd`, whose children are `conhost.exe` and the omp (`bun.exe … cli.js`). "Its omp has started no process" therefore reads the launcher's one child besides the console host as the omp and counts that omp's children; a console host (`conhost.exe`, the image name `memory.processes` reads from `szExeFile`) never counts, and a launcher of any other shape (no omp under it, or two) reads busy. Counting the launcher's own children would keep every Windows tab from release. macOS spawns the omp itself (`ps` names no images). Pinned by the Windows case of `idle-release.test.ts` and `e2e/idle-release.e2e.ts` on Windows.
- **What a session costs** is measured with `bun scripts/session-footprint.ts run --fake 20 --real 3` (opt-in spec `e2e/session-footprint.e2e.ts`: built app, macOS `phys_footprint` of every process under main, CPU per window, REA's answer cache seeded). Rough baseline: app fixed cost about 510 MB and about 2 % of a core idle (the extensions worker exits 60 s after its last answer); each real session one omp of about 255–280 MB fresh, growing with its transcript, plus what it starts (an eval worker per session, a daemon broker shared per project); main and the renderer add under 1 MB per open tab; an omp reads ready in about 1.5 s (real), 60 ms (fake).
- **Who uses the memory is written down when it runs short** (the owner's report, 12 Nov 2026: the 16 GB Mac mini froze and `gui-runtime.jsonl` held no line that said what had filled it). As a sample reads memory short (idle release's own `memoryShort`), and every `RECORD_EVERY_MS` (5 min) while it stays short (`RecordClock`), the watch writes one `memory short` line (source `memory`; `recordShort` in `memory-watch.ts`, the rules pure in `memory-record.ts`): the reading, `top` (the `RECORD_TOP_PROCESSES` = 8 largest processes: name, pid, MB, age in minutes, whose) and `sessions` (the `RECORD_TOP_SESSIONS` = 6 sessions that hold the most: title, folder, the device it runs for, MB, process count), both JSON text because the log keeps only primitive details, and `sessionsMb`, `ompdeskMb`, `otherMb`. Whose a process is (`processOwners`): the session whose tag it carries (Session processes, below), else the tab whose omp it runs under (a parent that started after its child is a reused pid and is not followed), else OMPdesk when it runs under main, else `closed session` for a tag no open tab holds (a session that is gone, or another OMPdesk's), else `not OMPdesk's`. Never a full process list and never a command line (arguments hold tokens). No screen shows it: this section has no memory surface, and the owner asked for the record. Pinned by `memory-record.test.ts` and the short step of `e2e/session-processes.e2e.ts`.

### Session processes
- **The owner's report (12 Nov 2026)**: work done through OMPdesk on the Mac mini (16 GB, hosting other computers' sessions) left `next dev` servers, Playwright's browser, an Android emulator and an `adb` daemon running until the machine froze. The user's rule: **a computer does not fill up with what finished work left behind**, and a session's processes live as long as its tab.
- **Whose process it is** (`src/main/session-processes.ts` `SessionProcesses`, one per app in `index.ts`, handed to every `SidecarManager` through `sidecar-factory.ts`): a tab's first spawn makes its tag (16 random bytes as hex), kept for every later omp of that tab (a restart, a crash, a wake after idle release) and set as `OMP_GUI_SESSION_TAG` (`SESSION_TAG_ENV`, in `sessionEnv` and `SESSION_OWNED_ENV`, so a tag inherited from another OMPdesk session's shell is never passed on). Whatever the omp starts inherits it, however deep, and keeps it once its parent is gone (a daemon, a double fork, `nohup`, `&`). The tags are kept in `<userData>/session-processes.json` (0600; tag, folder, session file, the device a hosted tab runs for), parsed with zod, and **only a tag in that file is ever ended**.
- **Read back and ended by the core** (`native/ompdesk/crates/core/src/procs/`, native-rust › 3d): `procs.list {env}` answers every process with pid, parent, resident bytes, start, image name and the tag in its environment; `procs.end {env, tags, keepArg, graceMs, timeoutMs}` ends what carries one of the tags. macOS reads `sysctl KERN_PROCARGS2` (the arguments and environment a process was started with), Windows the process's own environment block through its PEB (`NtQueryInformationProcess`, `ReadProcessMemory`), Linux `/proc/<pid>/environ`. Asked first, then killed: SIGTERM, `END_GRACE_MS` (5 s), SIGKILL; on Windows `WM_CLOSE` to each top-level window a target owns (never a console's window, which would end every program on that console), the grace only for those asked, then `TerminateProcess`. It scans again after each round, at most 5, because a supervisor starts its child again. The pid is checked at the point of risk: Unix reads the pid's tag again right before each signal; Windows terminates through the handle it read the environment through, so a reused pid is never hit.
- **When they end**:
  - **The tab is released** (the person's close, an agent's `ompdesk_session_stop {close}` or `{delete}`, the auto-close of a finished child, a deleted session, a closed window, a paired device's close, a hosted tab whose grace ended): `SidecarManager.dispose` waits for the tab's omps to exit (so an omp's own cleanup of its tools comes first) and then closes its tag (`#endEntry`). A turn's Stop ends nothing: the tab is still open.
  - **A quit ends nothing** (`frozen: quitApproved`): tabs come back at the next launch and a "Restart to update" must not take every open session's dev server with it. The tags stay in the file.
  - **The next launch** (`sweep`, called in `index.ts` once the saved tabs exist): every tag in the file is one the last launch left. Kept: a session with a tab in the restored layouts (desktop and paired web pages) or a marker of interrupted work (`interrupted-turns.json`, read before `TurnResume.launch` drops what it settles); the tab that starts on that session takes the tag over (`open`), so the session's processes are its own again and end with it. Ended at once: every other tag, also one with no session file (a first turn that was never written starts over). This is the cleanup after a crash or a forced quit, where no close ran. A tag of a tab this computer ran for a paired device waits `HOST_TAB_GRACE_MS` (the device may be reconnecting) and ends then unless a hosted tab holds its session.
  - **A restored tab closed before it ever started** has no tag of its own: the pool's `released` activity ends what the last launch left for its session (`sessionReleased`).
  - **Idle release leaves them** (the owner's condition for it is "nothing lost"): it gives back only an omp with no child process, the tab stays open, and the omp that wakes carries the same tag. What a quiet session left running shows in the `memory short` line instead.
- **Never the wrong process**:
  - A process started outside OMPdesk, or by another OMPdesk (another `userData`: a dev or test app), carries no tag of this file.
  - A tab that is open keeps its processes: a tag is ended only once its tab is gone, and **a tag whose end is in flight is never handed out again** (a session reopened while its closed tab's leftovers go down gets a new tag; otherwise the core would kill the new omp). An end the core could not answer puts the tag back for the next launch. So does an end that left something running (a stock worker kept with what it started, a process that survived the kill): the tag stays in the file, is tried once more after `RETRY_REMAINING_MS` (60 s: a per-omp stock worker ends itself once its omp is gone, and what it started then carries the tag alone) if no tab took it over meanwhile, and after that at the next launch.
  - **Stock omp's own shared workers are stock's to end** (`STOCK_WORKER_ARG` `__omp_worker_`, sent as `keepArg`): a tagged process whose command line has an argument starting with it, and every live process under it, is never signalled. That is the project's service broker (`__omp_worker_daemon_broker`, started by the project's first omp with that omp's environment, so its services carry that tab's tag whoever asked for them): its services stop with the project's last omp, or stay while the person's `launch.persist` is on (models-accounts › Held stock defaults), as before. Also the other selectors of stock's `cli/worker-selectors.ts`: the LSP multiplexer, the blob broker, the embedding server, the updater.
  - A tag the app itself runs under (OMPdesk started from that session's shell) is refused whole by the core (`own`: the core or one of its ancestors carries it), and logged.
  - ai-memory's service is launchd's or the logon entry's, and its `setup` is started by main, isolated: neither is an omp's child, so neither carries a tag.
- **What it does not see**: a process that cleared its environment (`env -i`, `sudo`); a program the system started on the session's behalf instead of as its child (macOS `open`, a launchd job, a VM's XPC service: Docker Desktop's and the Android emulator's hypervisor helpers); on Windows a process this user may not read (elevated, protected) and one that removed the variable from its own live environment; scheduled `omp -p` runs, benchmarks and model setup, which carry no tag and end by themselves. **What it ends that a person may have come to use**: a program an agent's command started as a child is the session's, also a browser or editor (`start <url>`, `code .` on Windows, where the launch is a child; not on macOS, where `open` hands it to the system), and a daemon another session shares (`adb`, a Gradle daemon) goes with the tab that started it and starts again on its next use. Stock's own daily `omp gc --compress` carries the tag too and ends with the tab.
- **Cost**: nothing per sample: `procs.list` runs for the `memory short` line only, `procs.end` once per released tab and per tag the launch sweeps. One Windows listing with every environment read took 90 ms (median of 20, 608 processes, 406 readable, the machine at 99 % CPU from other work): 55 ms the snapshot and handles, 33 ms the environments. A session that left nothing writes no log line; one that did writes one `session-processes` line (`ended`: why, folder, session file, device, how many, how many had to be killed, MB, names; `left` when something survived the kill; `not ended` and `refused…` as warnings).
- **Rejected**: a Windows job object per session (main spawns the launcher through node, so a job could only be assigned afterwards by another process, racing the launcher's own children, and a job cannot be found again after a relaunch without a name); a walk down the omp's process tree (it loses exactly the re-parented processes the report was about); `ps -E` (it cannot tell an argument from an environment entry).
- **Model-checked** by `formal/session-processes` (TLC; `skill://session-processes-verify`): only a tag whose tab was closed outside a quit or whose session did not come back is ended, an open tab never has its processes ended, nothing is left in the file at rest, a tag with running processes is never forgotten. Pinned by `session-processes.test.ts` (real processes through the real core: a tagged tree with a re-parented grandchild found and ended, another tab's and an untagged process untouched, stock's worker kept, a quit and the takeover, the launch sweep; the reopen, failed-end, frozen, released and hosted-grace cases on held ends), the Rust tests of `procs/mod.rs` (the same on each OS, SIGTERM before SIGKILL, `keepArg`, `own`, the parsers), `omp-launch.test.ts` (the variable is session-owned) and `e2e/session-processes.e2e.ts` (the built app on the fake omp: a detached child ends with its closed tab, another tab's stays).

### Control socket and the `ompdesk` CLI
- **The user's decision (30 Oct 2026)**: anything running on this computer (a terminal omp, a shell script, another agent CLI such as Claude Code or Codex, a subagent through bash) drives OMPdesk the way OMPdesk's own agents do with the `ompdesk_*` tools. Modelled on Herdr's external control surface (https://herdr.dev, Apache-2.0): JSON lines on a per-user socket, server-owned waits, `agent_blocked`, `events_lost`. No Herdr code is copied, so `THIRD_PARTY_NOTICES.txt` is unchanged; copying any would need its Apache-2.0 attribution there (`bun run gen:licenses`).
- Files: wire contract `src/shared/control-protocol.ts`; CLI `native/ompdesk/crates/cli` (Rust, binary `ompdesk`, shipped as `extraResources` `ompdesk-bin`; build, staging and packaging: native-rust). Server `native/ompdesk/crates/core/src/control/`: `endpoint.rs` folder, token and endpoint file, `listen.rs` Unix socket and Windows named pipe, `conn.rs` framing and auth, `router.rs` methods and waits, `events.rs` event ring, `link.rs` asks to main. Main `src/main/control-socket/`: `endpoint.ts` synchronous path naming and typed folder/token clients, `server.ts` the core client and backend relay, `backend.ts` the seam to `AgentControlRuntime`, `index.ts` `startControlSocket` (called from `ipc.ts`), `cli-install.ts` launchers and `env.ts` per-spawn plumbing.
- **One service**: a `tool` request is `AgentControlRuntime.runOutside(caller, tool, args)` → `AgentControl.run`, the same rules, tiers and cards as a host tool call; `credentials.read` and `cards.answer` stay `never`. Pinned by "a caller outside OMPdesk" in `host.test.ts`.
- **The outside caller** (`OutsideCaller`, `host.ts`): id `outside:<name>#<connection>`, one per socket connection. The name (hello `caller`, `OMPDESK_CALLER`, `--caller`, `[a-z0-9_-]{1,32}`, default `cli`) is the process's own claim, never an identity: another process claiming it owns none of the first's sessions or reports. Title `outside process "<name>" (self-declared)`; cwd the CLI's folder. It has no tab: `AgentControlHost.outsideCaller` gives the service a stand-in `ControlTab` (never listed), it acts through the front desktop window (`outsideWindow` = `windowManager.getTargetWindow()`; none open refuses), and the sessions it opens are its own (`#parents`: stop/close need no card, their `ompdesk_report`s reach it as `report` events) but get no pool opener (they sit in the sidebar like the person's), no review list, no auto-close and no provenance after a relaunch (ids starting `outside:` are excluded wherever a tab opener is expected). A closed connection releases its caller (`releaseOutside`); its sessions stay open. Its cards are native `dialog.showMessageBox` over that window (`confirmOutside`, `[OMPdesk]` title, detail "Outside process: <name> (self-declared)" / "외부 프로세스: <name> (자체 표기)", `CARD_TIMEOUT_MS`, no answer = no), one at a time per caller (`#outsideCards`). Whatever goes through the caller's own omp (stock settings, models, usage, MCP app actions, the app action journal note) answers that an outside caller has none (`#hostCommand`).
- **Endpoint** (`control/endpoint.rs`): `<userData>/control/` (mode 0700, a real folder owned by this uid, else refused) holds `token` (32 bytes of OS randomness as 64 lowercase hex, 0600) and `endpoint.json` (`{version, socket, pid}`, 0600; `pid` is main's). The token survives close and is reused unless damaged or exposed: folder or file had group or other bits, or the file is another user's (`prepareControlDir` reports a repair, `readOrCreateToken({exposed})`). Entropy read failure refuses startup; no fallback. The listener removes `endpoint.json` only while it still names this socket, also at stdin EOF. A killed core leaves a stale endpoint file and, on POSIX, socket; the next listener overwrites the endpoint and clears a dead socket. macOS/Linux socket `<dir>/control.sock` is bound inside the 0700 folder then chmodded 0600, without a process-wide umask that could affect other core requests. Past `sun_path` (103 bytes), only the socket moves to `<tmpdir>/ompdesk-<uid>-<hash>/` (same checks). A socket is replaced only when nothing answers on it (`ECONNREFUSED` or `ENOENT`); a live listener or a non-socket fails startup (`SocketInUse`). Close removes only the dev/inode made at bind; tokio never unlinks another process's file at close. Nothing listens on TCP.
- **Windows pipe**: `\\.\pipe\ompdesk-<32 random hex>`, new each app launch, published only in `endpoint.json` under the user's `%APPDATA%`. The Rust listener keeps the default pipe DACL, as Node did, adds `FILE_FLAG_FIRST_PIPE_INSTANCE` on its first instance (an existing pipe refuses startup), and sets `PIPE_REJECT_REMOTE_CLIENTS` on every instance. The folder and files inherit the user's profile ACL; that ACL is not checked, as before. A core restart listens again at the same pipe name, so running sessions' `OMPDESK_SOCKET` still works. Nothing is answered before the token.
- **Auth and limits** (`control/conn.rs`): the first line must be `hello {token, protocol}` within 10 s and at most 64 KiB; a wrong or missing token, any other first request or another protocol is answered `unauthorized`/`protocol_mismatch` and the connection ends. At most 64 connections (the next is answered `unavailable` and closed) and 16 running requests per connection. Past that, or while queued output reaches 16 KiB, the server stops reading until a request answers or the output drains. The CLI sends the token only to a socket that is this user's alone: on POSIX the socket, its folder and token file must belong to its uid with no group or other bits, else exit 3 before any byte (`owner_only`, `crates/cli/src/endpoint.rs`).
- **Env, per spawn** (`env.ts`): main never puts the socket's address in `process.env`. `controlEnvFor(foreign)` gives this computer's own tabs (`SidecarOptions.controlEnv`, read per spawn) and their terminals (`terminalRequest`'s `env`, merged by the terminals worker) `OMPDESK_SOCKET` and `OMPDESK_CONTROL_DIR`; a tab run for a paired device (`origin`) or owned by the phone page (the pool factory's `web` flag) and its terminals get only `OMPDESK_CONTROL_OFF=1`, which the CLI refuses on (exit 3), so neither acts as an outside caller beyond its device's grants and `PeerQuota` (threat models in `multi-viewer-web.md` and `remote-devices.md`). `withoutControlEnv` strips what a login shell or a parent OMPdesk passed on, for omp spawns and the stock helper workers.
- **Waits** (`control/router.rs`, Herdr's `prompt_agent` mechanics re-implemented): `state` is `SessionState` from `sessionState` (`backend.ts`): `blocked` = the tools' `waits` (an ask or approval that is no sign-in, or a plan up for review: the renderer's `lib/attention.ts` `pendingAsks`) over `working` (busy or resuming), `starting`, `stopped`, `idle`. Each request asks main to watch before resolving a name. Main sends every lifecycle step with the visible sessions at that moment; the core dates the steps by their push sequence and keeps each wait's snapshots (`link.rs` `Watch`, `Glance`). `wait --until idle|blocked|done|any`; no `until` = settled (idle, blocked or stopped). `done` and `any` are edges: a turn end (any step for `any`) after the mark satisfies them, replayed. `idle`, `blocked` and settled are states: only the current state at a check matches, not a past lifecycle step. `send` refuses a blocked session unless `force`. With `wait`, its mark is main's last push as it enters the send tool, so activity heard between resolve and send does not count as the sent turn's. The gate passes if it was working already, a step after that mark shows working, blocked or a turn end, or its state now is working or blocked (a plan raises no step). Within 5 s (`start_wait_ms`) or the remaining total timeout if nearer, else `agent_prompt_stalled`. The final wait counts from that mark, so a turn end the gate consumed still ends `done`. If it was already working, the final wait counts from the receipt instead (an end while send was in flight belongs to the older turn), and idle just after such an end is held for 5 s unless a new step comes (the queued follow-up's gap). A follow-up folded into the ended turn settles after that hold. One total timeout covers send, gate and wait. Known limit: a message steered into a turn still running at receipt settles at that turn's end.
- **Events** (`control/events.rs`): `subscribe` starts live; `session_state`, `ask`, `turn_finished`, `session_closed`, and `report` only to its addressed caller; never a hidden session. A ring of 1 024 events, one cursor per subscriber; falling behind the oldest retained event gives one `events_lost` frame (count and resync hint: subscribe again, resync with `ompdesk sessions`/`state`) and ends the subscription, never a silent skip. `control/link.rs` turns main's activity forwarding on only while a wait or subscription needs it. Main answers `control` events through numbered `control.push` requests; their numbers preserve main's order across the core's concurrent request tasks. Main holds `control.closed` to notice a dead core and rebinds the listener; the disconnected callers are released and the new callers' decimal ids include a new incarnation, so no ownership is inherited across that restart.
- **CLI and PATH** (`cli-install.ts`, called from `index.ts`): every launch writes `<userData>/bin/ompdesk` (and `ompdesk.cmd` on Windows) running the app's `ompdesk` executable by its absolute path (`<resources>/ompdesk-bin/ompdesk[.exe]`; an unpacked run: `resources/ompdesk-bin/<platform>-<arch>/`) and appends that folder to `process.env.PATH` for everything OMPdesk spawns; a packaged, non-headless app also writes it into Bun's global bin (where `omp` is, so an outside terminal finds it), only over a missing file or one with its marker line. The CLI needs neither Bun nor omp on the machine. Exit codes 0 ok, 1 failed, 2 usage, 3 OMPdesk not running or refused; `--json` prints the raw result. An interrupt ends `events` with 0 and any other command at once.
- Tests: `control-socket/server.test.ts`, `router.test.ts` and `events.test.ts` run through the real core and real socket (Windows named pipe). They keep auth refusals, modes, ownership, stale sockets, env, send/wait gates, events, hidden sessions and report routing, and cover EOF cleanup and killed-core recovery. `control/captured.json` has the original TypeScript's connection, caller, wait, send, ring, number and path rows, replayed in Rust tests on a paused clock. Exact ring loss counts are covered there; the real socket suite derives loss from the delivered cursor because OS buffering differs. `cli.test.ts` runs the built CLI unchanged against the real server (caller, folder, stdin, JSON, exit codes, ownership); the CLI crate's tests cover flags, numbers, stdin, output, events, owner checks and a fake server end to end. Also `cli-install.test.ts`, "a caller outside OMPdesk" in `host.test.ts`, and `e2e/control-cli.e2e.ts` (launcher against the built app and fake omp).

### Heavy slots and `ompdesk check` (`native/ompdesk/crates/checks`, local commands of the CLI)
- **The owner's order (13 Nov 2026)**: "검사 한번이 2시간 20분인게 말이되냐 … ompdesk로 작업할때 이 부분도 해결되는것을 기본 내장해야함". Measured that day: one project's release check took 142 min (Playwright 115 min, 1 144 tests, one worker) and ran from scratch three times, the last after a 7-line change; a check died with an OMPdesk restart; heavy slots were glued by hand per project; tests put a keychain dialog and an installer error box on the owner's screen; checks took 22-77 % of tool time in this computer's sessions. One product feature, no setting, on for every project.
- **Local commands**: `run`, `heavy` and `check` are answered by the CLI itself before anything else (`ompdesk_checks::cli::dispatch`, called first in `crates/cli/src/main.rs`): they need no running OMPdesk, no control socket and no token, and they work under `OMPDESK_CONTROL_OFF` (a paired device's tab), in CI and in a plain terminal.
- **Heavy slots** (`heavy.rs`): one counting pool per user and computer, in a fixed folder (`$XDG_CACHE_HOME|~/.cache/ompdesk/heavy`, Windows `%LOCALAPPDATA%\ompdesk\heavy`; `OMPDESK_HEAVY_DIR` for tests), never per app profile, so a dev OMPdesk, the installed one and any script share it. A slot is an OS file lock (`flock`, `LockFileEx`) on `slot.<i>`, held for the holder's life: a holder that dies gives it back at once, nothing judges staleness. Waiters queue in order of a numbered ticket each keeps locked (`queue/`); only the oldest live ticket takes slots, so `--all` is never starved by smaller holds behind it; a dead waiter's ticket is removed by whoever finds its lock free. Size `pool_size`: min(⌊(GB − 8) ÷ 8⌋, ⌊cores ÷ 2⌋), 1 to 7 (`OMPDESK_HEAVY_SLOTS` overrides). `ompdesk run --heavy [--all] -- CMD` holds a slot while CMD runs (SIGTERM/SIGHUP to the holder are passed on, so the slot is never given back while CMD runs) and sets `OMPDESK_HEAVY_HELD=<holder pid>`, under which a nested heavy command runs inside its parent's slot. `ompdesk heavy hold [--all]` prints `held <slots>` and holds until stdin ends (how this repository's `scripts/lock-slots.ts` takes the pool); `ompdesk heavy status [--json]` lists holders and the queue.
- **The shim** for a project's own heavy script (the one line that makes `heavy-run.sh`-style scripts join the pool):
  ```sh
  #!/bin/sh
  if [ "$1" = --all ]; then shift; exec ompdesk run --heavy --all -- "$@"; fi; exec ompdesk run --heavy -- "$@"
  ```
- **`ompdesk check [--full] [--light] [--release] [--] CMD`** (`check.rs`): runs a test suite or check command. What it reuses, against the newest earlier run of the same command in the same folder whose files did not change while it ran:
  - **Inputs** (`inputs.rs`): every file of the checkout by content (SHA-256; a stat cache per checkout skips unchanged files), `node_modules` and build output included, so uncommitted edits count and HEAD is only shown, never compared; except `.git`, folders tagged `CACHEDIR.TAG` (cargo's `target/`) and, where git ignores them, cache and report folders (`CACHE_NAMES`). Plus files the command names outside the checkout (a wrapper script), every environment variable but terminal and OMPdesk plumbing (`volatile_env`, by hash), and the tools: OS and kernel, `node`, `bun`, for cargo `rustc` and `cargo`, and the CLI's own version with its reporters' hash (a changed check program reuses nothing).
  - **Nothing changed** (same digest): a run that passed is reused whole (nothing runs); otherwise its passes are reused and only what did not pass runs again: Playwright `--test-list-invert` of the passes, Vitest by test name (the failed files and `-t` with their full names) or, when a failed file names no failed test (it did not load, a hook failed), `--exclude` of the files that passed, Jest `--runTestsByPath` of every listed test file but those that passed, `cargo test -- --exact <failed>` after a run that reported every binary (`--no-fail-fast` is added to every cargo run for that). A plain command is reused only whole.
  - **Only test files changed** (files the earlier run recorded tests from, or new files named with a suffix those had, `.test.ts`, `.e2e.ts`): those files run in full, the other passes are reused. **Anything else changed** (product code, a test helper, config, a lockfile, the environment, a tool): everything runs. Unknown means full.
  - **Runner signals not trusted**, and why: Playwright `--only-changed` selects only changed test files and the test files importing them, so it never finds the e2e tests that exercise changed product code (server or browser). Vitest `--changed`/`related` follow the import graph, which misses what a test runs without importing: in this repository the bridge loaded by a real omp (`-e`), `e2e/sidecar-fixture.ts` as the fake omp, the native binaries. Playwright `--last-failed` and Jest `--onlyFailures` read the runner's own record of the last run of any command in that folder, which another command overwrites and which a cut-off run leaves incomplete. Mapping product code to tests needs coverage recorded per test (stage 3); until then the only narrowing is by the run's own recorded results.
  - **A filter cannot pass for a test**: each result the earlier run did not pass that this run was meant to run again must come back; one that is missing or reported skipped reads `missing` and fails the verdict. A test this run left out by name (reported `skipped` by a `-t` filter) keeps the result it reused.
  - **Provenance**: `verdict.txt` lists every result with `run now` or `reused from run <id> (<commit>, <time>), log <path>`; `verdict.json` the same for programs. The reporters (`reporters/*.{cjs,mjs}`, written into the store per hash) record each result as it ends, so a run cut off half way keeps what passed; Playwright's rides in `PW_TEST_REPORTER`, so a Playwright run inside any script is recorded.
  - **Flaky quarantine** (`flaky.rs`): a test that passed and failed on the same input digest (a rerun of the same inputs, or Playwright's retried `flaky` outcome) is quarantined per check; its failures do not fail the verdict and are always listed with pass and fail counts and the inputs it flaked on; `--release` fails while a quarantined test failed (or flaked) in that run. It leaves after 5 passes in a row on different inputs (`CLEAR_AFTER`, reason in `flaky.rs`).
- **Survives a restart**: the foreground starts a detached runner through a middle process that exits at once (POSIX: own session; Windows: outside the console, group and job, on the desktop `ompdesk-checks` made with `CreateDesktop`, so a message box never reaches the person's desktop) and follows its log. The runner journals every step in `<cache>/ompdesk/checks/runs/<id>/` (`run.json`, `log`, `results.jsonl`, `reused.jsonl`, `inputs.tsv`, `verdict.*`) and holds `alive` locked; a free `alive` with a running journal reads `killed`. Killing the starter's process tree leaves it running; `ompdesk check attach [id]` follows it again; starting the same check while one runs attaches to it; `status`, `cancel`. The runner keeps `OMP_GUI_SESSION_TAG`, so closing the tab still ends it (Session processes). It holds one heavy slot while the command runs and decides again if the inputs changed while it waited; `--light` takes none; a check inside another check's command runs as its plain child.

### Worker contract
- `#openOne` sends each child `agent_control_worker {from}` (local handler → bridge `agent_control.worker`, free in `quota-commands.ts`) once ready and before its first prompt. - `ompdesk_compare` reads each child's branch (`git merge-base`, `diff --numstat`, commits ahead, uncommitted and untracked counts), a merge prediction and its final answer; it **runs no tests** (a child reports them). The prediction (`predict` in `crates/core/src/git/branches.rs`, core `git.predictMerge`; the scratch store is made and deleted inside the request) is `git merge-tree --write-tree --name-only` of the parent's HEAD and the branch tip with a quarantined object store (`GIT_OBJECT_DIRECTORY` a scratch dir, the repo's store as alternate, deleted after; idea from Orca's `conflict-summary.ts`, MIT, re-implemented), so no checkout, index, ref or object of the repo changes; the line reads `merge: would conflict in <files>`, `no conflict with <base>` or `not predicted (<reason>)` (git < 2.38), and a predicted conflict marks the child's review item `conflict`.
- **Where a branch lands** (`branchFacts`/`landingFacts`, one rule): the parent checkout's HEAD and the upstream its branch tracks (`<branch>@{upstream}`, else `refs/remotes/origin/HEAD`; refs as last fetched, never fetches, never touches the parent checkout). Agents push their own work (`git push origin HEAD:main`) while the parent's local main stays behind, so a tip in either has **landed** (`BranchFacts.merged`) and its diff is measured from that tip (only uncommitted work is left). An unlanded branch is measured from its merge-base with the upstream when the upstream holds the parent's HEAD, else with the parent's HEAD, so a stale local main never lends a child the upstream's newer commits.
- `ompdesk_merge` merges into the parent checkout's current branch with `git merge --no-ff` (never a push, no remote command in the module). It refuses a detached parent, uncommitted work in child or parent, and a branch with nothing to merge (`mergeProblem`); asks one `[OMPdesk]` card only while `agentControlManage` (default on) is off; refuses a merge `predictMerge` says would conflict before running `git merge` (`MergeOutcome.predicted`, the files named, the parent untouched), and still aborts a conflict it did not predict (`git merge --abort`) naming the files. The repository's `.ompdesk/worktree-pre-merge` / `worktree-post-merge` hooks run around the merge (Worktree seeding).
- **The work board has no review section** (the user's decision): the agent that opened a child reviews and lands it itself with `ompdesk_compare`, `ompdesk_merge` and `ompdesk_session_stop`; nobody clicks Approve, Discard or Dismiss on a board (desktop or phone strip), and `agent_control_review` only lists. `AgentControl.reviewItems` stays: pushed as `AGENT_CONTROL_REVIEW` after a 400 ms settle on child activity and asked once on mount via the `agent_control_review` command `dispatchRpcCommand` answers itself, it feeds the "Child sessions" rows (title, status, step, clock, report, waiting) and the opener's next-prompt children. A child that needs the person (a question, a blocker, a plan waiting for approval: `AgentReviewItem.waiting`) shows as a waiting row and a notification. No item when nothing is left: idle (no turn, no open ask), branch landed, no uncommitted or untracked file, not failed, not waiting on an answer (its opened row reads merged). A landed branch with leftovers lists only those.
  - The review list follows the world, not only tab activity: besides the pushes after a child's activity and after `ompdesk_session_open`/`_merge`/`_stop`/`_autopilot`, `AgentControlRuntime.#sweepAll` (the 10 s timer that also runs the auto-close pass; `OMP_GUI_TEST_AGENT_SWEEP_MS` in e2e) re-reads each opener's `reviewItems` and sends `AGENT_CONTROL_REVIEW` only when the list differs from the one last sent (`#reviewSent`), so a commit, push or merge made outside the app moves a child's row: an idle child whose branch has landed (an untouched branch counts: its tip is in the parent's HEAD) and has no uncommitted or untracked file has no item. `e2e/agent-review.e2e.ts` commits into each child's checkout from outside and waits for the board to list all three as opened rows, with no review section or button; `host.test.ts` pins the timer push (changed → sent, unchanged → silent).

### Sessions sharing a checkout
- The user's rule: sessions working in the same project folder at the same time know of each other and talk instead of breaking each other's work (without it, one session's work lands in another's commit through `git add -A` or a commit without paths, a shared formatter rewrites the other's files, and `git stash` swaps work across worktrees; guard plus messaging settles even same-file work). Stock has no cross-process channel to reuse: `src/irc` is one process's bus (subagents), `collab` shares one session with browsers.
- Two scopes, as git keeps them: the worktree (`git rev-parse --show-toplevel`: files, index, HEAD, build output) and the repository (`--git-common-dir`: stash, branches, refs, shared by every worktree). Main's `CheckoutPeerCoordinator` (`src/main/checkout-peers.ts`, wired in `ipc.ts`) groups this computer's live omps (the tabs of its windows and `LocalHostServices.checkoutMembers()`, the tabs it runs for paired devices; a paired host's tab is that host's to coordinate) by both, on tab activity and every `CHECKOUT_PEERS_SWEEP_MS` (10 s; `OMP_GUI_TEST_CHECKOUT_PEERS_MS`), reads each same-worktree member's changed files and task from its bridge (`checkout_status`) and pushes each member `checkout_peers_set` (`CheckoutPeers`, `resources/gui-bridge/modes/checkout-peers-contracts.ts`) only on a change; a session never told of company starts alone and one left alone is told once. A session hidden from agents is a peer with no id, title, task or files; one run for a paired device has no id (its control tools answer on the device).
- The bridge (`modes/checkout-peers.ts`, rules `checkout-peers-core.ts`, capability `checkoutPeers`) adds the `<shared-checkout>` section through `registerPromptSection` (names and ids of both groups, stage and commit by name, change a shared file with the edit tool, formatters on own files only, one `ompdesk_report` note before a commit, install, rebuild or dev-server restart, a question to have a peer commit or hold); it carries no files, so it stays the same text turn after turn and the prompt cache holds. A `tool_call` guard reads `bash` and the `eval` tool with Autopilot's own parser (`shellEffects` in `autopilot-guard-core.ts`, a collect mode of its walk) and judges each git run by one table (`GIT_RULES`); see Round 2 and 3 below. A git run in another repository is not judged; a session alone is never judged. Paths are compared in main's spelling: the bridge resolves its cwd, its writes and each git run's cwd to the native real path of the nearest existing folder (`canonicalPath`; macOS `/var` is `/private/var`, Windows temp dirs have 8.3 names); case is folded only on win32 and darwin (`isInside`, `foldsCase`). The answer names the run's session file; the device opens it (`spawnTab {device, sessionPath}`), the host attaches that as a view of the run's tab (one omp), and the device tab counts as the caller's opened run, so status and stop go through it to the window tab that runs it. The run is charged to the device until it ends (`chargeRun` with its root and session; `ipc.ts` feeds every reply of a pool tab whose `Autopilot.runRootOf` names a charged run to `runEvents`; `runEnded` → `endRun`), whether or not the device still views it. Pinned by `service.test.ts`, `host.test.ts`, `host-services.test.ts`, `hosted-autopilot.test.ts`, `autopilot.test.ts` and `e2e/agent-control-remote.e2e.ts`.

### New worktree preparation
- `src/main/local/git/worktree-seed.ts`, run by `createWorktree` after `worktree add`, so the worktree dialog, Autopilot and `ompdesk_session_open` worktrees all get it (stock omp has no `worktreeinclude` and no worktree hook). The seed's rules and file work are the core process's (`native/ompdesk/crates/core/src/git/seed.rs`, one cancellable request `git.worktreeSeed`; native-rust › 2i); the file is its client and runs the hooks.
- `.worktreeinclude` at the main checkout's root lists paths or globs (`*`, `?`, `**`; `#` comments) copied from the main checkout only when `git check-ignore` reports them ignored (a tracked file never is). Refused: absolute paths, `..`, `.git`, `!`, any match whose real parent leaves the checkout. A symlink inside a copied folder is recreated only when it points inside; one written with an absolute path into the main checkout points at the worktree's own copy once the worktree has one (a tracked file, or one the seed copied; `point_links_at_worktree`), else keeps the main checkout's (a shared store); **on Windows a file link is copied (a file symlink there needs Developer Mode or admin, and OMPdesk never requires one) and a folder link becomes a junction** (`worktree-seed.test.ts` "copies an ignored file link on Windows"; tests that make a file symlink use `itWithFileSymlinks` from `src/main/test-symlinks.ts`, skipped where the OS refuses). Budget: `SEED_MAX_FILES` 10,000 always, `SEED_MAX_BYTES` 50 MB only where the filesystem cannot clone, and 60 s to start new entries (`SEED_BUDGET_MS`, sent with the request); what does not fit is skipped as `budget`. Every file is first asked as a clone (APFS `clonefile`, Linux `FICLONE` on btrfs and XFS; Windows has none); if that works (`WorktreeSeedReport.cloned`, `describePreparation` adds "(reflink)") every later file is a clone too and the byte cap is off; a clone that fails (the first file: a volume without reflinks; a later one: a file on another mount) is copied plainly and the cap applies from there over what took real disk (a file over it is then skipped; `cloned` reports only a seed that cloned every file). `seedWorktree`'s optional `pretendClones` (how many files clone before the volume refuses) lets tests stand in for a volume. Existing files never overwritten; every skip reported (`WorktreeSeedReport.skipped`). **The seed writes only in the new worktree and only reads the main checkout**: every create, link and removal takes a `Place`, which only `Worktree::place` makes after it checked the path (no `..`, no absolute path, on Windows no `:` and no part ending in `.` or a space, the nearest existing folder a real folder whose real path is the worktree or inside it; a refusal is the skip `destination_outside`). Pinned by the Rust test `writes_only_in_the_worktree_and_leaves_everything_else_as_it_was` (a `..` pattern, an absolute one, links and junctions out of the main checkout and out of the worktree).
- Then `.ompdesk/worktree-setup` (`.cmd` on Windows), only when it exists in the new worktree or the main checkout (the core looks and names the log: `git.worktreeHook`), runs in the worktree under the setup supervisor (`/bin/sh <file>`, env `OMPDESK_ROOT_PATH`/`OMPDESK_WORKTREE_PATH`, `SETUP_TIMEOUT_MS` 120 s, process tree killed at the timeout and its exit code then ignored, output in `<worktree git dir>/ompdesk-worktree-setup.log`). A failure is reported in `RpcWorktreeCreateResult.setup`, never fatal. **Merge hooks** (`runWorktreeHook`, the same lookup, supervisor, timeout and tail; `WORKTREE_HOOK_SCRIPTS`; env adds `OMPDESK_HOOK`; log `ompdesk-worktree-<hook>.log`): `.ompdesk/worktree-pre-merge` runs in the child's worktree after the checks and the conflict prediction and before `git merge`: a non-zero exit or timeout returns `MergeOutcome {reason: "hook"}` and no merge starts (`#runMerge` fails with the script, exit, worktree and output tail); `.ompdesk/worktree-post-merge` runs in the parent checkout after the merge commit and never undoes it (a failure is `postMerge` on the outcome, appended to the success text). Both run on the computer holding the worktree (a paired host's `host.git.merge` calls `mergeBranch` there). `ompdesk_merge`'s answer budget gains `MERGE_HOOKS_BUDGET_MS` (2 × `SETUP_TIMEOUT_MS`) on the link request (`host.ts` `#git`); a local merge has no RPC deadline of its own. There is no merge button (the board has no review section). **A hook's script runs in main, not in the core** (native-rust › 2i says why): a hook needs its whole tree ended at its timeout and must never outlive the app, and on POSIX only the setup supervisor's own process beside the command gives both.
- The dialog toasts both (`announcePreparation`, `worktree.seed*`/`worktree.setup*`); `ompdesk_session_open` adds `describePreparation` to its notes. `worktree_create`'s budget includes it (`WORKTREE_PREPARE_BUDGET_MS`; renderer, agent-control and Autopilot wait 960 s). Pinned by `worktree-seed.test.ts` (real temp repos through the real core; a `.cmd` hook on Windows) and the Rust tests of `git/seed.rs`.

### Worktree names
- Files: `shared/project-origin.ts` (rules), `main/local/git/origin.ts` (git reads), `renderer/lib/project-origin.ts` (`useProjectNames`), `stores/project-origins.ts`, channel `project-origin:get` = `window.omp.projectOrigins.get(cwds)`. A linked worktree's folder (`~/.omp/wt/gui-<name>-<hash7>`) never shows as a project name.
- Git alone says what it is: `--git-common-dir` names the main checkout (`<main>/.git`, else the first `git worktree list` entry for a bare or relocated dir); `--git-dir` ≠ common dir marks a linked worktree; the branch gives its kind (`autopilot/…` → "오토파일럿"/Autopilot, `omp/agent/…` → "병렬 작업"/Parallel work, or the child's title where a one-line `project · title` is shown; any other branch shows as itself).
- No new store: main caches each cwd for 30 s (5 s when git cannot place it); the renderer asks once per cwd and retries an unknown one after 10 s. A lookup that fails (no answer: the computer restarting, a dropped link) is no unknown: the folder keeps what was known and the store asks again by itself every 2 s until one answers (`stores/project-origins.ts` `RETRY_FAILED_MS`; a null would hide a worktree's rows as a removed folder; `project-origins.test.ts`). A folder git cannot place (removed worktree, not a repository, a paired host's path) shows its own name with the `gui-…-<hash7>` dressing stripped.
- Surfaces: in the sidebar a linked worktree's sessions are **rows of their project's own group, never a group of their own** (the user's rule): in the project's order (pins, then recency), each marked at the row's end by what it is for (`data-sidebar-worktree`: `Rocket` for `autopilot`, `GitBranch` for `agent` and a user's own branch), the kind's word (`Autopilot`/`Parallel work`, else the branch) in the row's tooltip and screen-reader text. A project whose own folder has no session gets its group from its worktrees' sessions, keyed and named by the main checkout (its `+` starts there), never by the worktree. The group header and its `+` are the project's only; phone and tablet the same. Title bar and pane header breadcrumb `acme-web › Autopilot › <title>` (`data-titlebar-worktree`, `data-pane-worktree`; an Autopilot run shows the rocket alone, its word for screen readers); work board head `acme-web · Parallel work` (`data-board-project`; a run's is `acme-web` and the rocket, the word for screen readers); window title `<name> — acme-web · Autopilot`; an untitled worktree tab chip reads from `IpcTabWorktree` (`baseCwd` + branch, no git); session and workspace pickers. **A new surface that shows a cwd's folder name goes through `useProjectNames`, never `basename`.**
- An Autopilot run's children (`autopilot/<run>-c<N>-<area>`, `autopilotRunOf`) are no rows of the project's list of their own: they sit right under the run's row, newest first, one step in and with no mark (`data-session-run-child`; `runParentOf` in `Sidebar.tsx`, from the branch git reports or, while git cannot place a new child worktree, the child tab's `worktree.baseCwd`). Parallel work sessions nest under their opener as family rows when the opener is listed (see Sidebar families), else are plain marked rows of the project.
- A session another agent opened (`ompdesk_session_open`, an Autopilot child) reads as its task until stock names it: `agentTaskTitle` (`shared/agent-control.ts`: the body's `Title:` line by `assignmentTitle`, else its first line) of the indexed first message in `sessionDisplayTitle`, and before the index lists it the tab's `task` (`IpcTabInfo.task`), never "New session". The task rides the spawn (`SpawnRequest.task` → `IpcSpawnTabPayload.task` → `SidecarPool.acquire`), so the tab's first status already carries it (set after the spawn, a phone's row would read "New session" for a frame). Only a tab that already exists (one a relaunch restored, named from its saved session by `#nameUntitled`) gets its task afterwards (`SidecarPool.setTabTask`). Pinned by `sidecar-pool.test.ts` ("from the first status any window hears") and `agent-control/host.test.ts`.
- Tests: `project-origin.test.ts`, `origin.test.ts` (real temp repos: main, linked, detached, bare, removed), `Sidebar.test.tsx` "worktree sessions", the run row in its project's group in `e2e/autopilot-cycles.e2e.ts` and `e2e/mobile-autopilot-rows.e2e.ts`, and the no-`gui-2026`/`gui-agent` assertions in `e2e/autopilot-cycles.e2e.ts` and `e2e/agent-review.e2e.ts`.
