## Build, test, CI

### E2E

- Run: `bunx playwright test`. `playwright.config.ts` sets `OMP_GUI_HEADLESS=1`: windows are transparent, click-through, off the Dock/taskbar and never focused, and the app creates no menu-bar tray item and never registers the `omp://` handler (both belong to the user's installed OMPdesk; a test's tray once stalled the main thread before the first window reached Playwright). It posts no OS notification either (`holdTestNotifications`, `src/main/app-icon.ts`: `Notification.prototype.show` is a no-op, so a spec that wraps it still sees each one): macOS filed a test's notification under node_modules' Electron.app and the user's Notification Center showed e2e's "Autopilot ended" with the Electron logo. Tests never cover the user's screen or rewrite their LaunchServices state. Set `OMP_GUI_HEADLESS=0` only when you must watch.
- Fake vs real omp: `e2e/real-core.e2e.ts` and `e2e/deep-audit.e2e.ts` run against the real system omp (isolated agent dir, no credentials). Every other suite uses the fake omp in `e2e/sidecar-fixture.ts`, installed per test by `fixtureOmp()` (`e2e/harness.ts`; an `omp.cmd` shim on Windows) and passed as `OMP_GUI_OMP`. It speaks stock `--mode rpc-ui` and serves the gui-bridge methods those suites reach on `OMP_GUI_BRIDGE`.
- Tear apps down with `exitApp()` (same file; it kills a main process that does not act on the exit within 10 s). On Windows it then waits (`e2e/process-tree.ts`) for every process the app started (Chromium's helpers, omp, its MCP servers, git) and kills one still running after 10 s: a process holds the folder it works in, and the launcher exits ~0.1 s before they do, so a spec's `fs.rm(profile)` right after found `project` busy (`real-core.e2e.ts`: `EBUSY` in 5 of 24 runs, the omp and its `npx` chain alive when `exitApp` returned; 0 of 30 after). Shortcuts in tests use `ControlOrMeta`. A path inside a CSS attribute selector goes through `cssString()` (`e2e/harness.ts`): a raw Windows path's backslashes read as CSS escapes and the locator matches nothing.
- **A test app never outlives its worker, and a run's temp files never outlive the run** (21 Oct 2026: a Windows PC held 108 test Electron processes, their fake omps and fake ai-memory servers, and 289 test profiles plus 405 WebKit profiles after a day of agent runs). Playwright's exit handler is the only thing that ends an app it launched, and a worker that dies without running it (Node 24.15's 0xC0000409, an outer `taskkill /F`) left the app running under the `cmd.exe` Playwright starts it with; stdin cannot tell, since Electron's main process on Windows has an empty `process.stdin`. `playwright.config.ts` sets `OMP_GUI_TEST_LAUNCHER_PID` to each runner's and worker's own pid and `appLaunchOptions` (`e2e/harness.ts`) puts it in every `launchApp` env, and main (`src/main/test-launcher-exit.ts`) exits once a second's check finds that pid gone (taken out of its environment, so nothing it spawns inherits it); a spec that builds its own env keeps the variable by spreading `process.env`. On Windows every run also gets its own temp folder (`e2e/run-temp.ts`: TEMP/TMP point at `<temp>/ompdesk-e2e-XXXXXX` with an `owner.json`), so every `mkdtemp` profile, Playwright's own and whatever the apps and fakes write land there; `globalTeardown` ends every process whose command line names it (the detached fake ai-memory server included) and removes it, and `globalSetup` does the same for a folder whose runner died first. What must outlive a run (the compiled fake `gh` launcher, opt-in evidence folders) uses `baseTemp()`. Pinned by `e2e/app-lifetime.e2e.ts` (launches with `appLaunchOptions`' env, whose launcher dies running no handler: the app, its helpers and its omp are gone within seconds; it fails with that wiring removed) and `e2e/run-temp.test.ts`.
- **The fake ai-memory server ends itself** (`e2e/fixture/fake-ai-memory.ts` `serve`): it is detached like a real service, so nothing above reaches it on macOS (there is no run temp folder there). It checks once a second and exits when its data dir is gone (the spec's teardown) or the worker that installed the fake no longer runs (`FAKE_AI_MEMORY_OWNER_PID`, baked into the launcher by `fixtureAiMemory`). Seen 28 Oct 2026: 49 servers (136 MB RSS) from a week of runs, every data dir already deleted; 0 after `ai-memory`, `memory-page`, `memory-sync` and `memory-upkeep` ran twice with `--repeat-each 2`.
- **A fake omp ends with the test that wrote it** (`DIES_WITH_TEST`, `src/main/test-fake-omp.ts`; `exitWhenGone` in `scripts/vitest-orphan-guard.ts`). `writeFakeOmp` writes every fake omp (unit tests and `fixtureOmp` alike) as an entry `omp.ts` that arms it and only then imports the test's source from `body.ts` beside it: in one file it ran after the source's static imports, and `sidecar-fixture.ts`'s `stats` and `-p` modes await forever there, so those fakes never armed it. A long-lived process a unit test starts itself (an idle stand-in, a SIGTERM-ignoring child, an installer's grandchild) begins with it too. It checks every 2 s whether the process that wrote it still runs and exits once it does not, so a killed or crashed Vitest or Playwright worker leaves none behind. It watches the writer, never its own parent: an app the spec kills (SIGKILL) must still be what stops its fake through stdin, so the app's stop stays tested, and on Windows the fake's parent is the `omp.cmd` shim's cmd.exe, which outlives the test too. Seen 10 Nov 2026: two `sidecar.test.ts` fakes that ignore SIGTERM and stdin's end alive under launchd for 33 h; with it, the same fake is gone within 5 s of `kill -9` of its runner. A process the guard cannot run in (one kept stopped with SIGSTOP) is still only ended by its test's own teardown.
- Fake omp layout: `e2e/sidecar-fixture.ts` only reports the version (`fixture/version.ts`) and dispatches in stock's order: `--version`, `stats` (`fixture/stats.ts`), `update --check` (`update-check.ts`), `worktree … --json` (`worktree.ts`), `-p` (`print.ts`), then `--mode rpc-ui` (`rpc-ui.ts`: stock RPC plus every gui-bridge method the suites reach; one closure, because its fake session state is shared by every command). A new fake RPC command or bridge method goes into `rpc-ui.ts`; a new CLI invocation into its own `e2e/fixture/` module and the entry's dispatch. A fixture branch no spec uses any more goes with the spec that used it.
- With `OMP_GUI_TEST_SESSION_FILES=1` the fake's journal is a stock-shaped session file: a new session writes `sessions/fixture/fixture-<pid>.jsonl`, and a stored file that `--session` or `switch_session` opened keeps its header and takes every later entry, as stock's `SessionManager.open` does (`e2e/fixture/rpc-ui-session-file.test.ts`). Writing it elsewhere makes a relaunch's continued turn a second session the sidebar lists beside the first.
- Two shared steps a spec never re-implements (`e2e/harness.ts`): `dragTabToPane` splits by dragging a tab's sidebar row onto a pane edge, naming the tab with a `fixture:title:` shell line first, since a fresh tab has no row until something is typed into it (`unstarted`, Sidebar.tsx; four inline copies dragged `[data-session-path="tab:<id>"]` of a spawned tab and found nothing once that rule landed). `untilAnswered` waits for a tab's transcript to hold the fake's reply: never read an agent-opened child's `lastRun.reply` or last answer for it, because main asks a child whose turn ended with no `Result:` line and no report to report (`#nudgeSilent`, about a second after the turn) and the fake's "Read the note report from …" then follows (viewer-family, agent-control-across's blip test and remote-host-family failed so under load); `after` waits for the reply to a later message, and an `ompdesk_compare` `final answer:` is either reply.
- **No build, no run.** Electron with a missing entry opens a native "Error launching app: Unable to find Electron app at …/main/index.js" dialog on the user's screen for every test, and `OMP_GUI_HEADLESS` does not stop it. `playwright.config.ts`'s `globalSetup` (`e2e/global-setup.ts`) resolves `<OMP_GUI_E2E_OUT ?? out>/main/index.js` once (`scripts/e2e-app-entry.ts`) and fails the whole run before any worker starts ("No build: … Run `bun run build` or `bun run check:changed`"). `launchApp` (`e2e/harness.ts`) asserts the same before `electron.launch` (covers a spec run with a custom config); a spec that calls `electron.launch` itself uses `assertAppBuilt()`. Pinned by `scripts/e2e-app-entry.test.ts` (Playwright on an empty `OMP_GUI_E2E_OUT`: fast non-zero exit, no process on that path). Never run Playwright in a fresh worktree before `bun run build`.
- Specs launch `path.resolve(process.env.OMP_GUI_E2E_OUT ?? "out", "main/index.js")` (a new spec does the same, or uses `launchApp`); see Lock and gate for why the path is a snapshot.
- Env-gated specs and helpers:
  - `e2e/performance.e2e.ts` runs only with `OMP_GUI_PERFORMANCE=1` (optional `OMP_GUI_BASELINE_DIR` compares another built checkout); CPU and compositing budgets run only with it.
  - `e2e/load-performance.e2e.ts` runs only with `OMP_GUI_LOAD_AUDIT=1`: five fake-omp tabs streaming at once (a long reply, two bash outputs, two task calls with `OMP_GUI_LOAD_AGENTS` subagents; fake omp knobs `OMP_GUI_TEST_WORK_AGENTS`, `fixture:work-ticks`), then 10 s windows watch / away (unfocused) / switch (⌃⇥ timed to the shown pane, plus scrolling) / pressure (`OMP_GUI_LOAD_BUSY` busy loops, default one per core). Reports main's event-loop delay, CPU per process, frames, IPC and omp reads per switch, the generator's ticks; `OMP_GUI_BASELINE_DIR` interleaves a built checkout, `OMP_GUI_LOAD_RUNS`, `OMP_GUI_LOAD_OUT`, `OMP_GUI_LOAD_MAIN_PROFILE` (main's CPU profile per window), what-if `OMP_GUI_LOAD_CSS` / `OMP_GUI_LOAD_AWAY_SCRIPT`.
  - `e2e/real-startup.e2e.ts` registers only with `OMP_GUI_REAL_STARTUP=<dir>`: the built app on the user's installed omp (a private copy of `~/.omp/agent`'s config, extensions and databases plus the two largest sessions written this week), per run the main startup marks (`omp-spawned` included), the window's boot skeleton, layout, first row and composer, and a session opened in a new tab with and without its transcript snapshot. `OMP_GUI_REAL_STARTUP_SUBJECTS=before=<root>,after=<root>` interleaves built checkouts, `OMP_GUI_REAL_STARTUP_RUNS` (default 5); writes `results.json` and `summary.md` (median and range) to the dir. No model is called.
  - `e2e/event-replay.e2e.ts` runs the fake omp with `OMP_GUI_TEST_REPLAY_FRAMES=1` (every message and tool frame sent again behind the next one) and main with `OMP_GUI_TEST_BATCH_INTERVAL_MS=400`, so snapshot loads overtake held frames. `src/renderer/hooks/event-replay.test.tsx` is its seeded unit counterpart. Renderer stores apply a frame for a message or call they already hold (by stock timestamp and call id) as a no-op.
  - `OMP_GUI_TEST_INSTALLER=<executable>` turns on automatic machine setup in a test launch and replaces every install plan with `<executable> <item> <method>`. `e2e/machine-setup.e2e.ts` uses it with `OMP_GUI_OMP` naming a not-yet-existing fake omp (missing omp → install fails → Retry → detected → the tab restarts ready); `OMP_GUI_SETUP_CAPTURES=<dir>` adds its captures. Real installs never run in a test against the user's profile: `scripts/setup-install-check.ts` runs the real Bun installer, PortableGit (Windows) and `bun install -g` omp in a child with a temp HOME/USERPROFILE and BUN_INSTALL, checks `omp --version` against the minimum, and deletes the temp dir.
    - A spec that keeps setup from installing an item at launch seeds its back-off with `seedSetupBackoff` (`e2e/harness.ts`), never a hand-written `setup-state.json`: the ledger counts only misses stamped with the running version (`app`), which for the built app launched as a script is Electron's own. Unstamped seeds read as an older version's misses once that rule landed (654fef190), so the launch installed gh at once and `github-cli-install` found its card `installing` instead of `missing`.
  - Opt-in model audits (`OMP_GUI_REAL_WORK=1`, they spend tokens): `e2e/real-work-map.e2e.ts`, `e2e/real-work-scenarios.e2e.ts` and `e2e/real-advisor.e2e.ts` (asserts each custom message an `agent_end` commits, advisor card or background job result, carries its journal `entryId`, which the sidecar's `sessions.attach_entry_ids` stamps, and that its card is in the live transcript; `e2e/fixtures/real-advisor-frames.json` is a trimmed recording). All copy `config.yml` and `agent.db` into a private 0700 agent dir through `e2e/real-omp.ts` and run the main model on the user's `smol` role; `OMP_GUI_REAL_WORK_ARTIFACTS` picks the capture directory.
    - `e2e/real-voice-call.e2e.ts` (macOS: speech from `say`; `e2e/real-voice.ts` hands the call a mixer track the test plays clips into and logs the call bar, the tab's turn and every sound the call schedules): a voice call with the bot on the real dictation and speech models, linked from `~/.omp/agent/cache`. The English rows run with the conversation language pinned to English (Parakeet); then a second call in Korean gets Whisper large-v3-turbo ready (downloaded into that cache when it is not there, captured as `desktop-call-preparing-ko.png`) and must transcribe the Korean question and get an answer. Writes `real-voice-call.md`/`.json` (the latency table) and its captures to `OMP_GUI_REAL_WORK_ARTIFACTS`.
- **Tiers.** `@smoke` (the tag in a test's title) runs on every release's `mac` and `win` packaging jobs against the build they just made; it is the only e2e a release waits for. The default run (`bunx playwright test`) is the full suite: locally on demand (`bun run gate`; `check:changed` picks specs from it), on hosted runners nightly and on demand (`e2e-nightly.yml` and ci.yml's `e2e=true`, both through `e2e-shards.yml`; informational, never a release block).
- **Variants and captures are opt-in.** `variants(all, keep?)` in `e2e/harness.ts` keeps one variant (en light; for the mobile matrix one engine × device per shell mode) and does not register the rest unless `OMP_GUI_VARIANTS=1`, so they neither run nor show as skipped. `OMP_GUI_*=<dir>` capture tests register only with their dir set.
- **Rules for a new e2e.** No theme, language or size variant matrix as blocking tests (en light runs, the rest goes behind `variants()`). Prefer a unit or component test (vitest with linkedom) for anything that needs no real Electron window, Chromium layout, real processes or the wire between them; an e2e asserts a flow across those, and its header names the component tests that cover the rest. To move an e2e down, write the unit case first, confirm it fails when the behaviour breaks (break the guard, run it, put the guard back), then delete the e2e and any fixture branch only it used.
- **Parallelism.** Locally Playwright runs 4 workers (`OMP_GUI_WORKERS` overrides; 1 on GitHub's runners, `GITHUB_ACTIONS`). Every test launches its own app on `mkdtemp` userData, agent dir and fake omp, with ephemeral ports (a fresh bridge socket per spawn; a remote spec's host and client share one free port from `makeRemoteProfile`, which a parallel test may hold a successor of, so never assert the exact successor), so a new spec never uses a fixed path, port or shared profile. That remote port comes from `freePortRun` (`src/main/remote/test-ports.ts`), which walks a band of 500 ports per parallel worker (Playwright `TEST_PARALLEL_INDEX`, Vitest `VITEST_POOL_ID`) run by run, never at random from one shared range: a run is picked seconds before its app listens on it, and every app on the machine sees the others on 127.0.0.1, so two random picks that touched sent a device to another test's host, and the second device to reach it failed `[remote_key_mismatch]` in `remote.connect` (`connectHost`). Measured with the range cut to 45 ports: 2 of 24 `remote-resume` runs failed that way, each beside a pair of touching picks in the pick log (`test-ports.test.ts` pins the bands).
  - The suite is bound by its total work, not its slowest test: all workers stay busy to the end and apps running at once slow each other down. A launch on the fake omp costs about 1 s here and 2 s on a hosted runner, so sharing an app between tests saves little; fewer tests is the lever. Split a long test into tests that run side by side only while it ends the run.
  - `e2e/deep-audit.e2e.ts` (`mode: "parallel"`) splits its settings rows by measured cost over `SETTINGS_SHARDS = 3` apps (6 shards added work and left wall time unchanged). 5 or 6 workers measured only ~10 % faster than 4 at more load, so 4 stays.
  - Reference (18 Oct 2026, 15-core Mac): full default run ≈ 4 min. `MEASURED_SECONDS` in `scripts/e2e-shard.ts` holds per-spec costs for the shard dealer, measured on the hosted macOS runner with one worker (a nightly's per-test times summed per file): measured here with 4 workers, deep-audit read 184 s against 672 s on the runner, and its shard ran past the 30-minute step limit (nightly 39749113072).
- **Responsive audit.** `e2e/responsive-audit.ts` (engine), `e2e/responsive-surfaces.ts` (named surfaces), `e2e/responsive-audit.e2e.ts` (the matrix), `e2e/responsive-smoke.e2e.ts` (the default run). It visits the dev harness (`src/renderer/harness.html`; `?stress=1` overflow-prone turns, `?host=1` a fake web host so host sheets mount, `?pwa=push|ios`, `?platform=darwin|win32` paints the page as that OS's Electron window: desktop layout, no mobile shell; `window.__stores` exposes the ui/toast/extension-ui/plan/updater/host-ui stores so a surface opens the way a click would) at 48 looks: touch phones 320/360/390/412, tablets 768/834/1024 (portrait and landscape) and iPads sideways 1133/1180/1366, then desktop windows 1100/1280/1440/1920 with a mouse, once as the web client (column `W`) and once as the Electron window (`E`); en and ko, light (dark at 390 and 1280), with simulated safe areas (`--safe-*`) on touch looks. A surface that shows a panel's error boundary (`PanelErrorBoundary`, `data-panel-crashed`) or the root crash screen fails with its message (the harness once answered `getLaunchProfile` with nothing, and Settings › Projects & launch was measured as "This panel crashed" for weeks). Each surface reports page overflow, escaping elements, truncated controls, clipped text, off-screen popovers, hit boxes under 44 px (a list row under the shell's `--sc-row-touch`, 36 on a phone; 36 on a field or a cluster that declares `--hit-gap-*`), text under 11.5 px, overlaps, stolen taps and content under the insets; hit areas, stolen taps and insets only on touch looks. Every audit page carries the stress turns, the reply showcase (`dev-harness/reply-showcase.ts`) among them, so `session-idle` measures every reply component too. Small text by meaning is not small text: a `<sub>`/`<sup>` (a footnote marker too) and a formula's script levels (KaTeX's `.mtight`) read as body text at the floor; a reply's `<kbd>` and inline code are words to read and keep the phone's 12 px floor (`mobile.css`). Anything covered by a layer (judged at the centre of its on-screen part) or scrolled out of its scroller is not measured, and a popover or toast inside a scroller is judged by what the scroller lets through on each axis it scrolls (a fixed box, or an absolute one whose containing block sits above the scroller, escapes it; pinned by "a scroller lets through only what it scrolls" in `responsive-smoke.e2e.ts`); a menu, popover, sheet or toast over a control covers it rather than stealing or colliding; the drawer's edge strip is looked through (it hands taps on); a control drawn inside a field's box is the field's adornment; a list row's own actions over its title, whose ::after stretches over the row (ListRow's ⋯ the title runs on under), are layered, not an overlap; a text editor (CodeMirror's contenteditable) is a field, its hit box its own; a checkbox or radio inside its label is measured by the label's box and reach (it carries the hit area); a point outside its clipping ancestors (a tab half scrolled out of its strip) is no tap of the control's; a control with `pointer-events: none` is no target (a tree row's chevron on touch, `TreeView`: a row with children and no action of its own toggles them, so the whole row is the target); a point past the curve of a clipping ancestor's rounded corner (a half-scrolled segmented tab; per ancestor and corner, `e2e/rounded-outline.ts`) taps nothing drawn and counts for no one, while a point inside the curve still counts. Soft-keyboard surfaces (`composer-keyboard`, `composer-keyboard-slash`, `dialog-rename-keyboard`, portrait touch looks) shrink the layout viewport as Chrome on Android does, and the home bar's inset is dropped while `html[data-kb="open"]`.
  - `OMP_GUI_AXE=<dir>` (`e2e/axe-surfaces.e2e.ts`) runs axe-core and a Tab walk (every stop must draw a focus ring: Tailwind 4's `outline-none` beside `focus-visible:outline-2` drew none on ten controls; `tokens.test.ts` also refuses that pair) over the same surfaces on the dev harness, one test per look (`OMP_GUI_AXE_LOOKS=<width>-<theme>-<lang>,…`, 390/412 a phone and wider the Electron window; default 1280 light and dark en, 390 light ko and dark en; `_ONLY=<regex>`), writes `<look>.json` and fails a look on any violation or a surface that did not open; rules that cannot hold are listed in the file with their reason (`region`, the composer's combobox). All four default looks were clean on 23 Oct 2026 (≈ 2 min a look).
  - `OMP_GUI_RESPONSIVE=<dir>` (plus `_WIDTHS`, `_LANGS`, `_THEMES`, `_ORIENT`, `_DEVICE=touch|web|electron`, `_AREA`, `_ONLY=<regex>`, `_SHOTS=all|none`) writes `report.json`, `summary.md` and `shots/`. Run it one look per `bun run locked` hold (`-g "responsive 390P-light-en$"`, ≈ 1.5–3 min) with `--trace off --output <private dir>`: a Playwright locator action has no default timeout (the audit sets 8 s) and a shared `test-results/` is wiped by other agents' runs.
  - The default smoke (390 + 834, en light) refuses page overflow, an escaping element, an off-screen popover and, at 390, an app chrome above 19.4 % of the screen. It also pins what the pass of 20 Oct 2026 fixed: at 390 and 834 no stolen tap, overlap or inset finding on fourteen key surfaces (the feedback and worktree dialogs' checkbox and radio rows, a question card and a figure header among them) and two host sheets, a question card's step tabs and a figure header's buttons as 36 px targets, whole summary figures on a work card and 36 px controls in a docked tablet sidebar; a tap on the drawer's edge strip reaches the PR row under it; a 1100 px Electron window keeps Settings › Memory's tabs clear of the project picker and cuts no Run popover choice; an Autopilot run's board (1133 docked, 390 in the strip) never scrolls sideways, its controls are 36 px targets and the goal bar's Pause, Edit and Drop keep their taps; the transcript never scrolls sideways (`overflow-sideways` covers `.omp-transcript-scroll` and names the element that widens it) on every look, and an 800 px dark and a 1280 px Electron window check it on the session and the reply showcase's text, tables and code (6 Nov 2026: a reply picture's chip, its file unreadable, spilled its full path 247 px out of its figure cell; the showcase keeps a row of pictures whose files are gone; every parity view fails the same way); a picture viewer (`image-viewer`: a chat pane's viewer stays inside the pane under the title bar, the full size's unlayered `100dvh` overridden, its bar's buttons 36 px targets on touch and the picture clear of the home bar) fits the screen; more toasts than a 1280×480 window holds scroll inside it (`Toast.tsx` `data-toast-scroll`, top from `--omp-toast-top`), a wheel over a toast reaching the newest. Every look emulates Reduce motion, and under it a mermaid diagram still lays out: `global.css`'s reduced-motion rule ends animations at 0.01 ms but runs no transition at all (`transition-duration: 0s`), since at 0.01 ms every element began one on any style change and code that styled and measured in one task (mermaid's labels) read the old size.

### Lock on a small machine

- **One heavy hold at a time on 16 GB** (2 Nov 2026, this Mac mini Mac16,10, 16 GB). Between 08:05 and 08:38 KST 11 agent sessions here ran check:changed, tsc, vitest, Playwright and builds; the per-kind slots let one of each kind run together and typecheck and targeted vitest ran outside the lock. At 08:47:57 WindowServer's userspace watchdog fired with 445 processes and 29.9 GB of footprint (node ×9 10.0 GB, four of them tsc/vitest at 2.0–2.7 GB; bun ×39 8.6 GB; chrome-headless-shell ×9 3.5 GB; rustc ×12 2.3 GB) while it paged in compressed memory, and the owner had to reboot.
- **What it does.** Every hold takes a slot of the machine-wide `heavy` semaphore first, then its kind's (`acquireHold` in `scripts/lock-slots.ts`; folders `heavy.<i>` and `heavy.queue/` under the same lock root, so every checkout and worktree shares it). The heavy queue is one FIFO for all kinds: a stream of Playwright runs never starves a build. Stale heavy slots and tickets are reclaimed like any other; the old `/tmp/ompdesk-build.lock` still holds everything.
- **Size.** `heavySlots(RAM)` = ⌊(GB − 8) ÷ 8⌋, at least 1 and at most the kinds' slots together (7): 16 GB → 1, 24 → 2, 32 → 3, 64 → 7, the old per-kind behaviour. 8 GB stay for macOS, OMPdesk and its sessions (bun ×39 held 8.6 GB in the incident) and each hold gets 8 GB: a whole-project `tsc --noEmit` alone peaked at 3.0 GB RSS (measured 2 Nov 2026, `/usr/bin/time -l`), and vitest or Playwright workers add an app or a fork each. `OMPDESK_LOCK_SLOTS=heavy=N` overrides for measuring; `OMPDESK_LOCK_RAM_GB` stands in for RAM in tests only.
- **Workers.** `ramWorkers(RAM)` = one per 8 GB (2 on 16 GB) caps Playwright's per-run default and share (`workersFor`) and vitest's default `maxWorkers` (`vitest.config.ts`); `OMP_GUI_WORKERS`/`OMP_VITEST_WORKERS` still override.
- **Typecheck is a heavy hold**: `bun run check:types` runs `tsc --noEmit` through `locked --kind vitest`; under check:changed or the gate it runs inside their vitest hold.
- **Nesting never deadlocks.** `OMPDESK_BUILD_LOCK_HELD` carries `heavy` with the kinds a holder has. A locked command nested under it runs inside it whatever its kind, except a build, which still takes the build slot (builds into out/ never overlap). The only wait a nested command makes is for the build slot, and a build holder never waits on anything, so no cycle of waits can close (with per-kind waits, a build holder nesting vitest beside a vitest holder nesting a build waited for ever). Two phases of one gate in one process are not nested: each takes its own heavy slot, so on 16 GB the gate's vitest phase and its build run one after the other. Inside their one vitest hold, check:changed and the gate run typecheck, biome, the surface policy and vitest one after another when the machine has a single heavy slot (`runSteps` in `scripts/build-lock.ts`), side by side otherwise.
- Pinned by `scripts/lock-slots.test.ts` ("the machine-wide heavy slots": mixed kinds from two checkouts one at a time in FIFO order, nested under a holder at once, a stale heavy slot reclaimed, the old lock blocking) and `scripts/build-lock.test.ts` (workers on 16 and 64 GB, a nested build under a one-heavy-slot machine, two holders nesting each other's kind).

### CI

- **Public-repo trust rules.** No workflow uses `pull_request_target`. A pull request (fork or not) runs only ci.yml's Linux jobs with a read-only `GITHUB_TOKEN` and no secrets. release.yml starts only from a push to `main` that touches `package.json` or from a manual dispatch (write access). `MAC_SIGNING_P12_BASE64` and `MAC_SIGNING_PASSWORD` are read only by `mac`'s Package step and only for `main` (a dry run from another ref signs ad hoc). The former self-hosted runner (`ompdesk-mac`) is retired; its secret `RUNNER_STATUS_TOKEN` is unused.
- **Why no bun cache.** `actions/cache` keyed on `bun.lock` saves nothing: a cold `bun install` takes 2–10 s on Linux and ~10 s on macOS (a restore costs about as much), and on Windows restore + install measured no faster than the 28–41 s cold install, with a 42 s upload per lockfile change. So no job caches bun's install. The two caches that pay are the memory build's (`Swatinem/rust-cache` and the built binary, see "Memory (ai-memory)"). A pull request's cache entries are scoped to its own ref, so a fork's run can never put a binary in front of `main` or a release.
- **Electron comes from a cache, installed in one place** (8 Nov 2026: five runs on `main`, e2e-nightly, release v0.119.4 twice, omp-latest and ci, went red before any test ran: electron's postinstall download got 502/503/504, and `socket hang up` in electron-builder's win Package step). The step log says `Electron <version>: cache-hit=true|false`, with `@electron/get` debug lines. Tests are never retried. A pull request or branch reads `main`'s entries and writes its own.

- **Test scope.** release.yml's `win-platform` job runs `bun run test:platform --shard=n/3` (`vitest run --exclude "src/renderer/**"`), the suite minus the renderer, as three shards. - **Windows test pitfalls the platform job found** (release run 41071663946):
  - A process holds the folder it runs in: `rm` of a child's cwd fails `EBUSY` until the child exited. A test that runs a child in a temp folder stops it and waits for it to be gone (its pid, or the product's own stop that awaits it) before removing the folder (`mcp-hub-rea.test.ts` "runs each omp's REA in that omp's folder").
  - A live worker holds the files it opened: the stock helper's SQLite databases (`history.db-shm`, `agent.db`) and the native module stock copies into a private HOME (`.omp/natives/<version>/pi_natives.*.node`). `child.kill()` returns before the process is gone, so a cleanup that removes the folder right after fails `EBUSY`/`EPERM`; await the child's `exit` first (`stock-helper-accounts.test.ts`, `stock-helper-sessions-named.test.ts`). An exited child's folder can still be refused for a few hundred ms, as `EBUSY` or `EPERM`; `removeWhenFree` (`src/main/test-folders.ts`) retries both.
  - A bound under test (a step's or drain's timeout) is reached on a fake clock at the moment the test means, never by a short wall-clock bound over real git: each git process costs ~30 ms idle and over a second on a busy runner, so a 300 ms drain bound stopped the drain the case expected to pass mid-push (and its `git-receive-pack` then held `remote.git` at cleanup). `vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout"] })` for the stuck part only, `vi.useRealTimers()` before the real work (`autopilot-ship-stall.test.ts`).
  - A path compared or used as a key keeps the spelling the product saw. windows-latest's `%TEMP%` is the 8.3 `C:\Users\RUNNER~1\…`: `os.tmpdir()`, `fs.realpathSync` (JS) and a child's `process.cwd()` keep it, `fs.promises.realpath` and `fs.realpathSync.native` spell it `C:\Users\runneradmin\…`. A test takes the path the product reported (a `get_state` answer, an event) instead of rebuilding it with `realpath` (`link-traffic-relaunch.test.ts`'s relaunch; see the remote-devices rule).

Skipped on Windows with the reason in the file: `bridge-ssh-diagnostics` (stock verifies no SSH login there).
