## Composer

User's rules: **composer controls never move outside the composer box, and the phone composer never folds**; **the Run sheet is one line per row**. Never undo either.

### Answering a steer first

- **A person's message that joins a running turn is answered in text before the next tool call**. Bridge `resources/gui-bridge/answer-first.ts` (feature `answerFirst`) and `typed-prompts.ts` (feature `typedPrompts`), main `src/main/local/prompt-origin.ts` `noteTypedPrompt`.
- Main tells the omp who typed each message: just before a person's own `prompt`, `steer` or `follow_up` reaches the omp (`ipc.ts` `dispatchRpcCommand` for IPC, a window or the paired phone page; `remote/host-services.ts` `#run` for a paired device's prompt into a tab this computer runs; never Autopilot's prompts, an agent's `<ompdesk-agent-message>` (`personsPrompt`), a relaunch's continuation or a retry), it sends the bridge `typed_prompt {text, steer}` (`steer` = stock `steer`, or `prompt` with `streamingBehavior: "steer"`; bounded at 500 ms, a refusal ignored). The bridge keeps the notes in one store (`typedPrompts`, 30 min, newest 16) that memory recall and answer-first each take from once.
- At `before_agent_start` of the batch that delivers the steer (its `prompt` is the queued texts joined), while the agent loop owns a turn (`agent.state.isStreaming`; a steer that found the turn over starts a fresh one and gets nothing) and the note says `steer`, the hook returns one hidden companion `ompdesk-answer-first` (`display: false`, `attribution: "agent"`): "The person wrote the message above while you were working. Answer it in text now, in this turn, before any further tool call or wait; then continue the work." Stock appends it right after the batch in every steering mode (agent-core `#prepareQueuedMessageBatch`), so it needs no steer of its own. It is agent-attributed because pi-ai's Anthropic provider upgrades it to a mid-conversation `system` turn, which models heed; a user-attributed one was skipped. A follow-up gets none; a subagent never.
- **The companion alone is not enough, so the same hook opens a gate**. From that companion until a response of the turn says something to the person (a text block or a narration block holding a letter or digit), the `tool_call` hook refuses every call of the main agent with "Not run: the person wrote to you while you were working and you have not answered yet. Answer their message in text first, then call tools again." A narration block is a thinking block whose signature names it narration (pi-ai `ThinkingContent.narration`, set at `thinking_end`; stock shows it as answer text, `presentNarrationAsAnswer`), so it counts as an answer. Text is heard as it streams (`message_update`), because agent-core prepares a message's calls **before** its `message_end`; `message_end` still closes the gate for a message that never streamed. Let through: `read`, `grep`, `glob`, `find` (what an answer needs) and `ask`. Only text or the turn's end (`agent_end`, a Stop included) closes it; no give-way after silent responses. A subagent's or the advisor's calls (`ctx.agent.kind !== "main"`) are never held; an agent's mail or a reminder never opens it.
- Pinned by `bridge-answer-first.test.ts` (companion cases, store take-once and TTL, the gate in stock's event order), `local/prompt-origin.test.ts` (`noteTypedPrompt`), the daily-limit case of `remote/host-services.test.ts`, `e2e/answer-first-remote.e2e.ts` and `e2e/answer-first-phone.e2e.ts` (the `typed_prompt {steer: true}` record lands right before the steer).

### Ask forms (pictures before choosing)

- **An agent's question shows its pictures before the person chooses**. Stock's `ask` takes one HTML `<form>` and only a UI context with `formDialog` draws it whole; RPC has none, so without OMPdesk stock walks it field by field through `select`/`input` and drops its paragraphs, tables and pictures.
- `resources/gui-bridge/ask-form.ts` (feature `askForm`) defines `formDialog` on the session's RPC UI context, as a getter that exists only while the host has the ask card on (`set_ask_dialog`), and asks the whole form through that context's `askDialog`: one card question per named field, the content before it as Markdown in the question's `context` (`ExtensionAskDialogQuestion.context`, OMPdesk's own field; pictures in a row share one paragraph, `<svg>` a ```svg fence), the section's legend as its header. The form's rules are stock's html-form helpers (`parseHtmlForm`, `fieldQuestions`, `choiceValue`, `textValue`, `fieldError`, `defaultFormData`); an unanswered field keeps the form's value, a field `fieldError` refuses is asked again with the error as its header, a timeout submits the values so far.
- The card (`ExtensionDialog.tsx` `AskDialog`) is titled by the current question's header, else its first line, and the body then draws only the lines after that first line, so the question is said once; the title wraps, never cut (`PromptCard`). Its region is named as a question waiting for an answer, "Question: <title>" (`extDialog.ask.region`), the visible title unchanged. The step strip is the kit's segmented `Tabs` (`data-ask-steps`, each tab `data-ask-step`; an answered step leads with a ✓ and trails an `sr-only` "answered"; the tab's tooltip names its question), with no step counter beside it: a click moves focus into that question, an arrow keeps it on the strip. It draws `context` above the question through `MarkdownRenderer`: a run of pictures is a figure row (alt as caption, each zoomable), thumbnails at most 8rem tall so the question and choices stay in view (`[data-ask-context]` in components.css); a local picture is read through `fs.readImage` (from the host on a paired computer and the phone). A remote URL stays a link. The `reply-presentation` section tells the agent to put each picture of a choice in the form (`<img>` above the choices, alt naming the option).
- **A Windows drive path is a picture's path, not a URL scheme**: Markdown percent-encodes `![…](C:\shots\a.png)`, and the URL sanitizers would drop it as scheme `c:`. `markdown.tsx` lets every drive letter through for `<img>`/`<video>`/`<audio>` `src` (`WINDOWS_DRIVES`, `WINDOWS_DRIVE_PATH`) and `classifyImageSrc` decodes a bare path as it decodes a `file:` URL's. The bridge escapes a picture's backslashes in the destination it writes, so `\.omp` stays a folder name. Pinned by the drive-path case of `markdown-image.test.tsx`.
- Pinned by `bridge-ask-form-stock.test.ts` (installed omp's `ask`: one frame with pictures in `context`, answer back as form data), the pictures case of `ExtensionDialog.test.tsx`, and the parity surface `card-ask-pictures`.

### Run controls (Stop, Esc, queue)

Code: `lib/messages.ts` (`abortActiveTurn`, `stopFromEscape`, `restoreAbortedQueue`, `resumeRestoredQueue`), `stores/composer.ts`. Stock's semantics, nothing new on the wire.

- **One Stop per turn**: `composer.stopping` is set before `abort_and_restore_queue` goes out and held until the session's `isStreaming` goes false (10 s cap, `STOP_SETTLE_MS`), so a double click, a double Esc or Stop + Esc send one command.
- **Esc while a turn runs and the field holds text or a picture only arms** (`composer.stopArmedAt`, `DOUBLE_ESC_MS` 1.5 s; an edit of the draft disarms; "Press Esc again to stop", `input.escAgainToStop`). A second Esc inside the window, or an empty field, stops. Popovers/menus/dialogs that consume the Esc never abort (`defaultPrevented`/`[role=dialog]` guards in `App.tsx`). The Stop button never asks twice.
- **Stop never releases the queue**: stock withdraws it. `restoreAbortedQueue` keeps each message its own `composer.restoredQueue` item (steers, then follow-ups, oldest first) while a view that shows them is mounted (`ComposerRestoredQueue` registers `restoredTrayMounted`): Resume sends the first as a `followUp`-behaviour prompt and the rest as follow-ups, "Put in the field" edits one, nothing is sent by itself. Without such a view they merge ahead of the draft with a blank line between and one toast.
- **Withdrawing a prompt that waits on the automatic mode choice returns at once** (`runAutoMode` `signal`, `composer.decidingMode` for the "deciding" cue); a decision the host makes afterwards is ended when it lands (`onLateDecision`).
- **⇧Tab is never ours** (keymap chords need ⌃/⌥/⌘; Shift+Tab is focus navigation). The thinking level cycles on `thinking.cycle` (⌥⇧T on both platforms, remappable in Settings › Keyboard and the palette).
- **Pictures sent as steers** are remembered by queue chip id in the queue store (`expectImages`, matched by text when the chip appears, dropped when an edit or a steer→follow-up move re-queues text only), so the pill and popover count them although stock's lanes are text only. A picture-only chip's "[Image]" is the UI language's word (`lib/queue-chip.ts`). `queue.moved` says where an edited message landed (the end of its lane).
- `lib/composer-blocked.ts` `composerBlockedBy` names what the cards above wait for (`ask` | `approval` | `plan`). Placeholder priority: blocked > editing queued > suggestion > follow-up > steer > idle.
- **A session activation hands the next key to the composer** (`lib/tab-focus.ts`, installed in `App.tsx`): after a tab or session change, focus on `<body>`, a sidebar button or a pane that just left moves to the active composer; a dialog, a text field, the terminal, the files editor and touch input are left alone. The move waits a frame for React's commit, and a printable key typed before that frame moves it at once so the key lands in the new composer (`tab-focus.test.ts` "at the first typed key").
- **F6 / Shift+F6 move between the window's regions** (`lib/region-cycle.ts`, installed by `App.tsx` in the capture phase so the terminal cannot keep it): the sidebar (its roving row), the focused pane's transcript, its composer, its docked work board, the side panel; a region not on screen is passed over and nothing moves while a dialog or menu is open. Not a keymap action (chords need ⌃/⌥/⌘), listed as a static row in Settings › Keyboard. Pinned by `region-cycle.test.ts`.
- **A shortcut or menu command given while the active tab changes waits for it** (`lib/tab-routing.ts` `waitForActiveTab`, `openingTab`; called first by `App.tsx`'s keymap dispatch and menu handler): while ⌘T's tab is not yet answered by main, or the selected tab's route has not landed, commands queue in order and run one at a time, each after the route the one before it started has landed; a command still waiting after `ROUTE_WAIT_MS` (2 s) is dropped. ⇧⌘]/⌥⌘] step from the tab the latest `switchTab` is on its way to (`steppingFromTabId`), so a key in the gap never acts on the tab being left. Pinned by `tab-routing.test.ts`, the stepping case of `tabs.test.tsx` and desktop.e2e's ⌘T-then-⌘W lifecycle.
- The queue is one pill in the send cluster (`ComposerQueuePill`, `[data-queue-pill]`) opening a popover (a bottom sheet on a phone): lane headings (`queue-lane.tsx`), the policy line from `steeringMode`/`interruptMode`, rows `Edit: <text>` with Steer now primary. Nothing is added to the box while messages wait (`e2e/composer-queue-view.e2e.ts` checks 0 px). Edit queued (`composer.editingQueued`, `ComposerQueueEdit.tsx`) takes the field over; Cancel/Esc restore the exact draft snapshot; Send becomes a save ✓ (`composerQueue.editSave`). Stop pauses: `ComposerRestoredQueue` is one 36 px row (chips, Resume, Discard). `ComposerQueueLive` is the single polite status region.
- Pinned by `messages.test.ts`, `auto-mode-client.test.ts`, `queue.test.ts`, `tab-focus.test.ts`, `ComposerRestoredQueue.test.tsx`, `e2e/composer-flows.e2e.ts`, `e2e/steer-send.e2e.ts`.

### Delegation strength

- The Run chip's Delegation section (`layout/composer/DelegationField.tsx`, mounted by `RunChip.tsx`; the phone's Run sheet shows it too; hidden when the omp cannot report a strength) sets Your settings / Solo / Assisted / Collaborative / Swarm per tab through `get_delegation`/`set_delegation` → bridge `modes/delegation.ts` (rules `delegation-core.ts`, presets `delegation-contracts.ts`).
- Each strength is stock `task.eager`, `task.maxConcurrency` and (Solo) `task.maxRecursionDepth = 0` held as runtime overrides, never written to config.yml; stock's own listeners rebuild the prompt and drop or restore the task tool.
- The last pick is prefs `delegationMode`, passed as `OMP_GUI_DELEGATION` on every spawn (`sidecar.ts`; omitted for "default") and applied inside the extension factory like the thinking default. A Settings write of one of those settings releases the strength.

### Working cue

- **Working state is a light over what is already on screen** (the user's rule; no border light of any kind). One component and one stylesheet (`components/common/LiveShimmer.tsx`; `styles/components.css` `.omp-live-text`, `.omp-live-sweep`), one rule (`layout/live-work.ts` `liveWorkState`, `workingAgentCount`). **No new words, no new elements that take space**: a working session's **own title** shimmers (`LiveText` around the existing text: a sidebar session row, this computer's or a paired host's, through `SessionLiveTitle` with the count of its running family children, so a host's row lights for a child no tab here holds; a split pane's header title through `useTabLive`, `layout/SessionLiveTitle.tsx`), and the **composer box's background** carries the same light (`LiveSweep`, `ComposerLiveSweep` mounted first in `.omp-composer-box`: an `aria-hidden` layer at `z-index: -1` under `isolation: isolate`, so text and controls sit above it; its band is accent at 11 %, so a draft stays fully readable).
- States: `turn` (its own turn runs) the full light; `background` (the turn is idle, work it started still runs) the same animation and duration, lower contrast only (the title's band 62 % instead of 28 % of its colour, the box's 5 % instead of 11 %), so a switch never restarts it; `waiting` (the session needs the person, `sessionAttention`: its question or approval, or a session it opened waiting on an answer; a session that is down says that instead) no sweep: the title turns `--sc-warning`, the box holds a still 7 % warning tint; `null` plain text, nothing drawn. Every sweep is 3 s (`--live-period`, `LIVE_PERIOD_MS`) with a hold at each end and starts on one shared phase (`--live-delay` = minus the document clock within the period, set when the work starts), so titles and the box sweep in step. Every light moves by `transform` alone, so nothing repaints: the box's is one band inside a clipped layer; a title's own glyphs turn transparent and a copy of its words (`LiveText` `text`, drawn by `.omp-live-shine-words::before` from `data-text`, so neither the DOM's text nor the accessible name doubles) sits in a window whose static mask holds the band, the window sliding across while the copy slides back by the same amount. Both move in `steps(50)` over the 2.1 s crossing (`--live-steps`, about 24 a second). Never `background-clip: text` (repaints every frame, and draws no title in Electron). Nothing breathes by opacity, nothing changes layout, all rest while the window is hidden (`data-paused`). Reduced motion runs no animation: a working title is still text with an accent cast (55 %, 30 % for background work), the box a still 5 % (3 %) accent tint. Any new looping cue draws still under it. **Software compositing** (`html[data-gpu="software"]`, set by main when `app.getGPUInfo("complete")` reports `gpu_compositing` not enabled; `softwareCompositing()` in `gpu-fallback.ts`) keeps every loop, held at ten frames a second by `lib/cue-clock.ts`, because a still cue reads as the app having stopped. Between turns the Send button also gets a still ring with a hint tooltip (`ComposerSend`, `input.live.background`), stepped out of the way while the field holds a draft.
- Background work = main's `settling` (`IpcTabInfo.settling`, `SessionSummary.settling`; `runSettling` in `sidecar-run-state.ts`, `RunState.turn` tells a turn from the time after it: stock's `prompt_result.sessionSettled: false` keeps `status` `running` until `session_settled` for resume, Stop and the quit guard, covering its subagents, async shells and queued wakes for hidden and paired-host tabs alike, with no poll), plus its working subagents (a sidebar row reads `SessionSummary.agents`; a pane header reads that tab's roster store directly) and the sessions its agent opened that run (not waiting; its whole family, on a paired device included); a session no tab holds counts only its opened sessions. **Restraint**: only top-level session rows and pane headers wear the title light; a child row (subagent or opened session) stays a plain row whose status token is the working arc while it runs (waiting ⚠). The family chip shows its count once: while something runs, one filled still accent pill with the kind glyph(s) and the running count (`data-family-running`); with none running, the plain muted counts per kind (`data-family-agents`, `data-family-sessions`); the label keeps the totals. `data-pane-running` = the turn only; compacting and (re)starting keep the header's spinner.
- **The age slot** (the user's rule): a session row's end shows the time since the session last did something, and while its work goes on (the title light's rule) the **working arc** instead (`common/WorkingArc.tsx`, `SessionLiveAge` in `layout/SessionLiveTitle.tsx`, `data-session-working`). Waiting on the person is not working: the waiting token stays (`.omp-sidebar-approval`, the attention word: Needs input, Needs approval, or Child waiting; capped at 7.5rem). A parent row says Child waiting whichever session the window shows (`childrenWaitingOf`, the board's `openedChildRows`), and is not busy for it (delete stays allowed): only its own question, approval or run makes a row busy. The age stays in the slot, `visibility: hidden` (`.omp-live-age`), so the row keeps its width. A running family child's token is the same arc (`FamilyStatus`), its age back when it stops. The arc is two 140° arcs (head ease-out, tail ease-in: one stroke of 140°–273°), advancing 180° more each 1.5 s turn, over an 18 % track. The easing is sampled into generated keyframes (`omp-working-arc-head`/`-tail`, 12 samples a turn, two turns per 3 s `--arc-period`) played in `steps(3)` per sample on one grid every arc shares (`--arc-delay` from the document clock), so all arcs are one 24 fps compositor stream. Two transforms, no dash animation (it repaints), at rest while hidden (`data-paused`), a still 270° arc under reduced motion (`html[data-gpu="software"]` keeps it turning at ten frames a second); `background` only fades its colour. Every age ticks on the shared clock (`useTimeAgo`; a family child's too, `TimeAgo`).
- **What the age reads**: `SessionInfo.modified` is the session's newest conversation message's own `timestamp` (stock helper `session-activity.ts`, read from the journal's end in a 64 KB window growing ×4 to 4 MB, cached per `mtime:size`), else the file's mtime, because relaunches append non-message entries that move the mtime. Every reader of `modified` means recency (sidebar age and order, session picker, project recency, agent tools' listings), so the helper replaces it at the source. Pinned by `session-index-activity.test.ts`.
- **How the age is written** (the owner's rule): a session row's age, a family child's too, here, on a paired computer's section and on the phone, is always a short age, never a date: "just now", "8m", "3h", "2d", "3w", "5mo", "2y" (Korean "방금", "8분", "3시간", "2일", "3주", "5개월", "2년"), so titles keep their width. `TimeAgo` (`common/TimeAgo.tsx`) asks `formatTimeAgo(value, { older: "age" })` (`lib/format.ts`, the one compact-age formatter; its other callers keep "Aug 2" past a week) and carries the exact date and time (`formatClock`) as the `<time>` element's `title`; a stored row's tooltip (`titleText`, `Sidebar.tsx` and `SidebarDevices.tsx`) ends with it too, since a hovered row shows its ⋯ in the age's place. Pinned by the short-age cases of `lib/format.test.ts`.
- **No leading slot** (the user's rule): a session row (local or a paired host's) leads with nothing, so its title starts at its group header's content edge (rows `padding-left: var(--sc-space-2)`, the header button's `pl-2`); its state is its title's light or its left-edge bar (waiting, error; an overlay, no reserved space), its words the tooltip and screen-reader text. One small mark sits at the row's end before the age (`data-sidebar-row-end`): an unseen finish as a ✓ (`data-sidebar-done`, a shape, not a colour alone), else a chat, pin, worktree (`data-sidebar-worktree`, see Worktree names) or fork glyph. A family child keeps its relation to its parent's title (`SidebarSubagents.tsx` `INDENT`/`CONNECTOR`: connector 2 px left of it, glyph 6 px right, a sub-subagent one 16 px step more; an Autopilot run's child row one 16 px step in).
- **The model's wait is said, not shown as thinking**, because such a wait is the provider's answer, never the model thinking (`.omp/rules/interrupted-work.md` Turn stages). The bridge sends `model_request` (`sent` as the main loop's own request goes out, `answered` when its headers come with a status below 400; never for an advisor's or another side request; two frames per model call, no timer: `wrapStreamFn` in `turn-stages-core.ts`, contract `MODEL_REQUEST_EVENT` in `turn-stages-contracts.ts`), main routes it like `token_rate` (`AGENT_EVENT_TYPES`, snapshot-neutral in `use-rpc-events.ts`), and the messages store's turn meter keeps `modelWaitSince` (the first unanswered request of the call; cleared by an answer, the first output, the run's end or a new run). `lib/model-wait.ts` `useModelWait` names it once it has lasted `MODEL_WAIT_SHOWN_MS` (30 s, so a normal call never flashes the words), on the shared clock: "Waiting for the model's response · 2m" / "모델 응답 기다리는 중 · 2분" (`chat.awaitingModel.wait`, `formatSpan`) replaces "Thinking…" as the work card's head before the first event (`WorkCardPending`) and between steps (`LiveStepPeek`'s thinking head, its thinking sub line then empty; an agent lane keeps its own words), the board's Now row (`WorkBoard` `turnState`) and the strip's "Working…" (`WorkBoardChip`; a plan's count keeps the strip). The paired phone page draws the same components from the same frames. A window that joins mid-wait learns it only from the next request. Pinned by `bridge-turn-stages.test.ts`, `bridge-turn-stages-stock.test.ts` (a silent server's attempts, which stock's provider repeats by itself: one `sent`, no answer), `turn-meter.test.ts`, `model-wait.test.ts`, `LiveStepPeek.motion.test.tsx`, `WorkBoard.test.tsx`, `WorkBoardChip.test.tsx`.
- **A wait that several sessions share says so**, because a shared wait is the provider's queue for the account, not one session. `src/main/model-wait-count.ts` `ModelWaitTracker` reads every tab's agent events in main (`sidecar-pool.ts`; a tab a paired device runs here is fed by `host-services.ts`; the `model_request` frame carries the model's `provider`, a frame without one joins no group), ends a wait like the turn meter does (answered, first output, run start or end, tab released) and counts, per provider, the tabs whose request has gone unanswered `MODEL_WAIT_TOGETHER_MS` (30 s); with 2 or more every such tab gets the group's size. Main pushes `IpcModelWaitTogether` (`MODEL_WAIT_TOGETHER`, `modelWait.onTogether`, whole map by tab id, only when it changes; a window opened mid-wait hears the next change) to every window that shows a tab and every paired web page; `stores/model-wait-together.ts` keeps it and `useModelWait` words it: "Waiting for the model's response · 4m · 3 sessions waiting together" / "모델 응답 기다리는 중 · 4분 · 세션 3개가 함께 기다리는 중" (`chat.awaitingModel.together`). A tab a paired computer runs counts on the host: the host sends `host.modelWait.changed` (`{ counts: { provider: n } }`, to every connected device, and on a connection's first call) from its own tracker and the viewer's tracker takes it for that device's tabs (`setHostCounts`); an older host sends none and the tab counts what this computer sees, an older device drops the event. Display only: nothing waits for the count. Pinned by `model-wait-count.test.ts`, `model-wait.test.ts`, `WorkBoardChip.test.tsx` and `e2e/model-wait-together.e2e.ts` (fake omp `fixture:model-request:sent:<provider>`).
- **Unfocused, the cues move at ten frames a second** (the owner's rule: a still cue reads as stalled, so they never stop on screen). `lib/cue-clock.ts` (`installCueClock`, loaded lazily by `main.tsx`): while the window is visible but `document.hasFocus()` is false, or while it composites in software (`html[data-gpu="software"]`, watched by a MutationObserver since main marks it after the first paint), every running endless animation (titles, sweep, arcs, the work card's motion, the board's pulse, spinners) is held at playback rate 0 (its play state stays `running`, which the e2e pins read) and one 100 ms clock (`CUE_STEP_MS`) moves them all to where they would be; focus restores rate 1 and each loop's own start time, so the shared phase holds. Hidden still rests (`data-paused`). Pinned by `cue-clock.test.ts`; cost measured with `e2e/load-performance.e2e.ts`.
- Pinned by `ComposerLive.test.tsx` (states, no border light, every `omp-live-*` keyframe animating transform or opacity only, still forms), the working-title cases of `Sidebar.test.tsx`, `SidebarSubagents.test.tsx` and `SplitWorkspace.test.tsx`, `sidecar-pool.test.ts` ("tells a turn from background work"), `row-glow.e2e.ts` (two transform animations per working title, words visible in every sampled frame across states and themes), `row-glow-harness.e2e.ts` (`OMP_GUI_WORKING_SHOTS=<dir>` writes captures), `composer-live.e2e.ts`, `background-tabs.e2e.ts` and the perf-gated `sidebar-edge-light.e2e.ts`. - The field is uncontrolled while typing (React 19 re-syncs a controlled textarea's `defaultValue` on every key, breaking ⌘Z): the draft store is the source of truth and every composer write goes through `placeDraft`.

- The take shows as a bar under the field (`ComposerUnderField`, `DictationOverlay.tsx`, `use-composer-dictation.ts`, `lib/voice.ts`), never over the draft. A failed take keeps a `failure` kind (denied, no-device, in-use, busy, empty, no-model, failed): one sentence plus a Details toggle (none for busy/empty); only no-model offers Open Settings.
- **Which model hears the speech** (the owner's rule): the speech's language is the conversation language (Settings › General, the device language by default; a paired host's tab follows the host's, as replies do), else stock's `stt.language`; a `language` the request names wins. The bridge reverse-maps the English name OMPdesk hands omp (`speechLanguageOfName`, `resources/gui-bridge/stt-language-core.ts`).
  - One rule (`sttModelForLanguage`): a language the selected dictation model lacks goes to `whisper-large-v3-turbo` (stock's 99-language tier); stock's `englishOnly` decides Nemotron, and `MODEL_LANGUAGES` lists Parakeet v3's 25 from NVIDIA's model card. English stays on Parakeet. Pinned by `bridge-stt-language.test.ts`.
  - A model not in omp's cache (`~/.omp/agent/cache/tiny-models`) downloads through stock's `downloadSttModel`, one download per model (`SttModels` in `stt-language-core.ts`, used by `resources/gui-bridge/voice.ts` for `stt_prepare` and `transcribe_audio`). Dictation's whole clip waits for that download.
- The take is heard on the model its language needs: Korean on Parakeet v3 goes to Whisper large-v3-turbo, and a take before that model is in omp's cache waits for its download inside `transcribe_audio`. Meanwhile the bar says so with the language and a `ProgressBar` ("Preparing Korean recognition…", `data-dictation-download`): from the take's first wait `recordAndTranscribe` asks `stt_prepare` every 500 ms (`onPreparing({language, percent})`; `prepareRecognition`, dynamically loaded from `lib/stt-prepare.ts` so the phone's first screen does not carry it). Once the model is here (or its download failed, or the omp has no `stt_prepare`) and the take is still being transcribed, `onPreparing(null)` puts the bar back on "Transcribing…"; nothing is reported after the take settled. A whole take is one Whisper pass already. Parity surfaces `composer-dictation-preparing` and `composer-dictation-downloaded`; pinned by `voice.test.ts` and `InputArea.queue-shorthand.test.tsx`.
- The + menu lists "Dictation" while `stt.enabled` is off and opens Settings (`agent:setting-stt.enabled`) without writing it. The item reads "Turn on dictation…" ("받아쓰기 켜기…", `voice.menu.enable`), one line like every item of the + menu (History keeps only its shortcut).
- The subagent steer box (`SteerSubagentForm`) grows like the main field (`fitFieldHeight`) and is never `disabled` while sending (`aria-busy`).
- The composer follows the keyboard (`--kb-inset`, `lib/keyboard-inset.ts`) with no transition: iOS animates the keyboard itself and the visual viewport events arrive per frame.
- Read-aloud (`lib/voice.ts` `startVoiceAutoSpeak`) follows stock `speech.enabled` and `speech.mode`: `assistant` speaks each finalized assistant message, `all` also speaks tool results, and `yield` speaks the run's last assistant message when the run ends.

### Enter on a touch input

- `useShellInput() === "touch"` (desktop byte for byte unchanged): a soft keyboard's return key adds a line and only the Send button (or ⌘↵ / the follow-up chord) sends; `enterkeyhint="enter"` on the field.
- A physical keyboard on a tablet gets the desktop's Enter back: `lib/hardware-keyboard.ts` latches, for the page's life, the first key only such a keyboard makes (Esc, Tab, arrows, Home/End/Page keys, F-keys, a chord with ⌘ ⌃ ⌥, Shift with a named key such as Shift+Enter; never a letter, Backspace or Enter, which some soft keyboards report with a `code`).
- Settings › Appearance & input › "Enter sends on touch keyboards" (`displayPreferences.mobileEnterSends`, per device, default off) makes touch Enter send.
- The IME guard runs first, so a composition's Enter is never a send or a newline rule. In `!`/`$` shell drafts the field turns autocorrect, autocapitalize and spellcheck off.
- Pinned by `lib/hardware-keyboard.test.ts`, `InputArea.touch-enter.test.tsx`, `e2e/mobile-enter.e2e.ts` (Chromium + WebKit, en/ko).

### Design record (19 Oct 2026)

Decided by prototype:

- **Toolbar → one Run chip and a toolbar-owned container**: Thinking in 2 taps, nothing moves when a turn starts, Plan mode moves nothing to its left. One Send/Stop button and a lane chip in the free room (see Toolbar).
- **Queue → pill and popover**: the transcript moves 0 px when items queue; lane switching and editing cost 2-3 taps.
- The prototyped phone status chip row is **superseded by the user's rule** (controls stay in the box, the phone composer never folds); no status row and no ⋯ sheet.
- Not decided by prototype: undo granularity, atomic paste markers, `@` ranking, keyboard route to attachments, paste menu anchoring, strip cap, drop target, focus after a tab switch, draft flush on page hide.
