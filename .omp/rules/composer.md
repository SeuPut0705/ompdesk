## Composer

User's rules (19 Oct 2026): **composer controls never move outside the composer box, and the phone composer never folds**; **the Run sheet is one line per row**. Never undo either.

### Run controls (Stop, Esc, queue)

Code: `lib/messages.ts` (`abortActiveTurn`, `stopFromEscape`, `restoreAbortedQueue`, `resumeRestoredQueue`), `stores/composer.ts`. Stock's semantics, nothing new on the wire.

- **One Stop per turn**: `composer.stopping` is set before `abort_and_restore_queue` goes out and held until the session's `isStreaming` goes false (10 s cap, `STOP_SETTLE_MS`), so a double click, a double Esc or Stop + Esc send one command.
- **Esc while a turn runs and the field holds text or a picture only arms** (`composer.stopArmedAt`, `DOUBLE_ESC_MS` 1.5 s; an edit of the draft disarms; the view says "Press Esc again to stop", `input.escAgainToStop`). A second Esc inside the window, or an empty field, stops. Popovers/menus/dialogs that consume the Esc never abort (`defaultPrevented`/`[role=dialog]` guards in `App.tsx`). The Stop button never asks twice.
- **Stop never releases the queue**: stock withdraws it. `restoreAbortedQueue` keeps each message its own `composer.restoredQueue` item (steers, then follow-ups, oldest first) while a view that shows them is mounted (`ComposerRestoredQueue` registers `restoredTrayMounted`): Resume sends the first as a `followUp`-behaviour prompt and the rest as follow-ups, "Put in the field" edits one, nothing is sent by itself. Without such a view they merge ahead of the draft with a blank line between and one toast.
- **Withdrawing a prompt that waits on the automatic mode choice returns at once** (`runAutoMode` `signal`, `composer.decidingMode` for the "deciding" cue); a decision the host makes afterwards is ended when it lands (`onLateDecision`).
- **⇧Tab is never ours** (keymap chords need ⌃/⌥/⌘; Shift+Tab is focus navigation). The thinking level cycles on `thinking.cycle` (⌥⇧T on both platforms, remappable in Settings › Keyboard and the palette).
- **Pictures sent as steers** are remembered by queue chip id in the queue store (`expectImages`, matched by text when the chip appears, dropped when an edit or a steer→follow-up move re-queues text only), so the pill and popover count them although stock's lanes are text only. A picture-only chip's "[Image]" is the UI language's word (`lib/queue-chip.ts`). `queue.moved` says where an edited message landed (the end of its lane).
- `lib/composer-blocked.ts` `composerBlockedBy` names what the cards above wait for (`ask` | `approval` | `plan`). Placeholder priority: blocked > editing queued > suggestion > follow-up > steer > idle.
- **A session activation hands the next key to the composer** (`lib/tab-focus.ts`, installed in `App.tsx`): after a tab or session change, focus on `<body>`, a sidebar button or a pane that just left moves to the active composer; a dialog, a text field, the terminal, the files editor and touch input are left alone. The move waits a frame for React's commit, and a printable key typed before that frame moves it at once so the key lands in the new composer, not the hidden pane's (`tab-focus.test.ts` "at the first typed key").
- **F6 / Shift+F6 move between the window's regions** (`lib/region-cycle.ts`, installed by `App.tsx` in the capture phase so the terminal, which sends every key to its shell, cannot keep it): the sidebar (its roving row), the focused pane's transcript, its composer, its docked work board, the side panel; a region not on screen is passed over and nothing moves while a dialog or menu is open. Not a keymap action (chords need ⌃/⌥/⌘), listed as a static row in Settings › Keyboard. Pinned by `region-cycle.test.ts`.
- **A shortcut or menu command given while the active tab changes waits for it** (`lib/tab-routing.ts` `waitForActiveTab`, `openingTab`; called first by `App.tsx`'s keymap dispatch and menu handler): while ⌘T's tab is not yet answered by main, or the selected tab's route has not landed, commands queue in order and run one at a time, each after the route the one before it started has landed; a command still waiting after `ROUTE_WAIT_MS` (2 s) is dropped. ⇧⌘]/⌥⌘] step from the tab the latest `switchTab` is on its way to (`steppingFromTabId`), since a switch to a tab that ran out of view first waits for its present. Before this a key in that gap was dropped or acted on the tab being left: ⌘W right after ⌘T closed the old tab (nightly 39525167897), and two quick ⇧⌘] under load landed on the same tab (runtime.e2e, 13 of 20 under `taskpolicy -c background`, 0 of 12 after). Pinned by `tab-routing.test.ts`, the stepping case of `tabs.test.tsx` and desktop.e2e's ⌘T-then-⌘W lifecycle.
- The queue is one pill in the send cluster (`ComposerQueuePill`, `[data-queue-pill]`) opening a popover (a bottom sheet on a phone): lane headings (`queue-lane.tsx`), the policy line from `steeringMode`/`interruptMode`, rows `Edit: <text>` with Steer now primary. Nothing is added to the box while messages wait (`e2e/composer-queue-view.e2e.ts` checks 0 px). Edit queued (`composer.editingQueued`, `ComposerQueueEdit.tsx`) takes the field over; Cancel/Esc restore the exact draft snapshot; Send becomes a save ✓ (`composerQueue.editSave`). Stop pauses: `ComposerRestoredQueue` is one 36 px row (chips, Resume, Discard). `ComposerQueueLive` is the single polite status region.
- Pinned by `messages.test.ts`, `auto-mode-client.test.ts`, `queue.test.ts`, `tab-focus.test.ts`, `ComposerRestoredQueue.test.tsx`, `e2e/composer-flows.e2e.ts`, `e2e/steer-send.e2e.ts`.

### Delegation strength

- The Run chip's Delegation section (`layout/composer/DelegationField.tsx`, mounted by `RunChip.tsx`; the phone's Run sheet shows it too; hidden when the omp cannot report a strength) sets Your settings / Solo / Assisted / Collaborative / Swarm per tab through `get_delegation`/`set_delegation` → bridge `modes/delegation.ts` (rules `delegation-core.ts`, presets `delegation-contracts.ts`).
- Each strength is stock `task.eager`, `task.maxConcurrency` and (Solo) `task.maxRecursionDepth = 0` held as runtime overrides, never written to config.yml; stock's own listeners rebuild the prompt and drop or restore the task tool.
- The last pick is prefs `delegationMode`, passed as `OMP_GUI_DELEGATION` on every spawn (`sidecar.ts`; omitted for "default") and applied inside the extension factory like the thinking default. A Settings write of one of those settings releases the strength.

### Working cue

- **Working state is a light over what is already on screen** (the user's call, 20 Oct 2026; supersedes the border comet and every border light before it: the left-edge bar's light, the masked ring, the two bars, the comet of pills). Prior art read first: Claude.app (`cds-shimmer-text-shine`, 3 s, a hold at each end), Claude Code and Codex CLI (a shimmer over the status word), ChatGPT and the Codex desktop app (`loading-shimmer`), Cursor (the agent's sentence animates); none uses a border light. One component and one stylesheet (`components/common/LiveShimmer.tsx`; `styles/components.css` `.omp-live-text`, `.omp-live-sweep`), one rule (`layout/live-work.ts` `liveWorkState`, `workingAgentCount`). **No new words, no new elements that take space**: a working session's **own title** shimmers (`LiveText` around the existing text: a sidebar session row through `SessionLiveTitle`, a paired host's row and a split pane's header title through `TabLiveTitle`/`useTabLive`, `layout/SessionLiveTitle.tsx`), and the **composer box's background** carries the same light (`LiveSweep`, `ComposerLiveSweep` mounted first in `.omp-composer-box`: an `aria-hidden` layer at `z-index: -1` under `isolation: isolate`, so typed text and every control sit above it; its band is accent at 11 %, low enough that a draft stays fully readable).
- States: `turn` (its own turn runs) the full light; `background` (the turn is idle, work it started still runs) the same animation and duration, lower contrast only (the title's band 62 % instead of 28 % of its colour, the box's 5 % instead of 11 %), so a switch never restarts it; `waiting` (a question or approval waits on the person; it wins) no sweep: the title turns `--sc-warning`, the box holds a still 7 % warning tint; `null` plain text, nothing drawn. Every sweep is 3 s (`--live-period`, `LIVE_PERIOD_MS`) with a hold at each end and starts on one shared phase (`--live-delay` = minus the document clock within the period, set when the work starts), so titles and the box sweep in step. Every light moves by `transform` alone, so the compositor draws each frame and nothing repaints: the box's is one band inside a clipped layer; a title's own glyphs turn transparent and a copy of its words (`LiveText` `text`, drawn by `.omp-live-shine-words::before` from `data-text`, so neither the DOM's text nor the accessible name doubles) sits in a window whose static mask holds the band, the window sliding across while the copy slides back by the same amount (the letters stay put). Both move in `steps(50)` over the 2.1 s crossing (`--live-steps`, about 24 a second): the masked window is drawn again only at a step and the compositor draws nothing in between (24.7 drawn frames a second instead of 47.7 on the harness). The earlier `background-position-x` under `background-clip: text` repainted every title every frame (+9.3 % of a GPU core with four panes streaming) and in Electron drew no title at all (a selected row in the background state showed only its chip). Nothing breathes by opacity, nothing changes layout, all rest while the window is hidden (`data-paused`). Reduced motion and **software compositing** (`html[data-gpu="software"]`, set by main after `app.getGPUInfo("complete")` reports `gpu_compositing` not enabled; `softwareCompositing()` in `gpu-fallback.ts`) run no animation: a working title is still text with an accent cast (55 %, 30 % for background work), the box a still 5 % (3 %) accent tint. Any new looping cue draws still under both. Between turns the Send button also gets a still ring with a hint tooltip (`ComposerSend`, `input.live.background`), stepped out of the way while the field holds a draft.
- Background work = main's `settling` (`IpcTabInfo.settling`, `IpcHostedSession.settling`; `runSettling` in `sidecar-run-state.ts`, `RunState.turn` tells a turn from the time after it: stock's `prompt_result.sessionSettled: false` keeps `status` `running` until `session_settled` for resume, Stop and the quit guard, and that covers its subagents, async shells and queued wakes for hidden and paired-host tabs alike, with no poll), plus the tab runtime's working subagents (read from that tab's roster store directly, no runtime provider around the card) and the sessions its agent opened that run (not waiting; its whole family, grandchildren and children on a paired device included, since the sidebar files every descendant under the root); a session no tab holds counts only its opened sessions. **Restraint**: only top-level session rows and pane headers wear the title light; a child row (subagent or opened session) stays a plain row whose status token is the working arc while it runs (below; waiting ⚠). The family chip shows its count once: while something runs, one filled still accent pill with the kind glyph(s) and the running count (`data-family-running`); with none running, the plain muted counts per kind (`data-family-agents`, `data-family-sessions`); the label keeps the totals. `data-pane-running` = the turn only; compacting and (re)starting keep the header's spinner.
- **The age slot** (the user's call, 21 Oct 2026): a session row's end shows the time since the session last did something, and while its work goes on (the same rule as the title's light: its own turn, stock's background work, its subagents, every session it opened, local or on a paired host) the **working arc** instead (`common/WorkingArc.tsx`, `SessionLiveAge`/`TabLiveAge` in `layout/SessionLiveTitle.tsx`, `data-session-working`). Waiting on the person is not working: the waiting token stays (`.omp-sidebar-approval`). The age stays in the slot, `visibility: hidden` (`.omp-live-age`), so the row keeps its width. A running family child's token is the same arc (`FamilyStatus`), its age back when it stops. The arc is two 140° arcs (head, tail) on opposite easings (head ease-out, tail ease-in: up to 133° apart, so one stroke of 140°–273°), advancing 180° more each 1.5 s turn so the stroke grows from a new place, over an 18 % track. The easing is sampled into generated keyframes (`omp-working-arc-head`/`-tail`: (turn + eased) × 360° + t × 180°, 12 samples a turn, two turns per 3 s `--arc-period`) played in `steps(3)` per sample: 24 positions a second on one grid every arc shares (`--arc-delay` from the document clock), so ten arcs are one 24 fps compositor stream. Two transforms, no dash animation (which repaints), at rest while the window is hidden (`data-paused`), a still 270° arc under reduced motion and `html[data-gpu="software"]`; `background` only fades its colour. Every age ticks on the shared clock (`useTimeAgo`; a family child's too, `TimeAgo`).
- **What the age reads**: `SessionInfo.modified` is the session's newest conversation message's own `timestamp` (stock helper `session-activity.ts`, read from the journal's end in a 64 KB window growing ×4 to 4 MB, cached per `mtime:size`), else the file's mtime. Stock lists the mtime, and every relaunch appends to sessions that did nothing (`session_exit`, an idle recap, `model_usage`, `title_change`, reports and restart notices, the interrupted-turn record whose message keeps the cut's time): on this Mac 11 of 23 sessions of the last three days had a mtime more than 2 min past their last message. Every reader of `modified` means recency (the sidebar's age and order, the session picker, project recency, the agent tools' listings), so the helper replaces it at the source. Pinned by `session-index-activity.test.ts` (a relaunch's appends leave the age; a reply past the first window; no message keeps the mtime).
- **No leading slot** (the user's call, 19 Oct 2026): a session row (local or a paired host's) leads with nothing, so its title starts at its group header's content edge (rows `padding-left: var(--sc-space-2)`, the header button's `pl-2`); its state is its title's light or its left-edge bar (waiting, error; an overlay, no reserved space), its words the tooltip and screen-reader text. One small mark sits at the row's end before the age (`data-sidebar-row-end`): an unseen finish as a ✓ (`data-sidebar-done`, a shape, not a colour alone), else a chat, pin, worktree (`data-sidebar-worktree`, see Worktree names) or fork glyph. A family child keeps the old relation to its parent's title (`SidebarSubagents.tsx` `INDENT`/`CONNECTOR`: connector 2 px left of it, glyph 6 px right, a sub-subagent one 16 px step more; an Autopilot run's child row one 16 px step in).
- Pinned by `ComposerLive.test.tsx` (states, no border light in the DOM or the stylesheet, every `omp-live-*` keyframe animating transform or opacity only, still forms), the working-title cases of `Sidebar.test.tsx`, `SidebarSubagents.test.tsx` and `SplitWorkspace.test.tsx`, `sidecar-pool.test.ts` ("tells a turn from background work"), `row-glow.e2e.ts` (fake omp: three running rows and a split's header, a roster subagent and stock's unsettled turn, two transform animations per working title, and every working title's words visible in five sampled frames of the sweep in turn, background, selected, split header, light, dark and reduced motion), `row-glow-harness.e2e.ts` (dev harness, desktop and an iPhone 15 drawer: the titles, the composer's sweep behind a draft, the row geometry; `OMP_GUI_WORKING_SHOTS=<dir>` writes every surface × theme × language with frame strips and the composer while typing in a turn), `composer-live.e2e.ts`, `background-tabs.e2e.ts` and the perf-gated `sidebar-edge-light.e2e.ts`. Cost: `e2e/flow-performance.e2e.ts` `grid` measures the cues while four panes stream, every animation running, the titles alone, none, then all again (`lightWindows` `all`/`titles`/`none`; an older build's comet is paused too). Measured 20 Oct 2026 (three runs each): three idle running rows cost the comet 0.3-0.4 % GPU / 0.3 % renderer, the background-clip title 0.6-0.7 / 0.6, the masked title 0.8-0.9 / 0.2 with 0 paints (170.7 paints/s before), 0.5-0.6 / 0.2 once stepped (grid, titles minus none: +20.2 → +9.0 % GPU); its GPU share is the masked layer drawn again whenever the words move inside the mask (0.3 % GPU with the mask turned off, a probe, not a usable look). Shimmering only one of a session's two titles (row or split header) measured no clear difference (grid titles minus none +8.9 vs +9.0, runs ±7).

### Toolbar (desktop/tablet)

- `RunChip.tsx` is the one trigger and popover for Mode (Plan/Goal/Autopilot/Auto mode, `ModesSection` of `ComposerModes.tsx`), Thinking, Tool approval, Delegation, Fast/Advanced/Model roles. `data-run-settings-trigger` is its hook; `data-active` paints it accent (never a utility-class tie, unlayered CSS: a `.bg-transparent` once beat the accent wash); the aria-label spells the whole state. Its trailing glyphs are the approval shield and fast/slow only: **no thinking or delegation icon on or beside it, on any shell** (the user's rule, 20 Oct 2026; both live in the popover and the aria-label). "Mode popover" elsewhere means the Mode section of this popover.
- Opened from the chip, the popover's Mode section shows the tab's first mode and follows it until the person picks a tab (`followsModes` in `RunChip.tsx`): on a run's new tab the Autopilot state can arrive after the popover opened (until then the tab shows no mode or the run's underlying Goal), and a section left on Plan or Goal had none of the run's controls (open the screen, End). Pinned by `RunChip.sheet.test.tsx`.
- The model chip reads `Model · Thinking` (`data-model-chip`); the model picker has the thinking row. Beside the provider's mark the chip drops the brand word the mark draws (`chipModelName` in `settings/providers/provider-marks.ts`: the company's first word or the mark's model family, `MARK_FAMILY` anthropic Claude / gemini Gemini / xai Grok; only when a word, not a number, follows: "Claude Opus 5.5" → "Opus 5.5", "Gemini 3 Pro", "Grok 5" and "GPT-6.1 Sol" stay; no mark or an OpenRouter name like "Anthropic: …" stays whole), and Auto thinking reads "· Auto" alone (a fixed level reads itself); the tooltip (`input.modelTooltipThinking`), the accessible name and the picker keep the full name and the effort Auto picked (the user's call, 20 Oct 2026). Pinned by `chip-model-name.test.ts`, the model chip cases of `ComposerToolbar.test.tsx` and `InputArea.queue-shorthand.test.tsx`.
- **The model picker opens on the composer and dims nothing** (the user's call, 22 Oct 2026): `ModelPicker` measures the focused pane's `.omp-composer-box` and opens with `Modal` `placement="above"` and that `anchor` (its bottom 8 px over the composer's top, its right edge on the composer's, no taller than the room above it: `--omp-dialog-room`) and `backdrop={false}` (no overlay colour, no blur; a click outside still closes). Chosen over a second ■ beside Send, which brought back a box that appears as typing starts and moves the row. The Steer/Follow-up chip renders only while a turn runs, before the `flex-1` spacer, so it takes free room and moves nothing; nothing is reserved for it while idle. Labels fold by the toolbar's own `omp-toolbar` container (860/740/620/500 px), not the viewport. Pinned by `send-slot.test.ts`, `ComposerToolbar.test.tsx` (state table, one node, right click → Stop never sends), `ComposerToolbar.phone.test.tsx` (long press → sheet → Stop), `e2e/composer-toolbar.e2e.ts` (no shift, no idle gap), `e2e/mobile-composer.e2e.ts` (running + draft + long press → Stop, draft kept).
- Below a 440 px toolbar (a pane split in four, 200 % zoom) the bash/python and queue badges give their room back (`display: none`; `e2e/desktop.e2e.ts` "narrow windows and 200 percent zoom"). There the row (and the send cluster) may also wrap, outside the phone shell: at 200 % zoom in a minimum-size window beside the docked sidebar the toolbar has ~110 px, and a row that cannot wrap pushed Send past the window's edge (regressed when the row became `flex-nowrap`). - Popovers close on Tab (`common/popover-focus.ts`); the context ring opens on click/Enter only. The palette's History/Expand/Attach go through `omp:composer-action` (`lib/composer-actions.ts`).

### Phone composer

The sheet (`.omp-action-sheet`) scrolls; the surface inside it and any `overflow-y-auto` list inside that (the queue's `max-h-72` list) neither cap nor scroll on a phone, and a phone tablist scrolls only sideways (`overflow-y: hidden`; a touch hit area made it scroll vertically). Every `::-webkit-scrollbar` rule is gated on `:where(html:not([data-input="touch"]))` (`global.css`, `components.css`): any matching rule turns Chrome's overlay bar into a drawn 9 px track, which Chrome on Android shows. Pinned by `e2e/phone-run-sheet.e2e.ts` "every composer sheet scrolls in one container" (Run, context, model, + and queue sheets; Pixel 8 and WebKit iPhone 15).

### Transcript floor

- **A waiting card and the workspace dock leave the transcript 240 px** (`TRANSCRIPT_FLOOR_PX`, `dialogs/ask-dock.tsx` `measurePromptRoom`). The room above the composer is the pane minus its fixed rows with their margins (header, banners), the transcript column's in-flow fixed rows (the work strip; the board's slot is out of flow), the composer box as currently sized, the ask dock's other children (extension widgets, margins included: the ask dock is `display: flow-root`, so the composer box measures the same with or without a card) and the dock's own rows (goal bar, island). The card gets that room less the floor (`--omp-prompt-room` on the ask dock; `.omp-prompt-card` keeps `min(55vh, 38rem, max(9rem, …))`); the dock's scrolling cards (plan mode, todos) get what the card leaves above the floor (`--omp-dock-room` on `[data-workspace-dock]`, set only while a `[data-prompt-card]` is mounted; `WorkspaceDock` caps its scroller at `min(cap, var(--omp-dock-room, 100dvh))`), down to nothing. Left with nothing, the dock's cards and its resize handle are `visibility: hidden` (`[data-dock-yielded]`), out of the Tab order and the accessibility tree.
- **A short card never scrolls for the floor; a tall one always gives way.** A card whose own height (uncapped: what its body scrolls counts) is `CARD_KEEP_PX` (240 px) or less keeps up to 240 px while the pane holds that beside the composer: in a short or split pane it has what it had before the floor existed, the transcript goes to 0 and the card covers the column's rows (goal bar, then the work strip) from below. A taller card gets the room less the floor, down to its 9rem minimum. Measured: a 1000x800 window split top/bottom (two 374 px panes) keeps a 2-option card whole at 185 px (transcript 0); an 8-option card there gets 144 px and scrolls (transcript 25). A 105 px widget over an 8-option card at 1000x800 with the dock and the strip leaves the card 180 px and the transcript 241 (158 and 240 with a 2-line draft).
- The room is written a frame after the ResizeObserver reports (`requestAnimationFrame`): a write inside the callback resized what it observed in the same frame, which the browser reports as a "ResizeObserver loop" window error. Every height is the laid-out box (computed `height`, border-box), never a rect: the card's `omp-pop-in` and the dock cards' `omp-fade-up` scale them while they enter, a rect read then was up to 14 px off, and no ResizeObserver reports a transform to correct it. A MutationObserver re-watches the transcript column's rows when one is added (the strip, a session switch remounting the transcript).
- The composer box itself is never capped by this; only its draft yields, to two lines that scroll (`.omp-composer-region:has(.omp-prompt-card) .omp-composer-box textarea`, `components.css`).
- A plan under review lets its text box give way first, down to 7.5rem or its own height (`min-height: calc-size(max-content, min(size, 7.5rem))`, `components.css`), so its first choice stays in view; a one-line plan keeps its own height. WebKit has no `calc-size`: there the box keeps its height and the card's body scrolls, as before.
- Measured on the dev harness (`?board=busy&family=1&todos=mixed`, plan mode plus an 8-option question, phones with touch; transcript px before → after): 1600x1000 183 → 240, 1000x800 0 → 241 (4 of 8 options in view, the rest one scroll or a digit away), 390x844 70 → 240, 360x740 0 → 240; the composer box keeps its 92/78 px. A 2-option question in a full-window pane is unchanged (589, 349, 460, 356). A landscape phone (844x390) holds neither: the card keeps 9rem (one option, 215 px before) and the transcript 34 px (0 before), a known limit. Pinned by `ask-dock.test.ts` (the room) and `ask-dock.slot.test.tsx` (the wiring).

### Run sheet (one line per row)

User's rule, from phone screenshots (descriptions under every row, a full-width select with a caption, loose paragraphs, 2-line radio rows). The desktop/tablet popover is the same content at `w-96`.

- Every row of the sheet, the Mode section and Advanced is a lead glyph and its control on ONE line; every explanation sits behind an (i) glyph (`SettingInfo`, text kept in the DOM): no `data-setting-desc`, no `<p>`, no footer line.
- Switches are **tiles** (`common/Switch.tsx` `SwitchTile`: lucide glyph, a short label that truncates, (i), the switch; the whole tile toggles), two to a row in a `data-switch-grid` (`grid-cols-2`): Fast | Slow, Ultrafast (`SpeedFields`), then in Advanced (`AdvancedAndRoles`, opens by itself while a value is not the default) Auto-compact | Extended, Auto-retry | Prewalk, Batch steers | Interrupt. Glyphs: Zap, Turtle, Gauge, Shrink, Maximize2, RotateCw, Rocket, Layers, OctagonX. Fast's "not on this model" is a dimmed glyph plus a sentence in the (i) text. Tile labels ("Auto-compact", "자동 압축") are the old sentences' short forms; the sentences are the (i) texts (`input.more.*Desc`).
- Choices are **segmented rows** (`ChoiceRow.tsx`: the group's glyph, a radio row of short labels, (i) holding the group's name and the held option's effect; the full name is each segment's accessible name and tooltip; arrows move focus, `selectOnArrow` also picks): thinking level (`ThinkingLevelField`, `input.thinking.short.*`, variant `row`; the model picker keeps `segmented`), tool approval (`ApprovalModeField`, shield glyphs, `input.approval.short.*`; full access still asks first through the host's dialog), delegation (`DelegationField`, `input.delegation.short.*`; its "applies from the next turn" note is in the (i)). Short labels abbreviate the long names (ko/en parity).
- The compaction point is one line with its value in the label ("압축 시점 · 850k", `ContextSizeField`, the only select left, compact at the right, its other-layer note in the (i)).
- `mobile.css` bounds the reaches (`[data-choice-row]`, `[data-switch-grid]`: `--hit-gap` 4 px) except a tile's (i) and switch (the (i) 10 px from the switch and reaching 10 px each way, the switch 4 px sideways and 6 px up and down: both 36 px targets, 20×20 and 32×28 before, 22 Oct 2026) and a choice row's (i), which sits 12 px further from the segments and reaches 10 px each way (a 36 px target, as in Settings' content) and gives a segment and a tile the touch row height.
- Tests: `RunChip.sheet.test.tsx` (no visible description or paragraph, an (i) per explanation, tiles two to a row with glyphs, three segmented rows, one select), `ThinkingControl`/`ApprovalControl`/`DelegationField`/`ContextSizeField` tests, `ComposerToolbar.phone.test` (no thinking or delegation icon, the context ring), `e2e/phone-run-sheet.e2e.ts` (`OMP_GUI_RUN_SHEET=<dir>` writes captures at 390 light/dark × en/ko; at 360/390/412 the sheet has no overflow, every tile label stays on one line, tiles pair up, a segmented row is ≤ 56 px, every switch and segment keeps ≥ 85 % of its own taps; the desktop popover keeps its width and cuts no label).

### Input mechanics

- The field is uncontrolled while typing (React 19 re-syncs a controlled textarea's `defaultValue` on every key, which cut ⌘Z to one character per press): the draft store is the source of truth and every composer write goes through `placeDraft`.
- **Any kind of file attaches** (`composer-files.ts` `intakeComposerFiles`, the picker has no `accept`). A picture in JPEG, PNG, GIF or WebP is an image block; one in any other format (HEIC, TIFF, BMP, AVIF, ...) goes through stock's own image path in main (`IMAGE_TO_MODEL` → stock helper `image.toModel`: `ensureSupportedImageInput`, `resizeImage`) at attach time, so the strip shows what the model gets; a web page sends it as it is and the host converts it the same way as it lands (`ws-router.ts` `convertsForModel`: every picture format but those four, a phone's HEIC and AVIF included; one stock cannot read fails the send with `unsupported_image`). A picture stock cannot read, and an SVG (text), attach as a file. A file with a path is an `@` mention; one with none (pasted, dragged out of another app) is inlined when it is text under 5 MB, else kept in this computer's upload folder (`FS_UPLOAD_TO_HOST` on a local tab: `web/uploads.ts` `attachHere`, folder `this-computer`, 25 MB a file, 200 MB a day, deleted after 24 h) and mentioned by that path. Only an empty file and a folder for another computer's tab are refused. Pinned by `composer-files.test.ts`, `input-area-utils.test.ts`, the attach cases of `InputArea.queue-shorthand.test.tsx`, `uploads.test.ts` (`attachHere`) and `stock-helper-images.test.ts` (installed omp: a BMP and an AVIF come back as PNG or JPEG, bytes that are no picture refused).
- A `[Paste #N, +L lines]` marker is atomic: Backspace/Delete/word/line deletes that touch it remove marker and blob as one step (`paste-marker-edit.ts`); a dangling `[Paste #N` never reaches the agent.
- `@` lists up to 20 000 files (`MENTION_FS_MAX_ENTRIES`) at depth 16 (`MENTION_FS_DEPTH`, `input-area-utils.ts`) ranked by `pathMatcher` (file name, word starts, CamelCase, Hangul initials); ←/→ keep the menu while inside the token (`arrowKeepsMenu`). The completion menu and the history overlay share `lib/listbox-nav.ts`; the field is `role=combobox` while a menu exists.
- Attachment strips (`strip-roving.ts`): one tab stop each, arrows, Delete/Backspace, Backspace on an empty field focuses the last attachment, "Remove all" from 2.
- The draft flushes on `visibilitychange`/`pagehide` and on unmount.
- A draft past 8 000 characters (`LONG_DRAFT_CHARS`, `ComposerField.tsx`) is set in the system face (`[data-long]`): Inter Variable was reshaped for the whole text on every key.
- `compositionend` followed within 40 ms by Enter is ignored (iOS Safari's order, `POST_COMPOSITION_MS`, `lib/ime.ts`).

### Dictation and steer box

- The take shows as a bar under the field (`ComposerUnderField`, `DictationOverlay.tsx`, `use-composer-dictation.ts`, `lib/voice.ts`), never over the draft. A failed take keeps a `failure` kind (denied, no-device, in-use, busy, empty, no-model, failed): one sentence plus a Details toggle (none for busy/empty); only no-model offers Open Settings.
- The + menu lists "Dictation" while `stt.enabled` is off and opens Settings (`agent:setting-stt.enabled`) without writing it.
- The subagent steer box (`SteerSubagentForm`) grows like the main field (`fitFieldHeight`) and is never `disabled` while sending (`aria-busy`).

### Enter on a touch input

- `useShellInput() === "touch"` (desktop byte for byte unchanged): a soft keyboard's return key adds a line and only the Send button (or ⌘↵ / the follow-up chord) sends; `enterkeyhint="enter"` on the field.
- A physical keyboard on a tablet gets the desktop's Enter back: `lib/hardware-keyboard.ts` latches, for the page's life, the first key only such a keyboard makes (Esc, Tab, arrows, Home/End/Page keys, F-keys, a chord with ⌘ ⌃ ⌥, Shift with a named key such as Shift+Enter; never a letter, Backspace or Enter, which some soft keyboards report with a `code`).
- Settings › Appearance & input › "Enter sends on touch keyboards" (`displayPreferences.mobileEnterSends`, per device, default off) makes touch Enter send.
- The IME guard runs first, so a composition's Enter is never a send or a newline rule. In `!`/`$` shell drafts the field turns autocorrect, autocapitalize and spellcheck off.
- Pinned by `lib/hardware-keyboard.test.ts`, `InputArea.touch-enter.test.tsx`, `e2e/mobile-enter.e2e.ts` (Chromium + WebKit, en/ko).

### Design record (19 Oct 2026)

Decided by prototype (three variants each, scored on taps, visible state, density, layout jumps, touch/a11y, ko + narrowest width, stock semantics kept):

- **Toolbar → one Run chip and a toolbar-owned container** (19/21 vs 14 and 16): 6 controls instead of 8, Thinking in 2 taps instead of 3, nothing moves when a turn starts (the old row wrapped to 70 px at 340 px), Plan mode moves nothing to its left. Its reserved Steer/Stop slots were replaced on 20 Oct 2026 by the one Send/Stop button and a lane chip in the free room (see Toolbar).
- **Queue → pill and popover** (15/21, the only variant winning the two heaviest criteria): the transcript moves 0 px when items queue (tray 75/83 px, in-box 40/44 px); price is 2-3 taps for lane switching and editing.
- The prototyped phone status chip row is **superseded by the user's rule** (controls stay in the box, the phone composer never folds); the status row and ⋯ sheet are gone.
- Not decided by prototype: undo granularity, atomic paste markers, `@` ranking, keyboard route to attachments, paste menu anchoring, strip cap, drop target, focus after a tab switch, draft flush on page hide.
