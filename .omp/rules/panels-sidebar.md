## Panels, sidebar and work views

### History, stats, compaction limits

- Composer history uses stock `HistoryStorage`. Reads (`history_recent`, `history_search`) go to the stock helper (`stock-helper/history.ts`, one handle on the shared history.db, unqueued beside the serial lane), never the tab's omp, whose thread a turn can starve. The write (`history_record`, needs the session id) stays a guarded bridge method. Local tabs share history with this machine's terminal omp; remote tabs use the paired host's history and never import client prefs. Legacy `inputHistory` prefs migrate oldest-first on the first successful local bridge load, then are deleted (`e2e/history-migration.e2e.ts`). Stock `shouldSkipHistory` keeps secrets out of SQLite. Transient recall and Up/Down draft restore stay renderer-local.
- Compaction-limit commit/prefill uses stock `config/compaction-threshold` helpers through `compaction_limits`; typing never waits for bridge validation.
- Stats: `resources/gui-bridge/stats-host.ts` runs the user's omp-stats server (stock `omp stats` always opens a browser) and adds the paginated `/api/stats/requests` route stock lacks.
  - It starts stock's live ingest itself (`omp-stats/live` `statsLive().start()`: full sync at start and every 5 min, plus each transcript a session writes, 800 ms after), because stock starts it only when a dashboard page subscribes to `/api/events`, which the GUI never does; without it `~/.omp/stats.db` stops updating.
  - The host attaches its stdin shutdown before any startup await, so a start that never finishes cannot orphan it.
  - The frustration judge's module (`pi-coding-agent/judgment/standalone`) is imported inside the judge callback (called only on a `/api/frustration/*` request, which the GUI never makes), because loading it at start is most of the host's memory and start time.
  - Pinned by `stats-host-stock.test.ts` (installed omp: rows reach `/api/stats/requests` with no page open) and `stats-host.test.ts`.

### Side panel

- `components/layout/PanelContainer.tsx`: header = view title, the four view icons (Terminal, Changes, Preview, Files), close; a phone's tab bar holds the same four. Beside the pressed view icon the title is said once, to screen readers only (`sr-only` inside `[data-panel-title]`, which keeps its box); it shows where no icon names the view (a phone's sheet, a subagent's transcript). On Windows with the panel docked right, the header's first row is the 48 px caption band, where the title shows (`global.css` undoes its `sr-only` there, so the band is not an empty strip), and the view buttons and close sit on a row below (`[data-panel-title]`/`[data-panel-views]`/`[data-panel-close]` in `global.css`), so the panel's ✕ never stands beside the window's; pinned by the Windows window case of `responsive-smoke.e2e.ts`. `PANEL_TABS` is those four; a subagent's transcript is the panel's one other view (opened from its row). **The panel has no View options list** (the user's rule). The other session views, with data and scope unchanged:
  - **Nothing clickable under the Windows caption buttons** (the owner's rule; the native ✕ takes every click). `global.css` › Frameless chrome holds every reservation: `--sc-caption-buttons` (width, `env(titlebar-area-*)`) and `--sc-caption-band` (height), 0 off Windows. The main top bar and a docked panel's header reserve them; a right or full sheet's `.omp-sheet-head` (`Sheet.tsx`, every `<Sheet>`: session tree, agent editor, context inspector, subagent transcript, plugin detail, the compact window's panel through `.omp-panel-topbar`) keeps its ✕ left of them; a window-level dialog's overlay starts under the band and `--sc-dialog-room` (`components.css` dialog geometry) sizes the panel to the rest. Pinned by `e2e/windows-caption.e2e.ts` on the dev harness painted as Windows (`?platform=win32`; `dev-harness/boot.ts` stands in the buttons at 138×48 and `[data-caption-buttons]`; `chromePlatform` keeps a mark the page already set): no control may reach the band on the title bar, a docked panel, the view sheets, a compact window's panel sheet, Settings, toasts and six dialogs in a 560 px-high window. `OMP_GUI_CAPTION_CAPTURES=<dir>` writes a PNG per surface.
  - Background tasks, the plan document (`PlanDockCard presentation="sheet"`: the latest plan with or without plan mode; the dock card shows it while plan mode is on), Logs, Session tree (`panels/SessionTreeSheet.tsx`, one view, owns the keyboard while open) and Work tree open as **sheets** (`useUiStore.openViewSheet`, `VIEW_SHEETS`; `layout/ViewSheetHost.tsx` mounts the lazy `layout/ViewSheets.tsx` inside the runtime of the tab focused when it opened, so a paired host's tab reads its host whatever the focus does next). Entries: palette `jobs`, `logs`, `plan-document`, `tree`, `work-tree`; native menu Jobs and Session tree; the title bar's session menu (tree); the work board's job rows and the dock island (jobs); the board's Child sessions section's last row (`data-board-work-tree`); Settings › Updates & about › diagnostics' Live log (`data-diagnostics-live-log`); the sidebar's Background tasks pin. The plan sheet's review footer (feedback, Approve plan, Request changes) shows only while plan mode is on and the plan has text; its steps number from 1 under each heading, and the tab's count is the plan's numbered and checklist items.
  - Queue: the composer's queue pill and popover run the same `useQueueActions` on the same tab (edit in the field, move lanes, remove, Clear all, per lane `data-lane-clear`).
  - Memory: Settings › Memory (`window.omp.aiMemory`, this computer's store), palette `memory`.
  - Retired (`src/main/retired-prefs.ts` `retirePanelViews`): a stored `defaultPanelTab` among the old views becomes Changes; `keymapOverrides` for `panel.jobs|plan|logs|queue|tree|memory` are dropped; an agent's `ompdesk_app ui.panel` takes the four views and the five sheet ids (`AGENT_PANEL_TABS`, `AGENT_VIEW_SHEETS`). Pinned by `ViewSheetHost.test.tsx` (local and paired tab, tab kept when focus moves), `PanelContainer.test.tsx`, `retired-prefs.test.ts`, `ComposerQueue.test.tsx`, `use-queue-actions.test.tsx`, `SessionTreeSheet.test.tsx`, `PlanDockCard.sheet.test.tsx`; captures `OMP_GUI_PANEL_COMPRESS_SHOTS=<dir>` with `e2e/panel-compress-captures.e2e.ts`.
- There is no Autopilot view: a run lives on the work board (see Autopilot › Overview). A view's own actions sit in its toolbar row, never in the header.
- Terminal reuses stock `@oh-my-pi/pi-natives` `PtySession` inside the stock helper's terminals worker (`resources/gui-bridge/stock-helper/terminals.ts`, `src/main/terminal/`): no second native addon, one `TerminalService` per worker (overlapping first requests share its creation), stdin EOF kills every PTY. A paired host's tab gets the host's terminals (`terminal.request`/`terminal.shells` in `remote/host-services.ts`, disposed with the host tab).
- A terminal viewport reads with one long poll, on desktop and phone alike (`lib/terminal-poll.ts`), so an idle terminal costs no IPC traffic: the worker holds `list` with `waitMs` until the PTY writes, any session changes what a viewer shows (exit, resize, restart, close, clear, a `claim`, which main forwards so other windows' polls answer with their new standing), or 1 s passes; the next request acknowledges the last output, cut to the 64 KB budget. A desktop window's failed request stops its read and shows the panel's error; a phone asks again. Pinned by `terminal-longpoll.test.ts` (a resize and a claim wake another window's poll) and `TerminalPanel.test.tsx`.
- The agent reads a tab's terminals through the read-only `gui_terminal_read` host tool (stock `set_host_tools` on every ready sidecar, answered in `ipc.ts`, `src/main/terminal/agent-tool.ts`).
- Preview: a main-managed `WebContentsView` (`src/main/preview/`) on a non-persistent partition with sandbox/contextIsolation, no preload, http(s) only; permissions, downloads and new windows refused; remote-tab loopback URLs blocked.
- **Background jobs are stock's tree**: bridge `composer.jobs` reads `getAsyncJobTree()` (the session's jobs and every subagent's, stock's recent limit of 10) and lays it out with stock `pi-tui/overlays/job-tree` `buildJobTree` (in omp's bundle, so no `COPY_SAFE` entry; `resources/gui-bridge/jobs-core.ts` makes the rows, `jobs-contracts.ts` is the contract), each job with stock `inspectAsyncJob`'s output.
  - A row carries `depth` and `cancellable` (stock's rule: `ownerId` absent or the tree's `rootId`; `cancelAsyncJob` refuses others, so a subagent's job stops with the task job that runs it); an agent row heads a subagent whose task job is no longer listed.
  - `get_jobs` returns `{ rows }`; `use-background-jobs.ts` is the one poll and derives the running shells/evals (nested included) for the work board, dock island and composer cue; the Background tasks sheet (`panels/JobsPanel.tsx`, `panels/jobs-tree.ts`) indents nested rows under their subagent.
  - The poll reads every 3 s only while the tree can change without a tool call: the last read listed jobs (stock's `AsyncJobManager` evicts a finished one 5 min after it ends) or failed, or the tab is at work (its runtime's `turnActive`, or a live subagent); the tab stopping work reads once more. `TabPollStart` gets the feed key for this.
  - Pinned by `use-background-jobs.test.tsx`, `bridge-jobs-core.test.ts`, `bridge-jobs-tree-stock.test.ts` (installed omp: nested job listed, inspected, cancel refused), `jobs-tree.test.ts`, `JobsPanel.test.tsx`. Fake omp `OMP_GUI_TEST_JOB_TREE=1`, dev harness `?jobs=tree`, captures `OMP_GUI_JOBS_TREE_SHOTS=<dir>` (`e2e/jobs-tree-captures.e2e.ts`).
- Changes polling (`panels/RepositoryChanges.tsx`, `get_git_fingerprint` in `local/git/changes.ts`): an open list asks main every 3 s only for a fingerprint (one `status --porcelain=v2 --branch -z --untracked-files=all --show-stash`, whose `branch.oid` is HEAD, plus an in-process `lstat` of each listed path so a second edit of a modified file moves it; a git older than 2.35 refuses `--show-stash` once and is asked without). The panel passes the worktree `root` its last full read reported, so `rev-parse --show-toplevel` runs only before the first read or when that root does not hold the tab's folder. An unchanged tick costs 1 git process vs 9 for a full `get_git_changes` (counted by trace2 in `changes.test.ts`).
  - **One watch per checkout for the whole app** (`src/main/git-fingerprints.ts`): the first ask of a folder starts a recursive `fs.watch` on its worktree and git directories (`rev-parse --show-toplevel --absolute-git-dir --git-common-dir`, once); every window's, tab's and paired device's ask is answered from memory while no event came since the last read, so an idle open list runs no git. Any event (ignored folders and `.git/objects` included) makes the next ask run git; concurrent asks share one read; an answer read across an event is not kept. Every ask runs git outside macOS and Windows, outside a repository, and after a watcher error; an answer older than 30 s is read again regardless; a folder nobody asked about for 15 s is unwatched. Pinned by `git-fingerprints.test.ts` (real checkout).
  - Only a changed fingerprint reloads the list; the open diff stays until its replacement arrives; a hidden window clears the timer; a failed reload keeps its fingerprint as baseline and waits for the checkout to change. A stash made or removed moves the fingerprint and the bar's stash count. Known gap: any other operation with no status change does not move it (the refresh button reads it).
- Every `git`/`gh` child gets `GIT_OPTIONAL_LOCKS=0` (`execBin`), so a status refresh never takes `.git/index.lock` from the agent's git. On macOS GUI git calls run the developer dir's git directly (`gitBin` in `exec.ts`), never xcrun's `/usr/bin/git` trampoline (CPU cost per call).
- Unsaved Files edits belong to their tab: `closeTab` on the tab named by `fileEditTabId` while `fileEditDirty` does not close it but raises the editor's discard confirm (`holdTabClose` → `pendingFileSwitch`). "Discard" sets `discardedForTabClose` and the side panel then closes the tab; Cancel keeps both.
- Subagent view (`panels/SubagentPanel.tsx`): a sidebar subagent row dragged onto a session pane (`omp:subagent-drag`, taken by `SplitWorkspace`) or its menu's "Open in side panel" sets `useUiStore.panelTab = "subagent"` + `panelSubagent {tabId, agentId}`; the view reads the transcript and steers through the owning tab's runtime. It is not in `PANEL_TABS` (default-view setting, `panel.*` shortcuts); panes stay main-owned omp tabs.
  - The transcript (`SubagentTranscript.tsx`, shared with `SubagentTranscriptSheet`) uses the main transcript's own components, never a second renderer: `buildHistoryRows`/`reuseTranscriptRows` drawn by `MessageBubble`, `ProcessGroup` (compact work card, or per-message tool cards by `transcriptDetail`) and `ReadGroupCard` under `.omp-transcript-editorial.omp-subagent-conversation` (`styles/subagent-view.css`; insets follow the panel width by container query; code and tables scroll inside their block).
  - It runs in a derived `SessionRuntime` of the owning tab with private tools/messages/session stores (`hydrateMessages`, `turnIsLive` while the agent runs), so the owner's streams and goal never reach the cards. `use-subagent-transcript.ts` reads through the owning tab's held transcripts (`subagents` store `transcripts`, `stores/subagent-transcripts.ts`, shared with the work map's and work card's replays), so a paired device never re-reads whole journals (Remote devices › A subagent's transcript crosses once): it shows what the tab already read at once, reads on from the byte cursor, asks nothing for an agent settled since its last read (`settledMark`), and follows a running agent (progress frame or 4 s `pollWhileVisible`; a hidden window asks nothing and reads once when shown; a page with nothing new keeps the same array). `use-stick-to-bottom.ts` is ChatStream's gesture-vetoed follow plus "Jump to latest". Header is one line (provider mark + agent, status, tokens, clock, open full / stop / copy); the steer box reuses `.omp-composer-box` and `.omp-composer-action`.
  - Tests: `SubagentPanel.test.tsx`, `SidebarSubagents.test.tsx`; `e2e/subagent-view.e2e.ts` (`fixture:subagents:transcript`/`:append`, 380/520 px, 320 px overflow; `OMP_GUI_SUBAGENT_SHOTS=<dir>` writes captures).

### Sidebar families and subagent titles

- Files: `layout/sidebar/SidebarSubagents.tsx` (group, chip), `SidebarFamilyRow.tsx` (one-line row), `sidebar-family.ts` (pure rules), `stores/sidebar-subagents.ts` (open state).
- **Family** = everything derived from a session, shown together under its row, one indent level in: its subagents (its summary's, below) and the sessions its agent opened with `ompdesk_session_open`, in a worktree or not, whatever their folder.
- **A row is live without a click, shown or not, on every surface, from one source** (the owner's rule; per-view "re-read when X" fixes kept missing tab events). A row's live state is never assembled per view from tab events.
  - **One builder** (`src/main/session-summaries.ts` `SessionSummaries`, contract `src/shared/session-summary.ts`): the computer that runs a session builds what every row shows of it, from facts its main already has: each tab's status, run, asks (an approval or any other answer; a plan up for review is an approval), why its omp failed, exited or restarts (`failure`: message and restart attempts, by `failureOf`, the one rule the tab listing also uses for every window's banner, `IpcTabInfo.message`/`restart`; a failed row's words and tooltip and `ompdesk_sessions` name it), title and auto title, `openFor` for a tab it runs for a paired device (`SidecarPool.summarySources`, `LocalHostServices.summarySources`; a paired host's tab and a view of a device's tab are left out, their computer says them), and its subagents (`agents`: the ones a row lists, running, waiting, failed, with label, step, tally, model and transcript file).
    - Main follows each omp's subagents from the `subagent_*` frames every omp writes over stdio (`SidecarPool` asks every omp for `progress` as it becomes `ready`, `SUBAGENT_LEVEL_FLOOR`), empties them when that omp starts or restarts, reads a new omp's `get_subagents` once as it becomes ready (the revived ones), and leaves out an agent a restart ended by the one restart-cut rule (`shared/restart-cuts.ts`).
    - One row per session file (an ask outranks a run). The pane's banner keeps reading its own tab's listing: a tab whose omp never started has no session file and so no summary.
  - **Versioned, never event-dependent**: `current()` is the whole set at a version (`epoch.n`); each burst goes out once (`SUMMARY_DEBOUNCE_MS`) as a `SummaryDelta` on the last version. A holder applies a delta only on the version it holds (`applySummaryChange`), else reads the whole set; a view reads every computer's whole set when it starts and on a web page's catch-up (`loadHostedSessions`: this computer's and every paired host's, `web/resync-page.ts`), and main pushes a host's whole set when its link comes up. Correctness never depends on having received every past event.
  - **Delivery**: `SESSION_SUMMARIES_CHANGED` `{device?, change}` to every window and phone page (not a stream channel, so the web router never drops it for a hidden page) and `SESSION_SUMMARIES(device?)`; a paired device gets `host.summaries` and reads `sessions.summaries` (remote-devices.md › One source, every view). The renderer holds every computer's in `stores/hosted-sessions.ts` (`summaries`, `useSummaryMap`, `summariesOf`), read and pushed there only: no view reads summaries on its own.
  - **A phone shows these rows only as fresh as the code it runs**: the page protocol is 2 (an older page reloads), and a page behind the build its host serves moves to it at its next unused moment (multi-viewer-web.md › Reloads, "The host's build"). Pinned by `e2e/phone-host-rows.e2e.ts`.
  - **Rows read only it**: this computer's rows (`Sidebar.tsx` `summaryFor`/`sessionRowState`), a paired host's (`SidebarDevices.tsx` `renderRow`), a family row of a session on a device (`remoteFamilyChildFor`) and folded headers all go through `summaryRowState` (`host-row-state.ts`); the chip, the subagent rows and the working cue (`SessionLiveTitle`/`SessionLiveAge` `agents`) read the summary's `agents` (`SidebarSubagents` `agents`), whether or not a tab of this view holds the session. A tab here only selects, opens and nests rows, and its `unreadDone` (this view's own mark) gives the ✓. A tab whose omp has named no session file yet is summarized under its tab (`unsavedSessionKey(tabId)`; a device's tab on a host under the device's tab id) and its live row reads that; such summaries are not rows of this computer's own list (`hostedSummaries`). An archived or stored row nothing runs lights only by the index's `pending`. `ompdesk_sessions` reads the same summaries (control-tools.md › What is open on a paired computer), so a list line and a row cannot disagree.
  - **Every other surface that says what a session does reads the same summary by the same rule** (the owner's rule). The rule is `sessionRun` (`lib/session-run.ts`: its own prompt unless the session is down, then a turn, background work or a compaction (`SessionSummary.compacting`), then a failed omp; `summaryRowState` is it plus the fold mark); a tab finds its summary with `tabSummary` (`stores/hosted-sessions.ts`: its file, else `unsavedSessionKey(tab.id)`, on the computer its omp runs on) through `useTabRun`/`useFocusedRun` (`hooks/use-tab-run.ts`).
    - Readers: the title bar's status (`TitleBar.tsx`; the web link and a paired host's link still come first, being this view's, not the session's), the window title and dock progress (`App.tsx`), the tray (`trayStatusOf`), `useSessionAttention` (its own ask from the summary, a waiting child only while it is up), a split pane's header (spinner, failure mark, `data-pane-running`, and `useTabLive`'s working cue with the summary's `agents`) and the Work tree (`work-tree.ts`: a root's token by `sessionRun`, so a turn that ended in an error is not a failed session; its subagents at work are the summary's `agents`, with `cost`; this window's roster only fills the finished fold).
    - A surface that needs more of a session adds it to the summary in main, never derives it from its own tab events. There is no tab strip; the tab overview's and the core's `rules/tab_close.rs` close guards (control-tools) still read the tab and the focused stream directly, because the summary's debounce would delay a safety check.
    - Pinned by `e2e/session-surfaces.e2e.ts` (split window: each state on the row, title bar, window title, pane header and Work tree; a tab no pane shows), `work-tree.test.ts`, `use-tray-sync.test.ts`, `host-row-state.test.ts`.
  - **What it replaced, deleted**: `HOSTED_SESSIONS`/`LIVE_SESSIONS` and their pushes, `host.liveSessions`/`sessions.live`, `HostView.live`, `hostRowState`'s tab-vs-live merge, `liveByPath`/`hostedFor` fallbacks, forwarding a hidden tab's lifecycle frames to windows, `reconcileTabs`' roster re-reads (`rosterRead`, `holdsLiveSubagent`), the re-read on a hidden tab's `TAB_STATUS` turning ready, and per-view `ensureHostSummaries`. Per-tab detail streams stay: an open transcript, the subagent panel and the shown pane's 3 s roster poll.
  - **A tab this page has no runtime for yet** (a page that just loaded lists its tabs after their frames start): every per-tab frame handler of `use-rpc-events.ts` goes through `openTabFrame`, which gives the tab its own runtime; `withSessionRuntime` would otherwise apply the frame to the focused tab's stores.
  - **An ask answered by no window** (an agent's `ompdesk_session_answer`, Autopilot): `routeSideChannel` sends every window the `answeredElsewhere` cancel, as for an answer another window gave, because stock sends nothing when an ask is answered.
  - Pinned by `session-summaries.test.ts` (frames, dead/new omp agents, revived read, stale registration, one row per file, delta per burst, gap read whole, closed tab removed, restart-cut rule), `host-row-state.test.ts`, `SidebarSubagents.test.tsx`, `sidecar-pool.test.ts` ("asks a tab's omp for subagent frames whenever it is ready", "closes an ask an agent answered"), `use-rpc-events.test.tsx` ("files a frame for a tab without a runtime"), `e2e/sidebar-live-status.e2e.ts` and `e2e/session-summary-matrix.e2e.ts` (window, paired view and phone page, case by case, and the row's count against `ompdesk_sessions`).
- **Provenance**: `AgentControlRuntime.#spawn` calls `SidecarPool.setTabOpener(tabId, callerTabId)` (not for an Autopilot child, which keeps its run's row). The tab entry carries `openedBy` (opener's tab id) and `openedBySession` (its session file) on `IpcTabInfo`; the saved tab layout keeps the file as `PersistedTabDescriptor.openedBy` (a restored tab's id is new; the file finds the opener; the opener's tab closing leaves the file). The renderer matches by tab id first, then by file (`openerOfSessions`): an opened session whose opener is listed leaves its project's rows (one without a live opener stays a marked row of its project, see Worktree names), one opened by an opened session goes under the first of them, a cycle nests nothing.
- **Row**: ONE line (`.omp-family-row`, 28 px; `--sc-row-touch` 36 px on a phone): 16 px kind glyph (subagent `Bot`, worktree session `GitBranch`, plain session `MessageSquare`), title, one status token (working arc while running, waiting ⚠, done ✓, failed ✕, ready to merge `GitMerge` in the info colour, paused) and age (an opened session's steps aside while it runs; a subagent's is its elapsed time); status in words, folder, model and progress are the tooltip. A subagent's title follows "Subagent titles" below; an opened session's is `agentTaskTitle`/`sessionDisplayTitle` (the `Title:` line else its first line, via `assignmentHeadline`/`stripTitlePrefix` in `subagent-title-contracts.ts`). The parent row's chip reads "🤖5 · ⑂4" with the running count as a filled pill: counts only.
  - **The sidebar shows no money** (the user's rule; it squeezes titles and on a subscription is only stock's API-price estimate): no cost on the chip, the row or a child's tooltip, which names only model and role (`childUsageText`: "anthropic/claude-x · @task"; a subagent's from stock's `AgentProgress` `resolvedModel`, `modelRole`; an opened session's from main's review push `AgentReviewEvent.usage`, else the closed record). Cost lives on the work board and in the Work tree (see Work board › Money).
  - The sidebar is on the phone's first screen (`WEB_FIRST_SCREEN_JS_BYTES`): usage is read where it is shown, never passed through `openedChildRows`. A phone bounds hit areas with `--hit-gap` (`mobile.css`).
- **A family is folded by default and NEVER opens or folds by itself.** Every follow-up message to a subagent is a new run, so an open-on-start rule would override the person's fold. Running, finishing or starting children change only the chip (running count = filled pill; warning tint `data-family-waiting`, `sidebar.family.waiting` in its summary while a child waits for the person).
  - The only thing a folded family shows unasked is a child that waits for an answer or approval (`waiting`: a stale registration, or an opened session `awaitingInput`): that row shows alone under the folded parent (`data-sidebar-surfaced`, flat, no connector) and leaves when answered; the store's `expanded` is untouched.
  - The person's own toggle (chip, session row click, ←/→, "expand/collapse all", the dock's reveal) is the only writer of `expanded`, remembered per session in memory; with no child the entry is dropped.
- **A session row is as wide as what it draws** (the owner's rule, so a pick never moves a row's title cut). The chip's slot at the row's end (`ListRow` `trailing`) exists only while the chip draws: both read `familyChipCounts`/`hasFamilyChip` (`sidebar-family.ts`) over the row's own summary subagents, shown opened sessions and the person's hide, on this computer's rows and a paired host's alike. A tab here holding the session adds no slot. A running row the list draws from its live tab alone (`data-live`) has no age in its slot and gains it when the index lists the row. Pinned by `e2e/sidebar-row-width.e2e.ts` (both lists, four picks; `OMP_GUI_ROW_WIDTH_SHOTS=<dir>` captures).
- **The list keeps its scrollbar's room whether it scrolls or not** (`.omp-sidebar-list`, `scrollbar-gutter: stable` in `sidebar.css`; the owner's rule), so a change of the list's height (a pick that folds the project the start tab left, `isCollapsed`; a family opened; a row added) never moves every title's cut. A finger's scrollbar is an overlay and reserves nothing. Pinned by "a pick that changes the list's height" in `e2e/sidebar-row-width.e2e.ts`.
- **Finished children are never listed** (the user's rule). A family shows only children that are live or need a look: running, waiting, failed or stale, or an opened session with work left to merge (`unmerged`: unmerged commits or uncommitted work). A finished subagent (completed/aborted/cancelled, or `restart-cut`, see interrupted-work.md "Revived subagents"; `isFoldedSubagent`) or a finished opened session that landed clean (`status` `done`, `isShownOpened`) has NO row and NO "n done" fold (no `sidebar.family.done` string, no `data-family-done`). The chip counts only shown children (`familyCounts`) and is absent when none show; a family left with nothing is dropped from the store. ### Split view and picking a session

- Files: `stores/tabs.ts`, rules in `shared/split-layout.ts`. Main owns tabs and the pool; the renderer owns what the window shows.
- A window shows one session alone or one split of 2–4 panes (`split`), and remembers the other splits it has shown (`rememberedSplits`: layouts only, no focus). A session is in at most one split, on screen or remembered.
- Three rules, all in `viewAfterPick`; every way of picking a session goes through `switchTab`: ① a pane of the split on screen only takes focus, the layout stays; ② a session outside the split leaves it and shows alone, full width, and the split on screen is remembered; it never replaces or opens into a pane; ③ a member of a remembered split brings that split back exactly as it was (sessions, positions, sizes) with the picked session focused, and the split that was on screen is remembered in turn.
- Picks: sidebar rows, ⌘1–⌘9, ⇧⌘[ ⇧⌘] / ⌘PageUp/PageDown when no split is on screen (with one they cycle its panes), tab overview, ⌃⇥ switcher, notification/prompt-card focus. Dropped on a pane edge it splits (`SplitWorkspace`), on a row of its own list it moves, anywhere else nothing. ### Files the conversation names

- OMPdesk shows attached and handed-over files itself, on this computer and a paired one (the user's rule: no instruction to the agent; OMPdesk presents what the reply and the prompt name), never as raw paths.
- **One card** (`tools/media/FileCard.tsx`, its kinds and what each draws in one table, `KINDS`): a file with something to draw is a card (a picture, a PDF's first page, a page drawn in an empty-sandbox frame at four times the card's width and scaled down, a spreadsheet's or CSV's first rows, a presentation's first slide title), any other file a row (Word, archives, programs, text, folders) with a kind tile; under both the name, "type · rows/slides · size" (archives, text and other files by their extension, "ZIP · 1.0 KB") and the file's buttons. The tile stays under a preview until it is drawn, so a slow or failing read never leaves a blank box. A click on the card previews it (the Files viewer; a picture zooms); a right click opens its menu. Reads go through the tab's own `fs.*` (a paired host's tab reads on that host) once the card nears the screen. Audio and video stay `ChatMedia` players with the same buttons in their caption; a recording too large to play over the link is a chip with them too.
- **Its buttons** (`tools/media/file-actions.tsx`, one rule for the card, its ⋯ menu and a link's right-click menu in `lib/link-menu.tsx`): by `useFileSurface` (`local` this computer's tab, `remote` a paired host's tab in a desktop window, `web` the phone's page). The card's own button is the file's place: Reveal in Finder/Explorer here; Save to this computer from a host; Save to this device on the phone. The menu: Preview, Open in default app / reveal (here; on the phone they go to the computer through shim.ts's host actions), Save a copy…, Copy path. A save says where it went, with a reveal action that shows that copy whatever tab is in front (`fs.revealCopy` → `FS_REVEAL_COPY`, only for a path `FS_SAVE_COPY` wrote this launch), because `system.revealPath` asks the tab in front, usually the host's tab the file came from.
- **Saving** (`fs.saveCopy` → `FS_SAVE_COPY`, `src/main/save-copy.ts`): this window's save dialog, then a local `copyFile`, or from a paired host a 64 KB first read (`host.fs.readRange`, which says the size and that the host streams) so the dialog shows at once, then 8 MB parts (`HOST_DOWNLOAD_PART_BYTES`, up to `HOST_DOWNLOAD_MAX_BYTES` 1 GB) into a temp file of its own beside it (`<dest>.<random>.ompdesk-download`, opened `wx`, so a file or link already at a name like it is never truncated or removed), renamed onto the destination once whole and removed on any failure. A host without `host.fs.readRange` answers `unsupported`: one `host.fs.readBinary` (≤ 11 MB), else "update OMPdesk on that computer". A web window's call answers the file's bytes instead (`readWorkspaceBinary` here, `readRemoteFile` from a paired host in the same parts, both up to `FS_BINARY_LOCAL_MAX_BYTES` 100 MB; never the viewer's one-frame `host.fs.readBinary`, which stops at 11 MB), which ws-router puts behind a `/blob` URL past 512 KB like a read, and the shim hands them to the phone's browser to save or share (`env.save`).
- **Under a reply** (`chat/ReplyFiles.tsx` over `chat-media.ts` `referencedFiles`): media, pictures, PDFs, pages, documents and any non-text file the reply links or quotes (an archive, an installer: kind `file`), plus a text file it links by an absolute path outside the tab's folder (`/tmp/summary.md`). A file that is not there (moved, deleted, never written) draws nothing, on this computer and on a host's tab alike, never a "Deleted" card (`e2e/session-views.e2e.ts`, `e2e/remote-flows.e2e.ts`). A link with a line (`a.ts:42`) or inside the project is a citation and stays in the text; a picture a tool already showed is not drawn twice.
- **Under a prompt** (`PromptFiles`, `shared/file-mentions.ts` `splitAttachedMentions`, `replaceFileMentions`): every `@path` outside code that reads as a path (a separator or an extension: `@kim` is a person, `@pytest.fixture` in a fence and `` `npm i @types/node` `` are code) is a card under it; a line that holds only mentions (what the picker, drop and paste insert) leaves the text; a mention inside a sentence by its whole path (an upload, a file outside the project) reads as the file's name linking to it (a `file:` URL with `(`/`)` escaped, so a Windows drive, a space or a parenthesis survives sanitize), a relative one stays as written, and the punctuation around it stays; one a sentence names gets a card only while it names a file.
- Pinned by `FileCard.test.tsx` (shapes, meta, sandboxed page, buttons and menu here and on a host's tab), `ToolMedia.test.tsx` (reply and prompt cards, citations), `chat-media.test.ts`, `file-mentions.test.ts`, `link-menu.test.tsx`, `shim.test.ts` (the phone's save), `save-copy.test.ts`, `host-services.test.ts` (`host.fs.readRange`), `e2e/chat-media.e2e.ts`, `e2e/remote-flows.e2e.ts` (a large file saved from the host byte for byte) and `e2e/mobile-attach.e2e.ts` (Save to this device).

### Preview: agent browsing and agent visuals

- **Agent browsing** (Preview toolbar robot button, off until the user clicks it): the tab's bridge (`resources/gui-bridge/browser-relay.ts`) starts stock's own `omp browser-relay` server (`tools/browser/relay/server.ts`) on a free 127.0.0.1 port with a random extension token and holds `browser.relay`/`browser.relayUrl` as session runtime overrides, so stock's browser tool runs in relay mode. Main joins as the relay's "Chrome extension" (`src/main/preview/agent-relay.ts`, stock's `relay/protocol.ts`) over the preview page's `webContents.debugger`, offering that one page, never the app window (which keeps no remote-debugging port).
  - Electron's per-page debugger is not confined to its page (`Target.getTargets` lists the app window and `Target.attachToTarget` onto it works). So the relay forwards an **allowlist** only: the page domains stock's puppeteer uses (`Page`, `Runtime`, `DOM`, `Input`, `Network`, `Emulation`, … never `Browser`, `SystemInfo`, `Tethering`, `Tracing`, `Memory`), and from `Target` just `setAutoAttach` and `detachFromTarget`. `Tracing` is browser-wide (records the app's other windows), so stock's `tab.traceStart()` fails by design.
  - Also refused: `Page.navigate` off http(s)/about:blank, `Page.close`/`crash`, downloads, `DOM.setFileInputFiles`, `Page.setInterceptFileChooserDialog`, `Input.setInterceptDrags`, an `Input.dispatchDragEvent` whose `data` carries `files` or a `file:` URL (Electron's debugger turns `files` into a real dropped File from the local path), a `Network.loadNetworkResource` whose `url` is not http(s) (keeps local files out whatever Electron does), and `Security.setIgnoreCertificateErrors`/`setOverrideCertificateErrors`/`handleCertificateError`.
  - `Page.navigateToHistoryEntry` is allowed only after the relay reads `Page.getNavigationHistory` and the target entry's URL passes the same http(s)/about:blank rule, so `tab.back()`/`tab.forward()` work. The relay addresses only sessions this page's own debugger announced with `Target.attachedToTarget` (its frames and workers, never a `page`/`tab`/`browser` target); the page keeps its partition, sandbox and no-preload rules.

  - **Phone and paired host's tab** (the user's rule): the robot button is on for every tab. A paired phone's page drives its offscreen preview window the same way (`PreviewPanel`'s banner and Take over are the phone page's own); a tab that runs on a paired host reaches the relay over the link, because it listens on the host's loopback. The page the agent drives is still the device's own native one (so it watches live, Take over/the robot button work as on the desktop, and the allowlist above applies device-side unchanged).

### SSH tools on this computer

- `src/main/ssh/`, contract `src/shared/ssh-tools.ts`, Settings › SSH: port forwards for a saved host (`ssh -N -L 127.0.0.1:<local>:127.0.0.1:<remote>`, saved in `<userData>/ssh-forwards.json`, started again at launch), the server's listening ports every 5 s (`SSH_PORT_POLL_SECONDS`), ssh-agent/key state, and a reconnect with growing delay until the chosen grace time (1 min–7 days, default 1 h).
- Main (`service.ts`) keeps what the person wants running and the saved list; every such ssh runs in the core process (`client.ts`, `native/ompdesk/crates/core/src/ssh`, native-rust › 4b) and ends with it, with `-F <userData>/ssh/config`, whose first `Host *` block pins OMPdesk's own `known_hosts` with `StrictHostKeyChecking ask` and no connection sharing, then includes `~/.ssh/config`. OpenSSH hands `-F` to every ProxyJump hop, so each hop's key is checked too. What a host, a user, a key path and a port may be is the core's rule (`ssh/rules.rs`): nothing the page sends can become an ssh option.
- Host-key, password, passphrase and code questions come through `SSH_ASKPASS` (`ssh/askpass.rs`: the helper is the `ompdesk-core` binary itself, a per-process token over a local socket; the core lists the waiting questions for main in `ssh.prompts`) into `SshPromptDialog`; answers are never stored, never logged, cut out of that ssh's stderr before it is read, and a question expires after 2 min. A changed host key stops the forward until the user forgets the saved key.
- The agent's own ssh tool stays stock's. SSH server windows (a headless OMPdesk on the server) are out of scope: OMPdesk ships for macOS and Windows only, and remote devices cover running work on another of the user's computers.
