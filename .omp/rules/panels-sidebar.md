## Panels, sidebar and work views

### History, stats, compaction limits

- Composer history uses stock `HistoryStorage`: reads (`history_recent`, `history_search`) are answered by the stock helper (`stock-helper/history.ts`, one handle on the history.db every omp shares, unqueued beside the serial lane), never through the tab's omp, whose thread a turn can starve for seconds; the write (`history_record`, which needs the session id) stays a guarded bridge method. Local tabs share history with this machine's terminal omp; remote tabs use the paired host's history and never import client prefs. Legacy `inputHistory` prefs migrate oldest-first on the first successful local bridge load, then are deleted (`e2e/history-migration.e2e.ts`). Stock `shouldSkipHistory` keeps secrets out of SQLite. Transient recall and Up/Down draft restore stay renderer-local.
- Compaction-limit commit/prefill uses stock `config/compaction-threshold` helpers through `compaction_limits`; typing never waits for bridge validation.
- Stats: `resources/gui-bridge/stats-host.ts` runs the user's omp-stats server (stock `omp stats` always opens a browser) and adds the paginated `/api/stats/requests` route stock lacks. It also starts stock's live ingest (`omp-stats/live` `statsLive().start()`: a full sync at start and every 5 min, plus each transcript a session writes, 800 ms after it), because stock's server starts it only when a dashboard page subscribes to `/api/events`, which `omp stats` always opens and the GUI never does: without it `~/.omp/stats.db` stopped at 15 Oct 2026 for five days while sessions ran. The host attaches its stdin shutdown before any startup await, so a start that never finishes cannot orphan it (22 such hosts were seen running for days). The frustration judge's module (`pi-coding-agent/judgment/standalone`, the agent graph) is imported inside the judge callback, which stock calls only on a `/api/frustration/*` estimate or run (the GUI asks neither): loaded at start it was ~84 of the host's ~142 MB footprint and ~220 ms of its ~310 ms start (omp 18.14.0, macOS, 5 runs). Pinned by `stats-host-stock.test.ts` (installed omp: rows on disk and a reply written after start reach `/api/stats/requests` with no page open) and `stats-host.test.ts`.

### Sidebar families and subagent titles

- Files: `layout/sidebar/SidebarSubagents.tsx` (group, chip), `SidebarFamilyRow.tsx` (one-line row), `sidebar-family.ts` (pure rules), `stores/sidebar-subagents.ts` (open state).
- **Family** = everything derived from a session, shown together under its row, one indent level in: its subagents (the tab runtime's roster) and the sessions its agent opened with `ompdesk_session_open`, in a worktree or not, whatever their folder.
- **A row is live without a click, shown or not** (the owner's report, 6 Nov 2026, v0.116.0: a background session's chip, run state and waiting mark were stale until its row was clicked and hydrated it). Pushes only, no poll of every tab:
  - **Subagents**: stock's `RpcSubagentsTracker` starts its stream `off` and then writes no `subagent_*` frame at all, and only a window that showed a tab asked for one, so a tab opened in the background (`ompdesk_session_open`), woken there (an agent's message to a restored tab) or restarted unseen never told its row a subagent started or ended. `SidecarPool` asks every omp for `progress` as it becomes `ready` (`SUBAGENT_LEVEL_FLOOR`; the windows' and devices' own asks only raise it, `highestSubagentLevel`), and a hidden tab's window gets the lifecycle frames (`#forwardToHidden`). Stock's `get_subagents` is the same tracker the frames come from (no idle or parked status reaches it), so the focused pane's 3 s roster poll adds nothing for a hidden tab.
  - **A tab this page has no runtime for yet** (a page that just loaded lists its tabs after their frames start): every per-tab frame handler of `use-rpc-events.ts` goes through `openTabFrame`, which gives the tab its own runtime; `withSessionRuntime` would otherwise apply the frame to the focused tab's stores (another session's roster, transcript or model) and the tab's row would never hear it. Each tab list reads the roster of a hidden running tab once per runtime (`reconcileTabs`, `rosterRead`), whichever named the tab first, its status push or the list, since the starts of the subagents already running went by before the runtime existed.
  - **Pushes this page missed** (the owner's report, 7 Nov 2026, v0.118.2: a paired host's session on the phone counted no subagents until tapped). A hidden tab's frames are lost when the page is hidden (the web router drops a hidden page's stream pushes, `STREAM_CHANNELS`), when its socket or a paired host's link drops, and its roster outlives an omp that died under it (the full channel's `starting` reset reaches shown tabs only). So the roster is read again: on a page's catch-up (`reconcileTabs({resync: true})`, `web/resync-page.ts`) for each hidden tab that runs or whose roster still counts a live subagent (`holdsLiveSubagent`), and on a hidden tab's light `TAB_STATUS` turning `ready` or `running` from any other status (a new omp after a death or a wake, a paired host's tab back over the link; `useSessionTabs`). A turn that only ends reads nothing.
  - **An ask answered by no window** (an agent's `ompdesk_session_answer`, Autopilot): `routeSideChannel` sends every window the `answeredElsewhere` cancel, as for an answer another window gave; stock sends nothing when an ask is answered, so the card and the row's waiting mark stayed.

The tab entry carries `openedBy` (opener's tab id) and `openedBySession` (its session file) on `IpcTabInfo`; the saved tab layout keeps the file as `PersistedTabDescriptor.openedBy` (a restored tab's id is new; the file finds the opener; the opener's tab closing leaves the file). ### Split view and picking a session

- Files: `stores/tabs.ts`, rules in `shared/split-layout.ts`. Main owns tabs and the pool; the renderer owns what the window shows.
- A window shows one session alone or one split of 2–4 panes (`split`), and remembers the other splits it has shown (`rememberedSplits`: layouts only, no focus). A session is in at most one split, on screen or remembered.
- Three rules, all in `viewAfterPick`; every way of picking a session goes through `switchTab`: ① a pane of the split on screen only takes focus, the layout stays; ② a session outside the split leaves it and shows alone, full width, and the split on screen is remembered; it never replaces or opens into a pane; ③ a member of a remembered split brings that split back exactly as it was (sessions, positions, sizes) with the picked session focused, and the split that was on screen is remembered in turn.
- Picks: sidebar rows, ⌘1–⌘9, ⇧⌘[ ⇧⌘] / ⌘PageUp/PageDown when no split is on screen (with one they cycle its panes), tab overview, ⌃⇥ switcher, notification/prompt-card focus. The session picker (⇧⌘F) and the sidebar's stored-session rows open a session no tab holds as a new tab: a pick of an outside session (`switchSessionNow` never re-roots a pane's tab while a split shows; `activeTabUntouched` is false then).

  - Also refused: `Page.navigate` off http(s)/about:blank, `Page.close`/`crash`, downloads, `DOM.setFileInputFiles`, `Page.setInterceptFileChooserDialog`, `Input.setInterceptDrags`, an `Input.dispatchDragEvent` whose `data` carries `files` or a `file:` URL (Electron 36's debugger turns `files` into a real dropped File from the local path), a `Network.loadNetworkResource` whose `url` is not http(s) (Electron 36 already says "Unsupported URL scheme" for `file:`; the rule keeps local files out whatever a later Electron does), and `Security.setIgnoreCertificateErrors`/`setOverrideCertificateErrors`/`handleCertificateError`.
  - `Page.navigateToHistoryEntry` is allowed only after the relay reads `Page.getNavigationHistory` and the target entry's URL passes the same http(s)/about:blank rule, so `tab.back()`/`tab.forward()` work. The relay addresses only sessions this page's own debugger announced with `Target.attachedToTarget` (its frames and workers, never a `page`/`tab`/`browser` target); the page keeps its partition, sandbox and no-preload rules.
  - A banner shows the agent's last CDP method; Take over (or a tab switch, closing the panel, the session ending) detaches the debugger, closes the socket and stops the relay. `e2e/preview-agent.e2e.ts` drives it with stock's relay server and puppeteer-core from the installed omp: back/forward work; `Target.getTargets`/`attachToTarget`, `Tracing.start`, a file drag and a `file:` resource load are refused.
  - **Phone and paired host's tab** (the user's order, 1 Nov 2026: it was desktop-only, tabs on this computer): the robot button is on for every tab. A paired phone's page drives its offscreen preview window the same way (`PreviewPanel`'s banner and Take over are the phone page's own); a tab that runs on a paired host reaches the relay over the link, because it listens on the host's loopback. The page the agent drives is still the device's own native one (so it watches live and Take over/the robot button work as on the desktop, and the allowlist above applies device-side unchanged). One transport seam: `agentStart` (`preview/host.ts`) runs the same `PreviewRelayExtension` over a `RelaySocket` (`preview/relay-socket.ts`): `localRelaySocket` dials the loopback relay of a tab on this computer, `LinkRelaySocket` (`remote/link-relay-socket.ts`, from `RemoteDevices.previewRelay`, passed to `registerPreviewHost` by `ipc.ts`) carries the frames over `host.previewRelay.open/send/close` and the `host.previewRelay` event (protocol and host side in remote-devices.md › Agent browsing over the link). `agentStart` awaits the socket's `ready`, so a host without a relay (or an older OMPdesk, `unsupported`) rejects and the panel toasts instead of showing a banner that never attaches. For a host's tab the agent is the host's, so its `Page.navigate` and history entries may not name this computer's own addresses (`blockLoopback`, the rule `allowed()` applies to a typed address and `will-frame-navigate` to the page's own moves).
  - Pinned by `preview/host.test.ts` (a host's tab: the extension runs on this page over the tunnel and never dials the host's address, loopback refused, Take over/relay close, an unreachable relay), `agent-relay.test.ts` (`blockLoopback`), `remote/host-services.test.ts` and `remote/devices.test.ts` (the tunnel, both ends), `e2e/preview-agent-remote.e2e.ts` (a paired phone's page, and a paired device's page driven by the host's agent: drive, Take over, hand back; the device case needs a non-loopback address of this computer).
- **Agent visuals** (`src/main/preview/visuals.ts`, `visual-navigation.ts`, `page-scripts.ts`; contract `src/shared/preview.ts`): the `gui_visualize` host tool (registered with `gui_terminal_read`, local tabs only) shows a project `.html`/`.svg`/image/`.txt` file, inline HTML the agent wrote or an http(s) page as a Preview tab of the calling tab, and keeps a version per change (`<userData>/visuals/<id>/v<N>.<ext>`, 20 per visual, 100 visuals in `history.json`, Page options › All visuals…). `gui_visualize open` with an existing `visual` id moves that record to the new target.
  - Sessions: each window's preview has two in-memory sessions reused by every preview host of that window, storage cleared when a host is disposed: `web` (`preview-<win>`) for every page the user, a popup, the agent's browser or a web visual browses, and `visual` (`preview-visual-<win>`) for file and inline visuals alone. Those load from `omp-visual://v<N>-<id>/…`, registered on the visual session only: the entry from its snapshot, other files from the entry file's own folder (the project folder when the entry sits at its root) by known asset type, never hidden paths or anything outside it. A page stays in the session it was made in (`PreviewPageState.session`): a visual opens in a visual-session page (an empty web tab is replaced, a web tab is never reused), an address typed on a visual's tab opens a new web tab, and the agent's browser never takes a visual's page.
  - Egress: every response (404 included) carries a CSP (`VISUAL_CSP`: `default-src 'none'` with each allowed kind named, `connect-src 'self' data: blob:`, `form-action 'none'`, no frames or objects) so the page cannot send what it reads off its origin by `fetch`, `sendBeacon`, `<a ping>`, WebSocket, image, CSS, prefetch, form or frame. What CSP does not cover the host refuses (Security #3): whatever a visual's page starts itself (link, `location`, form, meta refresh, frame load, redirect) goes only to another version of the same visual or `about:blank`/`about:srcdoc` (`visualMayNavigate`); popups never open; downloads are dropped silently; WebRTC runs with `disable_non_proxied_udp`; the visual session's proxy is a dead `http://127.0.0.1:1` with `<-loopback>`, so TURN over TCP and any other socket go nowhere.
  - DNS prefetch, which no CSP or proxy stops, is off app-wide: `index.ts` adds `dnsPrefetchingEnabled=false` to `--blink-settings` (merged with any given at launch) before ready; Blink applies it after each page's preferences in every frame and `x-dns-prefetch-control: on` cannot undo it.
  - A web address refused right after a real click or key on the page (the C143 gesture window) shows in full in a notice whose "Open in new tab" loads it in a web tab, only when the user picks it.
  - `e2e/preview-visual-egress.e2e.ts` pins all of it against a 127.0.0.1 sentinel (TCP and UDP) that must hear nothing and the visual session's net-log, which must hold no host resolution the page asked for.
  - The page keeps the Preview's sandbox (no preload, permission-less sessions). Comment on an element / region, pins, parent element and CSS variable tweaks run in an isolated world (`PAGE_WORLD`) on trusted events and go to the composer as one message; `choose` returns a `data-choice` click only when trusted: a real mouse/key release on that page within 1 s and neither the agent's relay nor any debugger holds the page.

### SSH tools on this computer

- `src/main/ssh/`, contract `src/shared/ssh-tools.ts`, Settings › SSH: port forwards for a saved host (`ssh -N -L 127.0.0.1:<local>:127.0.0.1:<remote>`, saved in `<userData>/ssh-forwards.json`, started again at launch), the server's listening ports every 5 s (`SSH_PORT_POLL_SECONDS`), ssh-agent/key state, and a reconnect with growing delay until the chosen grace time (1 min–7 days, default 1 h).
- Every such ssh runs under the setup supervisor with `-F <userData>/ssh/config`, whose first `Host *` block pins OMPdesk's own `known_hosts` with `StrictHostKeyChecking ask` and no connection sharing, then includes `~/.ssh/config`. OpenSSH hands `-F` to every ProxyJump hop, so each hop's key is checked too.
- Host-key, password, passphrase and code questions come through `SSH_ASKPASS` (`askpass.ts`: a Node helper run by the app binary, a per-process token over a local socket) into `SshPromptDialog`; answers are never stored and expire after 2 min. A changed host key stops the forward until the user forgets the saved key.
- The agent's own ssh tool stays stock's. SSH server windows (a headless OMPdesk on the server) are out of scope: OMPdesk ships for macOS and Windows only, and remote devices cover running work on another of the user's computers.
