## Release

### Updater

- **Auth** (`src/main/update-auth.ts`). The repo is public: release lookup and asset download carry no Authorization header. A token is optional (`GH_TOKEN`/`GITHUB_TOKEN` → `gh auth token` → a safeStorage-encrypted token from Settings › Updates & about, whose row shows only while the updater is `auth-required` or a token is stored); it raises the rate limit and keeps updates working if the repo goes private. Never bundle a token.
  - A token answered 401 is dropped and the check retried anonymously. Only an anonymous "not found" ends in `auth-required`; a 403 with `x-ratelimit-remaining: 0` is a failed request, not missing access.
- **Release lookup.** Each check reads `/releases/latest` (or `/releases` with pre-releases on) through the API. `src/main/update-release.ts` validates the metadata comment with zod against the release (tag = version, asset present with that size), identically with or without a token. A missing, malformed or contradicting comment means no update and the error "no valid update information"; a release without this platform's file reports a missing installer. `src/main/update-provider.ts` gives electron-updater a custom provider (`setFeedURL({ provider: "custom", updateProvider })`) pointing at the API asset endpoint (`githubApiHeaders` in `updater-state.ts`); differential download is off.
- **One check at a time** (`runCheck`/`checkOnce` in `updater.ts`). A Check for Updates (menu, Settings, a paired device) arriving while the 5-minute background check runs joins it, and that check settles as asked: its failure or "no result" reaches the banner, so the card never spins on "Checking for updates…". Pinned by `updater-check.test.ts`.
- **Dev seams** (unpackaged only; launch Electron on the repo root so the version is `package.json`'s). `OMP_DEV_UPDATE_CHECK=1 OMP_DEV_UPDATE_MODE=manual` (+ `OMP_DEV_UPDATE_PRERELEASE=1` for a throwaway pre-release). `OMP_DEV_UPDATE_MODE=relaunch OMP_DEV_UPDATE_BUNDLE=<writable copy of OMPdesk.app>` runs the relaunch path against that stand-in and swaps it on quit.
- **Install modes** (`src/main/updater.ts`). Windows: electron-updater's NSIS flow (background download, SHA-512 checked, applied on restart or quit). On a restart the installer starts on a worker thread (`OmpNsisUpdater` in `src/main/nsis-updater.ts`, over `spawnDetachedOffThread` in `installer-spawn.ts`) and the quit follows once that attempt ends, started or not, because `CreateProcess` on the fresh unsigned setup waits for Defender's scan and would freeze the main thread for seconds. The install at app quit (`autoInstallOnAppQuit`) still spawns in place, because the process may end right after it. macOS, ad-hoc or signed, avoids Squirrel (it would need the ZIP the release no longer ships):
  - **relaunch** (writable bundle): download `ompdesk-mac-arm64.dmg` into `<userData>/updates/ompdesk-X.Y.Z-arm64.dmg`, verify SHA-512, `hdiutil attach -nobrowse -readonly`, copy the `.app` out with `ditto`, detach, check `codesign --verify --deep --strict`, bundle id and version (`stageBundleFromDmg` in `updater-state.ts`). On "Restart & install" or any approved quit a detached `/bin/bash` helper (`SWAP_SCRIPT`) waits for exit, swaps with rollback, and reopens on restart.
  - **manual** (read-only: DMG, App Translocation): the same DMG, verified and opened in Finder from Downloads.
- **Install updates automatically** (Settings › Updates & about; pref `appAutoUpdate`, `APP_AUTO_UPDATE_PREF`, `AppAutoUpdateRow.tsx`). **Default on** (the user's rule, so an unattended Mac running Autopilot updates itself): only a stored `false` turns it off. Off: check, background download, "Restart & install", applied on the click or any approved quit.
  - On, once a verified update is downloaded and `restartableUpdate()` holds (relaunch or NSIS; never the manual DMG, whose switch is disabled with the reason, `updater:installMode`), `AutoInstallScheduler` (`src/main/app-auto-update.ts`, electron-free, injected clock, ticked every second by `updater.ts`) decides when.
  - **With Continue interrupted work (`resumeInterrupted`) on: the next safe point.** No ask, approval or plan-proposal card open (`asking`: the pool's and hosted tabs' open asks, `SidecarPool.restartHolds().planWaiting`) and no compaction under way (`compacting`: `restartHolds().compacting`, `LocalHostServices.compacting()`; a cut compaction does not resume). Nothing else holds it back (a running turn, background subagents and jobs, a focused window, typing, Autopilot runs, hosted tabs), because the relaunch continues the turn and restarts the subagents and cut commands (see Interrupted turns; `bridge-restore-subagents`, `turn-resume`). At the countdown's end it waits for a safe point again (log `held`, `open ask` | `compaction`) instead of installing over a card. Log `safe {waitedMs, running, resume}`. A card or a compaction has no cap (holds past the 30 min max wait too).
  - **Background work never holds the automatic restart** (the owner's rule). `AutoInstallFacts` has no background-work fact; there is no background-work wait, log reason, `overdue`, waiting notice or frozen countdown, and the update card has two states, the countdown and installing. Do not bring a hold, a wait or a notice for background work back without the owner.
  - **A person's restart asks** (`confirmUpdateRestart` in `app-quit.ts`, decided by `updateRestartConfirmation` in `quit-guard.ts`; "Restart & install", the countdown's "Now", the tray: all `applyUpdate`). With resume on and background work running, one native confirm names it (up to 3 names, subagents first; Restart / Cancel, Cancel default); with nothing running it asks nothing. With resume off the existing quit confirm covers running work. The scheduler's own install never asks. The only reader of background work is `askBackgroundWork` (`src/main/background-work.ts`, electron-free): the bridge's `composer.jobs` of every omp whose run is on, this computer's tabs and the tabs it hosts (`SidecarPool.runningBridges()`, `LocalHostServices.runningBridges()`), asked fresh at the click, one request per running tab. **It fails closed**: a tab whose request fails or takes over 3 s (or a pool that cannot be listed) is `unknown` work, named in the confirm; it never throws. **A paired page asks on the page** (`applyUpdate("device")` for a caller with a `connId`): its `ConfirmSheet` names the running work, and this computer shows no dialog. **A paired computer** asks in its own `ConfirmDialog` with the same sentence, then sends `host.desktop.update {action: "restart-now"}`, which the host runs while work runs only when its countdown shows; otherwise it is `install` (`host_busy` while work runs). `postpone` is the countdown's Later. Actions: `HOST_UPDATE_ACTIONS` (`src/shared/ipc-types.ts`). Pinned by `machine-services.test.ts` (paired device on the countdown) and `background-work.test.ts`.
  - A check while an update is downloaded answers with it and changes nothing (`checkForUpdate`), so a check (Settings › Updates checks as it opens) never drops the countdown. Pinned by `updater-install.test.ts` ("a check while the countdown shows keeps the countdown").
  - **With it off, or after the user's "Later" that round:** a quiet moment: no tab running a turn or compacting, no ask open (`resumeFacts`/`tabInventory`, this computer's and hosted tabs), and every window unfocused or no input for 2 min (`AUTO_INSTALL_IDLE_MS`, `powerMonitor.getSystemIdleTime`). Not quiet after 30 min (`AUTO_INSTALL_MAX_WAIT_MS`): with resume on it proceeds anyway (`forced`); with it off it never forces and keeps waiting for idle.
  - Then it announces: `UpdateStatus.downloaded.restartAt` (epoch ms, 60 s ahead, `AUTO_INSTALL_COUNTDOWN_MS`) shows one quiet line with a countdown and "Now / Later" in the sidebar update card and Settings › Updates & about, never a modal. "Later" (`updater:postpone`) postpones to the quiet-moment rule and restarts the 30 min wait.
  - At the deadline `restartIntoUpdate()` runs the existing quit path (`requestQuit`/`quitAndInstall`, so drafts, layout and resume markers survive); with resume off and work started during the countdown it withdraws the notice instead of asking. It first sets `UpdateStatus.downloaded.installing` (optional, also in the remote host schema): card and Settings row read "Installing update X…" with no button, even for a version put off with Later, and `current.installing` guards `restartIntoUpdate` and `updater:apply`, so a second click, a second "Now" or the deadline starts nothing. The scheduler is done once `install` ran; it announces and installs again only after the update stops being installable (install failed) or the pref goes off.
  - Dev seams: `OMP_DEV_UPDATE_STAGED` (+ `OMP_DEV_UPDATE_STAGED_VERSION`) treats a bundle as the verified staged update (with `OMP_DEV_UPDATE_MODE=relaunch`, `OMP_DEV_UPDATE_BUNDLE`; `e2e/fixture/stand-in-bundle.ts`); on Windows it is a pretend NSIS update whose install only quits (`devDryInstall`: every decision before it runs as shipped). `OMP_DEV_UPDATE_AUTO_COUNTDOWN_MS` shortens the countdown, `OMP_DEV_UPDATE_AUTO_MAX_WAIT_MS` the max wait after "Later" (unpackaged only). `e2e/app-auto-update.e2e.ts` (macOS) covers the default (installs unclicked), a stored off (waits) and a running background subagent (`OMP_GUI_TEST_BACKGROUND_JOB=1`, finished by `fixture:finish-background`; log `safe` → `countdown` → `install`); `e2e/app-auto-update-parity.e2e.ts` is the parity spec (this computer, a paired computer, the phone at 390 px); the second test of `e2e/autopilot-restart.e2e.ts` installs during an Autopilot cycle and the relaunch continues it. Pinned by `app-auto-update.test.ts` (resume on/off cases), `background-work.test.ts` (the ask, the naming), `quit-guard.test.ts`, `app-quit.test.ts` and `updater-install.test.ts` (installs while background work runs, no confirm).
- **The relaunch comes back as the app sat** (the user's rule). When an install begins (`beginInstall`, before the quit tears the windows down) `windowPresenceOf` reads every window: none shown → `hidden` (closed to the tray, or macOS with no window shown), all shown ones minimized → `minimized`, none focused → `behind`, else nothing. The install marker (`update-install.json`, `PendingInstall.presence`) carries it, and the next launch reads it before its first window (`readRelaunchPresence`, only within `RELAUNCH_PRESENCE_MS` of the helper's start, never with an argv folder): `WindowManager.launchPresence` keeps restored windows hidden, minimized or shown without focus (`showInactive`), and a hidden relaunch on macOS gives the focus back (`app.hide()`). The tray, the Dock and a notification bring them back as always. Pinned by "relaunch presence" in `update-log-core.test.ts` and "records how the windows sat" in `updater-install.test.ts`.
- **Update log.** Every decision goes to `<userData>/logs/gui-runtime.jsonl` (source `app-update`, `logUpdate` in `updater.ts`, `details.level: "info"`), so an unclicked restart is explained from the log (Copy diagnostics carries the last 100 entries, repeats folded, redacted). Never the token or a URL: failure reasons pass `scrubUpdateText` (`update-log-core.ts`: drops URLs and the token, runs the diagnostics redactor). `message` is the area, `details.event` the step:
  - `check` (every check, background one every 5 min): `no-update` | `found` {version, current, mode} | `error` {kind: a release-metadata code, `auth-required:<reason>`, `check-failed` or `no-result`, reason}.
  - `download`: `started` {version, mode, bytes} | `verified` {…, ms} | `failed` {version, mode, reason}; `mode` = relaunch, manual or nsis.
  - `scheduler` (transitions only, never one line per tick): `waiting` {reason: `busy turn` | `open ask` | `compaction` | `focused+active input`, waitedMs} once per reason; `safe` {waitedMs, running, resume} (resume on); `quiet`; `forced` {waitedMs, maxWaitMs, resume, reason} (30 min, resume on, after Later, a busy turn); `countdown` {restartAt}; `held` {reason} (a card or a compaction at the countdown's end, resume on); `postponed` {by: user}; `withdrawn` {reason: `pref off` | `update not ready` | `work started, resume off`}; `install` {trigger: `auto` | `user click` (incl. a paired device's) | `quit`} once per install, and nothing from the scheduler after it.
  - `swap`: `helper` {mode: `relaunch` | `nsis`, from, to, trigger} when the helper starts (it also writes `<userData>/update-install.json`); next launch one `result` {outcome: `installed` | `rolled back` | `changed`, previous, expected, current, mode, trigger, launchedAt; on macOS swapAt + swapOutcome from `swap.log`'s last entry, e.g. `install failed; previous app restored`}.
  - Pinned by `app-auto-update.test.ts` (transitions, no duplicate lines, done after `install`) and `update-log-core.test.ts`; `updater-install.test.ts` (double click installs once, "installing" before the installer starts, no second countdown after a stall), `nsis-updater.test.ts` (quit waits for installer start, failed start still quits and reports, install at quit stays in place) and `installer-spawn.test.ts` (a real process); the installing row in `SidebarUpdateCard.test.tsx`.
