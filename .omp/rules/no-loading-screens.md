## No loading screens

The user's rule: nothing waits on a spinner or a blank window; the app appears at once and fills in. `e2e/no-loading.e2e.ts` measures it. Paths are under `src/renderer/` unless full.

### Last known state
- `lib/snapshot-cache.ts`: localStorage on both surfaces (the first React render reads it synchronously). One key per kind × namespace × key: `omp.snap.<SNAPSHOT_VERSION>.…`; a version bump needs no migration (the old generation is never read; `pruneStale` deletes it). Kinds: `shell`, `tabs`, `sessions`, `transcript`, `usage`, `models`, `panel`.
- Namespace = whose data: `local` or `device:<id>` of a paired host, so a host's snapshot never paints as this computer's. `clearNamespace` forgets one; `clearAll` runs on an unpair (`web/web-boot.ts`).
- Bounded: entry ≤ `ENTRY_MAX_CHARS` (240 000), each kind keeps its newest `KIND_LIMITS`, whole cache ≤ `TOTAL_MAX_CHARS` (1.8 M), least recently written out first, a full storage evicts once and retries. Older than 30 days (`SNAPSHOT_MAX_AGE_MS`) is not read.
- **Private**: `scrub` runs on every write (credential-named keys dropped; token-, JWT-, PEM-, bearer-shaped strings replaced; inline picture bytes dropped). A setting's value (can be a secret) is memory only (`settings-data.tsx` `lastRead`).
- Never authoritative: a reader paints it and the live read replaces it in place. Writes are idle and coalesced, never on the render path.

### What is cached
- `sessions`: sidebar index, newest 150 rows (`stores/session-list.ts`; keeps its rows when the last holder lets go; the skeleton shows only with nothing known)). A held list whose read failed reads again after 2 s, doubling to 30 s, until one answers (`READ_RETRY_MS`): a paired host's last-known rows could otherwise keep sessions deleted there on screen (the user's report, 23 Oct 2026). A list reads again only when its own machine's list changed: `sessions:changed` names the paired host (`IpcSessionsChanged.device`, absent for this computer), because both computers of a pair write their journals all the time and every change of one made every list on the other re-read (a device asked its host for the list 21 times a minute; `session-list.test.ts`).
- `transcript`: a session's newest ≤ 120 committed rows (`lib/transcript-snapshot.ts`; key = session file, a file the tab is about to open, or the id). `installTranscriptSeeding` (`hooks/session-hydration.ts`, called in `main.tsx` before the first render) seeds every listed tab the moment its file is known, before its omp is ready, rebuilds tool cards, marks the store `restoredAt`. `commitHydration` then replaces the seed wholesale: a seed is a guess, never "loaded history" (no `prevCursor`; same-content rows keep their objects so nothing re-renders or moves).
- `models`: catalog and each session's selection (`lib/model-snapshot.ts`; catalog generation never restored; `resetSessionSurface` keeps the catalog). `usage`: last reports per host (`hooks/use-usage-reports.ts`). `panel`: a page's last read (`lib/last-read.ts`). `tabs`: below.

### Quiet cues, never a spinner for content
- A stale item shows the `omp-updating-hint` note (text over the top edge, hidden for its first 0.7 s, one opacity fade, nothing running after, still under software compositing). Older history streams in above through `TranscriptHistoryStatus` (same still note, out of the flow).
- A first visit shows a static skeleton shaped like the content (`TranscriptSkeleton`, `PageFrameSkeleton`, `SkeletonRows`; `AsyncSection`'s first load is `SkeletonRows`), **no shimmer**: `.omp-skeleton` is a flat fill (the sweep repainted every frame). A new empty tab (`starting`, no session file) shows the empty canvas at once; a tab opening a file shows the skeleton only until its rows come.
- A connecting/reconnecting session is a hollow still dot in the title bar (`StatusTone` `pending`, `TitleBar.tsx`).
- A spinner turns only for work happening (a running turn, a `Button`'s own action, a row's save/toggle: `<Spinner spin>`). `Spinner` is a still hollow ring by default (`Spinner.test.tsx`), so a content wait with no better form (Terminal starting, Preview loading, a dialog's probe) is a still frame; `IconButton loading` is still too. Under `html[data-gpu="software"]` even `spin` holds still, and every other looping animation (pulses, shimmers, carets, sweeps) plays once and rests (`global.css`; the indeterminate bar settles full width), pinned by the software test of `e2e/composer-live.e2e.ts`. Anything with a shape is a snapshot or static skeleton.

### Preload and transitions
- `components/layout/AppShell.tsx`: Settings, Agents, Insights load idle (≤ `IDLE_PRELOAD_TIMEOUT_MS` 3 s after start; a paired web page waits `WEB_PRELOAD_DELAY_MS` 5 s first) and on intent (pointer over, focus, touch start on a sidebar destination, the panel toggle or a rail pin: `preloadForIntent`; the panel's views via `preloadPanelViews`). Rendered from `loadedPages`, never through `lazy()` (~300 ms Suspense throttle). The first-screen budget in `scripts/check-main-bundle.ts` is unchanged.
- `lib/view-transition.ts`: a page and a Settings section cross-fade (View Transitions API, opacity only, `--sc-duration-fast`) and otherwise change at once: reduced motion, `html[data-gpu="software"]`, hidden document, no API, a swap inside a running transition. The side panel's views are not transitioned (the document is not tappable during one; a panel opens to be used at once). A page's content fades in once (`omp-page-in`).

### Panels and pages paint their last read
- `lib/last-read.ts`, kind `panel`, per host; keys name the folder, never another repository's rows. `lib/focused-scope.ts` = the focused tab's `{device, cwd}`.
- Readers: `useGithubLoad` (`lib/github.ts`; every GitHub list/detail of the Agents page, not a run's log); PR Center (`stores/pr-center.ts`: `enter(scope)` seeds repo and list before first paint; a slower answer for an earlier PR never replaces the one shown); Changes (`scm:changes`) and Commit history (`scm:log`), open diffs in memory only; branch picker; agent editor's authoring data; Files (tree per folder, memory plus snapshot up to `TREE_PERSIST_MAX` 1500; an opened text file ≤ 100 000 chars in memory only: `components/panels/viewers/use-file-read.ts`).
- First visit is a static shape: `PrDetail` skeleton, `DiffSkeleton` (`scm/DiffLines.tsx`), `ViewerLoading`, `SkeletonRows`; a rendering diagram is a flat box inside its `Figure`. Remaining spinners are still rings (Terminal, Preview, dialog probe) or action feedback.

### Tab strip and ghosts
- `lib/tab-snapshot.ts`, kind `tabs`: one entry per window `?slot=` (creation order; `web` for a phone), written 500 ms after the strip last changed, never from ghosts. `useTabsStore` starts from it: the first frame has the strip, the open tab's title, the sidebar's selected row (current by the tab's session file even before the session store has an id) and its last rows (via `installTranscriptSeeding`).
- Those tabs are **ghosts** (`SessionTab.ghost`): last run's ids, nothing runs behind them. `reconcileTabs` adopts each into the real tab of the same session file (a blank one takes the next blank ghost; same place, same selection) and drops the rest with their runtimes; `switchTab`/`closeTab` ignore a ghost.
- The real tab has a new id and fresh runtime, so what the user already typed (draft, pictures) is carried when `takeGhost` adopts it (`carryGhostComposer`, `stores/tabs.ts`; what the real tab holds wins). New per-tab state the first frame lets the user edit needs the same carry plus a test in `tabs.test.tsx`.

### A new session is usable before its omp is ready
- `stores/tab-ready-gate.ts` (installed by `tabs.ts`): the tab appears at once (`openTab`, `status` `starting`), the composer takes draft and send (`use-composer-submit.ts` accepts `starting`), and `tab-runtime.ts`'s `command` holds every command of a starting tab until the tab list says otherwise (≤ `READY_WAIT_CAP_MS` 120 s), then sends. Nothing shows the wait. A failed spawn fails the command as always and the composer restores the draft. A tab waiting for another omp to let go of its session (`isSessionHeld`) is held the same way: the composer takes the send and the gate waits until it opens. A `restarting` tab is still refused.
- **A new session lists nothing until the person writes to it** (the user's rule, 23 Oct 2026: opening a new session creates no session they did not type). A fresh tab and one ⌘N reset (stock `new_session`) are `unstarted` (`PoolEntry.unstarted`, `IpcTabInfo.unstarted`, set at a spawn with no session file and by a successful `new_session` in `dispatchRpcCommand`): the sidebar draws no live row for it (`Sidebar.tsx`, a host's `SidebarDevices.tsx`), as for the `placeholder` start tab, while its folder keeps its project group (`WorkspaceGroup.open`; on a host, an empty group of its folder) so its + and ⋯ stay. The person's first prompt, steer, follow-up, `!` or `$` line (`TYPED_COMMANDS` in `ipc.ts`) or a run's `agent_start` ends it (`SidecarPool.noteUnstarted`). One the person showed and then left for another tab, still empty (no draft, picture, queued message or run) and not a pane of the split on screen, is closed by `TabHousekeeping` (with no row they could not find it again); one they never showed (an agent's background tab before its first prompt) stays. Stock writes a fresh tab's file only at its first assistant message; ⌘N's in-place `new_session` still writes a header-only file, which no list shows (`sessionHasContent`). Pinned by "lists a new session only once its first run starts" in `Sidebar.test.tsx`, "marks a new session unstarted …" in `sidecar-pool.test.ts` and "closes an empty new session the person showed and left" in `TabHousekeeping.test.tsx`.
- **An Enter during a send is held, not dropped** (`use-composer-submit.ts` `heldSend`): `sending` lasts the prompt's round trip (10 to 115 ms measured on a Windows PC; a `!` command's whole run), and an Enter inside it used to do nothing with the draft kept (the workbench-shortcuts and preview-visualize specs lost 1 in 4 to 6 of 6). It now goes out when `sending` clears, only if the field still holds the pressed text: a failed send puts its own text back and an edit changes the draft, so either cancels it. Pinned by `InputArea.queue-shorthand.test.tsx`.

### The first frame is the layout
- `scripts/boot-shell.ts` → `index.html`/`web.html`; `public/pre-paint.js` sets what it reads. A flat skeleton of sidebar, top bar, transcript with the small π and the composer box, built from the app's own classes (`omp-session-sidebar`, `omp-topbar`, `omp-composer-box`, …) so the render-blocking CSS gives the real geometry; React's first render replaces it with nothing moving (`bootShift` ≤ 2 px).
- Composer box height = `COMPOSER_BOX_PX` in `src/shared/boot-shell-geometry.ts` (desktop 92, phone 77), measured against the React box: change the composer's height and the e2e names the new number.
- Sidebar width is mirrored to localStorage (`lib/sidebar-width.ts`, `omp.sidebarWidth` → `--boot-sidebar-w`); collapsed state likewise (`lib/sidebar-memory.ts`, `omp.sidebarVisible` → `data-boot-sidebar="hidden"`). `pre-paint.js` keeps the saved scheme and, in the desktop app, sets `data-platform` so the traffic-light room is there on frame one. The web variant has no sidebar below 1000 px and the phone's short bar and one-row composer, from media queries (`html[data-shell]` is not set yet).

### Tests
- Unit: `snapshot-cache.test.ts` (versioning, bounds, eviction, namespaces, privacy), `transcript-snapshot.test.ts`, `model-snapshot.test.ts`, `stores/session-list.test.ts`, `view-transition.test.ts`, `tab-snapshot.test.ts`, `sidebar-width.test.ts`, `lib/github.test.tsx`, `stores/pr-center.test.ts`, the ghost cases of `stores/tabs.test.tsx`.
- `e2e/no-loading.e2e.ts` (frame by frame via `e2e/loading-probe.ts`): a warm desktop start, a tab switch, a warm phone load (4× CPU, 150 ms link), the PR and GitHub centers, Changes, Commit history, Files, Terminal, Preview and Quick open (each opened twice) show no spinner, no blank window, no empty transcript, and move layout ≤ 0.05 (CLS); boot skeleton boxes equal the React layout's (≤ 2 px, desktop and phone); title and selected row are on the first React frame; a new session's composer takes a message sent at once and it reaches the omp when ready (the session file holds it).
- Perf numbers are opt-in and live in that file's header: `OMP_GUI_LOADING_PERF=<dir>`, `OMP_GUI_LOADING_SUBJECTS=before=<checkout>,after=<checkout>`, `OMP_GUI_LOADING_RUNS` (default 3), `OMP_GUI_TEST_BOOT_DELAY_MS` (fake omp boot; 800 ms, 1500 ms in a perf run). Frame strips: `<dir>/strips/<subject>/<scenario>.png`.
- A new surface that fetches on open follows these rules. A test mounting a store with module state calls its `reset…ForTest` (`resetSnapshotsForTest`, `resetSessionListFeeds`, `resetLastReadForTest`).
