# ompdesk — Development Rules

Read this before any edit in this repository.

## Repository identity

- Product: **OMPdesk** (`OMP` capitals, `desk` lowercase) is the display name in every user-visible string, the bundle (`OMPdesk.app`, `productName`), menus, tray, and window title. An unofficial desktop app for the omp agent. Identifiers stay lowercase: the package name, the bundle id `com.seuput.ompdesk`, `app.setName("ompdesk")` (which picks userData `~/Library/Application Support/ompdesk` (`%APPDATA%\ompdesk`) and the "ompdesk Safe Storage" keychain item), the repo, and the two release asset names `ompdesk-mac-arm64.dmg` / `ompdesk-windows-setup.exe` (README download links and the updater fetch them by exact name; `packaging-config.test.ts` pins them). The first launch moves the pre-rename profile from its sibling directory into userData before anything reads it (`src/main/legacy-user-data.ts`, skipped under `--user-data-dir`). Say "omp" only for the agent/CLI (`omp update`, "omp 18.7+"). The mark (an omp-style π: top bar and two legs, the shorter left leg ending in an accent-colored foot; full and ≤48px pixel-grid forms) is defined once in `src/shared/brand-mark.ts`; `bun run gen:icons` writes the SVGs in `resources/icon-source*.svg` and `resources/brand/` from it (`scripts/brand-svgs.ts`; never hand-edit them, `brand-mark.test.ts` fails on drift; the hand-made README buttons `resources/brand/download-*.svg` are exempt) and regenerates `icon.png`/`icon.icns`/`icon.ico`, the tray PNGs and the favicon. The in-app mark is `components/common/BrandMark.tsx`.
- Product repo: [`SeuPut0705/ompdesk`](https://github.com/SeuPut0705/ompdesk) (`origin`). All code, tags, and releases live here. The repo is **public** under the MIT License (`LICENSE`, `Copyright (c) 2026 SeuPut`; contributions come in under MIT too, no CLA). There is no `NOTICE` file: the attribution of vendored code (Mixdog-adapted files, REA's skill, the lobe-icons brand marks) and the license of every bundled dependency live in `THIRD_PARTY_NOTICES.txt`, generated from `node_modules` and `scripts/generate-third-party-notices.ts` by `bun run gen:licenses` (`bun run licenses:check` fails when it is stale; regenerate when production dependencies or vendored code change; the license texts of vendored code are in `LICENSES/`). `LICENSE`, `THIRD_PARTY_NOTICES.txt`, `LICENSES/` and Electron's `LICENSES.chromium.html` ship inside the app (`extraResources`, pinned by `packaging-config.test.ts`). Never commit a secret, a real e-mail, a tailnet or LAN address, or a screenshot showing one: the history is public.
- The agent is **stock omp** ([`can1357/oh-my-pi`](https://github.com/can1357/oh-my-pi)) installed on the user's machine. It is never built, vendored, or forked here. Users get agent updates with `omp update`.
- Platforms: **macOS and Windows only.**
- Brand surfaces, all generated by `bun run gen:icons` from the one mark (never hand-drawn; `brand-mark.test.ts` and `packaging-config.test.ts` pin them): the app icon (`icon.icns`, `icon.ico`, `icon.png`), the tray PNGs, `brand/app-icon.png` (256 px: `BrowserWindow` `icon` on Windows, the About panel's `iconPath` and Windows toasts through `src/main/app-icon.ts`; packaged as `extraResources` `app-icon.png`), `dmg-background.tiff` (the DMG window, `dmg.background`; the volume icon is `icon.icns`), the NSIS `installerIcon`/`uninstallerIcon`, the favicon and a first-paint mark in `#root` of `index.html` and `web.html` (`brandHtml` in `scripts/brand-svgs.ts` writes both; React replaces it), the PWA icons and the push `badge` (`icons/badge-96.png`), and `brand/social-preview.png` (1280×640; GitHub has no API to set it: upload it in repo Settings › Social preview). A new surface that shows the app's identity gets its asset from `scripts/brand-svgs.ts`, not a copy.

## Architecture

```
renderer (React) ── IPC ──▶ main (Electron)
                              ├─ src/main/local/*      fork-era commands served in main
                              │     (git/gh, fs, ~/.omp files, `omp` CLI, translation to stock RPC)
                              ├─ src/main/sidecar.ts   spawns `omp --mode rpc-ui -e <gui-bridge>/index.ts`
                              │                         (stock RPC over stdio)
                              └─ src/main/bridge-client.ts ◀── unix socket / named pipe ──▶
                                                         resources/gui-bridge/*  (omp extension,
                                                         live AgentSession access)
```

- The renderer speaks one command set. `RpcClient.command()` (`src/main/rpc-client.ts`) first looks for a **local handler** (`src/main/local/index.ts` merges `src/main/local/<area>.ts` maps; duplicate keys throw at startup). Commands without a local handler go to stock omp unchanged.
- A local handler (`LocalHandler`, `src/main/local/types.ts`) either does the work in main (git, gh, files, `ctx.omp.run([...])`), translates to stock RPC (`ctx.send(...)`), or calls the bridge (`ctx.bridge.request(method, params)`) when it needs live session state.
- Main's IPC handlers register through the one `IpcRegistry` (`src/main/web/ipc-registry.ts`, created in `index.ts`), never on `ipcMain` directly: `ipc.handle(channel, (caller, …args) => …)` / `ipc.on(…)` registers on `ipcMain` as before and also in the table a non-Electron caller (the planned web client) is dispatched from. A handler finds its window as `caller.win` (a `ClientWindow`, `src/main/web/client-window.ts`: the id, `send`, `isDestroyed` and the `closed` listener the sidecar pool, the window records and the handlers use), the calling page as `caller.sender`, and only a dialog sheet, the title-bar overlay or the preview take the native `caller.browserWindow`.
- `window.omp` is `createOmpApi(transport)` (`src/shared/omp-api.ts`): the preload hands it an `ipcRenderer` transport and adds only `fs.pathForFile`; a paired web page will hand it a WebSocket one. A new API member goes in `omp-api.ts`, never the preload. Every channel is classified in `src/main/web/ipc-policy.ts` (`IPC_POLICY`, typed over the whole channel union: a new channel does not compile until it has a direction, a `WebPermission` and a web mode; `ipc-policy.test.ts` matches it against the handlers main registers and the channels `createOmpApi` subscribes to). The web client's frames and permissions are `src/shared/web-protocol.ts`.
- Multi-viewer (`sidecar-pool.ts`): a tab has its owner window and may have viewer windows (`attachViewer`; only a paired web device's window, whose ids are negative, ever views another window's tab — `tab-spawn.ts` attaches one instead of refusing an owned session; env `OMP_GUI_TEST_VIEWER_WINDOWS=1` lets any window do it, for `e2e/multi-viewer.e2e.ts`). Each window keeps its own active/visible/split view; the full channel is wired once per tab and fans out to every window it is visible in; the light channel reaches owner and viewers. A viewer closing the tab only leaves it (`detachViewer`), the owner's close releases it for all (`TAB_LIST_CHANGED` to the viewers, which the renderer applies with `applyTabList`: `shared`/`viewerCount` on the tab, shown by `ViewersChip`). The first window to answer an ask wins: the others get a synthetic `cancel` (`answeredElsewhere`, a toast "Answered on another device"), a later answer fails `already_answered` (also a toast, the card closes). Draft-empty reports count per window (`noteDraft`), the subagent stream level is the highest any window asked (`noteSubagentLevel`), a mode toggle tells the other windows to re-read (`noteModeChanged` → `config_update {modes: true}`), a shared tab's notification is deduped across its windows, its terminals are keyed by the owner window, and `PREFS_SET` pushes `PREFS_CHANGED` to the other windows. Renderer rules that keep a shared tab honest (`stores/messages.ts`, `composer-submit.ts`): on a shared tab or a web page a plain message goes as `prompt(streamingBehavior)` and the host decides steer/follow-up (`hostDecides`), an optimistic echo is claimed only by the delivery with its own text (`sharedTab`, `ownSends`) and any other user delivery is another viewer's (`fromOtherViewer`, "from another device"), the dequeue's `omp:fill-composer` names the asking `tabId`, quota resume runs in the owner window only, and a web page keeps its own done marks (`lib/unread-marks.ts`). Prompt origins: main sends the bridge `prompt_origin_set {origin, text}` (local command `prompt_origin_set`) before a prompt, steer or follow-up from a paired web device (every window under the test hook) reaches the omp; `resources/gui-bridge/prompt-origin.ts` journals that device for the user message with that text, `labelPromptOrigins(…, null)` marks every prompt of a local transcript with `promptFromId`, and `ipc.ts` localizes each `get_transcript_page` per window (`localizePromptOrigins`: its own prompts plain, the host's named with the computer's name). A live delivery on another window says only "from another device" until the transcript is read again.
- Mobile web server (`src/main/web/`; assembled by `WebHost` in `web-host.ts`, created in `index.ts`): HTTP and WebSocket on `127.0.0.1:47831` only (`tailscale serve` publishes it; the Tailscale side is `src/main/tailscale/`). `server.ts` serves the built renderer from an allowlist (`/` and `/pair` → `web.html`, `/assets/ /cmaps/ /standard_fonts/ /wasm/ /icons/`, the manifest, `sw.js`; traversal refused), `POST /api/pair` (no code: an allowed Tailscale login's first visit makes the device and its cookie), `POST /api/session` (the device signs a server nonce with its WebCrypto key, then gets a 30 s single-use ticket), `/ws`, `/blob/<token>` (Range; HTML/SVG are downloads only) and `POST /upload` (25 MiB a file, 200 MiB a device in 24 h, deleted after 24 h). `auth.ts` checks every request, in this order: loopback peer; any `Tailscale-Funnel-Request` refused; **the secret path prefix** (`stripServePrefix`, constant-time: a request without it, or before serve is published, is a bare 404 and none of its headers is read; the server takes it off, so the page never sees it); `Host`, `Origin`, `Sec-Fetch-Site`; then `Tailscale-User-Login` (RFC 2047-decoded) against the allowed logins — a login that is not allowed, or no login (a tagged node), gets `refusal-page.ts`'s HTML (which account to use, `Accept-Language` ko/en; JSON `tailscale_user_not_allowed` / `no_tailscale_user` for an API call). **Identity is Tailscale's**: those walls decide who may ask, and the device cookie is what every later call uses (`__Host-ompdesk` over HTTPS; `devices-store.ts`: `web-devices.json` 0600, only the secret's SHA-256, 14 days sliding / 90 absolute, the record keeps the Tailscale node `nodeId`). `POST /api/pair` asks `tailscale whois` about serve's `X-Forwarded-For` address (injected `whois`, cached 60 s): the node's stable ID and device name (the device is named after it, else the page's own name), refusing a login that whois does not put behind that address (`identity_mismatch`), a blocked node (`blocked`), and more than 10 tries a minute from an address or 20 new devices an hour (`PairingGuard`, `NEW_DEVICES_PER_HOUR`). With "Approve new devices on this computer" (pref `mobileWeb.confirmNewDevices`, default **off**) `pairing.ts`'s `PairingConfirmations` holds the visit until the desktop approves (`WEB_PAIRING_REQUEST` to the desktop windows only, 60 s); otherwise the desktop is told after the fact, once (`WEB_DEVICE_CONNECTED`, desktop windows only, a toast with Block). **Block** (`WEB_DEVICES_REVOKE`, `WebHost.block`) is a revoke that sticks: `blocks-store.ts` (`web-blocked.json` 0600) keeps the node's stable ID — never the login, since one login has many devices — and every record of that node is revoked (sockets close with 4401, the virtual window is destroyed); a cookie-less page load while a block exists and `/api/pair` look the visitor up (`whois`) and answer the "this device is blocked" page / `blocked`; a visitor whose node cannot be told while its login has a blocked node is held back too (`unidentified`, fail closed), and a device with no node identity is blocked by its login (`WebDeviceInfo.blockScope`, the confirm and the Blocked list say every device of that login), `WEB_BLOCKS_LIST`/`WEB_BLOCKS_REMOVE` list and lift blocks. Revoking by expiry only deletes the record. `ws-router.ts` turns `inv`/`snd` frames into `IpcRegistry.invoke/send` calls with the device's `WebClientWindow` (`web-client-window.ts`, negative id, parked while no socket is open) as caller once `IPC_POLICY` and the device's grants allow the channel (`web_forbidden` otherwise; `pairing-admin` is never served and a web device cannot write `mobileWeb.*` prefs), meters model commands through `PeerQuota` (`remote/peer-quota.ts` takes any `QuotaStore`), batches pushes every 75 ms (neighbouring slim `message_update` deltas of a reply are joined), stops the streams while the page reports itself hidden, and pings every 20 s (three quiet ticks end a socket). Calls only a web device has (`web:host.*` browse/save/open/reveal/blob, `web:models.config.read/write` for models.yml as text through `readModelsText`/`writeModelsText` (parser + schema check, atomic, refuses a file that changed since it was read), `web:device.uiPrefs.*`; `shared/web-host.ts`, `host-actions.ts`) are a table in the router, not in `IPC_POLICY`. `FS_READ_BINARY` answers `{dataBase64}` up to 512 KiB, else `{blobUrl}`; `FS_MEDIA_STREAM` answers a `/blob` URL served from `MediaStreams`. Tests drive time through injected clocks and `Timers`; `server.test.ts` runs the real server on an ephemeral port, behind the prefix and with serve's headers (a stubbed `fetch` adds them), with only the IPC registry, the desktop window and `whois` faked.
  - Mobile web threat model (no pairing code; the user's rule: copy the tailnet URL, open it on any device signed in to the same Tailscale account, and it works). **Who may connect**: a device whose request reaches us through `tailscale serve` with a `Tailscale-User-Login` in `allowedUsers` (default: this computer's own login, set in Settings › Mobile web), over a Tailscale network only (serve, never Funnel: `service.ts` has no Funnel command and an `AllowFunnel` flag on our port stops the server; `Tailscale-Funnel-Request` is refused). Anyone who can sign in to an allowed account on a tailnet device, and anyone the user shared the computer's Tailscale node with while that account is allowed, can make a device and gets `DEFAULT_WEB_GRANTS` (never `pairing-admin`); the user's tools are "Approve new devices on this computer", the notice's Block and the Devices list (access tiers, limits, Block). **Forged headers**: a local process can write `Tailscale-User-Login` and `X-Forwarded-For` to `127.0.0.1:47831`. Serve joins its target's path to every request's path, so `service.ts` publishes `serve --bg --https=<port> http://127.0.0.1:<local>/<secret>` where the secret is 256 random bits (`serve-secret.ts`, `web-serve-secret.json` 0600, made on first use); only traffic through serve carries it, and without it nothing is served (404) and no header is read (`auth.test.ts`, `server.test.ts` "headers forged on the loopback"). The secret is never in prefs (the `mobileWeb.serve` record holds the local address only; `serve.ts` `ownProxy` owns a handler only when it proxies to exactly the current secret target, or to the bare recorded address for the one-time cutover from an earlier release; any other path on that address is the user's own handler and is never touched) and is never logged. **Residual risk**: the secret is in `tailscale serve status` and the 0600 file, so a process running as the same user can read it and then forge a login (and an `X-Forwarded-For` that whois accepts, so whois' cross-check only catches a forgery that contradicts itself); such a process can already read the cookie store, the prefs and the user's files, which is why a single-user Mac is not defended against it (a different user of the computer cannot read either file). `Host`/`Origin`/`Sec-Fetch-Site` stop a web page in a browser from reaching the loopback port. **Not defended**: a compromised allowed account or tailnet device (use Block, and the approval setting), and Tailscale's own control plane. **Block** is by node, not login (a login has many devices); a revoked device that returns is refused, not re-enrolled, until Unblock.
  - Mobile web UI for that flow: Settings › Mobile web (`settings/MobileWebSection.tsx`) shows, once ready, the link in a monospace line with a big **Copy link** button and one QR of it (`MobileWebConnect.tsx`, steps: install Tailscale, same account, open the link, the iOS Home Screen note), the "Approve new devices on this computer" switch (`set-confirm-new-devices`), the connected devices with **Block** (`MobileWebDevices.tsx`; the confirm names `revokeBodyLogin` when `blockScope` is `login`), the **Blocked** list with Unblock (`MobileWebBlocked`, `stores/mobile-web.ts` `blocked`, read again whenever the device list pushes) and the allowed accounts; there is no pairing-code step anywhere. The desktop shows a new device as one toast with a Block action (`dialogs/WebDeviceNotice.tsx`, mounted in `App.tsx`, `mobileWeb.devices.onConnected`) or, with approval on, `WebPairingDialog`. The web page's `/pair` (`web/PairScreen.tsx`) has no form: the page sends a browser whose session is refused there, it makes the device key, calls `POST /api/pair` (`pairing.ts` `pairFailureOf` maps blocked / account not allowed / declined / rate limited) and goes into the app, or shows the reason with Try again; a browser that already can get a ticket just goes on. `e2e/mobile-web.e2e.ts` plays the phone with the fake Tailscale's headers through the prefix (forged without it → 404, first visit → one notice, Block, still denied, Unblock, the approval dialog).
- Web host sheets (`src/renderer/web/host-ui/`, mounted as `<WebHostUi />` in `App.tsx`, nothing on the desktop): the web page has no native dialogs, so `shim.ts` calls the hooks of `web/host-hooks.ts` and `WebHostUi` registers them, queueing one sheet at a time (`host-ui-store.ts`): `PathActionsSheet` (open/reveal a file: view on the phone through the Files viewer, open on the computer, download), `SaveImageSheet` (phone or computer), `HostBrowserSheet` (the computer's folder/file/save browser over `web:host.listDirs`, which also replaces the project picker), `EditorSheet` ($EDITOR round trip, or "Edit on computer"), `ModelsConfigSheet` (models.yml editor, same), `ConfirmSheet` (restart for an update, quit; names the running turns). A link opens on the device at once with a toast to open it on the computer. A device without `desktop-control` gets `hostUi.computerOff`. Every sheet has a component test in `host-ui.test.tsx`. On touch (`data-input=touch`) a sidebar session row shows one ⋯ button (`data-sidebar-row-menu`) that opens its action sheet instead of rename/archive/delete, so the title keeps the width (`mobile-shell.e2e.ts`).
- Preview and Terminal on a phone (web viewers only; the desktop paths are unchanged). Preview: a paired web window has no native view, so `preview/host.ts` gives each of its tabs an offscreen `BrowserWindow` (`offscreen: true`, sandbox, contextIsolation; sessions `preview-web-<winId>` / `preview-visual-web-<winId>` with every rule of the desktop page: non-persistent, http(s) only, permissions/downloads/new windows refused, remote-tab loopback blocked, the visual session's CSP and egress block) and `main/web/preview-stream.ts` (`PageStream`) turns its paints into JPEG frames. The viewer's `preview.stream.poll({ack})` is the only transport (channels `PREVIEW_STREAM_*` in `shared/preview.ts`, all classified in `ipc-policy.ts`); the next frame goes out only after the viewer acknowledged the last (`preview-pacer.ts`: ≤ 12 fps, DPR ≤ 2, `toJPEG` only when the pacer sends, nothing for a still page, a page nobody polls for 15 s stops painting). The renderer's `layout` request carries the surface's `dpr`; `PreviewPanel` mounts `PreviewStreamView` where the desktop leaves a hole for the native view, and sends no cover-detection layouts there. Input is `webContents.sendInputEvent` (`preview-input.ts`, never a debugger, so `isTrusted` holds and `choose` stays allowed): `lib/preview-gestures.ts` reads fingers (tap, double tap, swipe and fling → wheel, long press → context, long press and move → drag, pinch → zoom), `lib/preview-keyboard.ts` maps the hidden `textarea`'s `keydown`/`beforeinput`/composition (soft keyboard and IME; a composition is sent once, committed, as `insertText`). **The one exception to "no preload"**: the two phone sessions get the fixed preload `main/web/preview-dialog.ts` (written by `writeDialogPreload` at launch, `ipcRenderer` only, no page-reachable API) that replaces `alert/confirm/prompt` so the page's dialog waits for the viewer's answer (`PreviewStreamView`'s bottom sheet; an unanswered one is dismissed after 60 s, more than 5 in 10 s are dismissed unseen; `beforeunload` just lets the page go). `savePdf` is overridden in `web/shim.ts`: the host prints (`PREVIEW_STREAM_PDF`), the phone keeps the bytes (share sheet or download). `features.preview` in the `hello` is `true` by default (`web-host.ts`). Terminal: for a web caller `terminal:request list` is a long poll in the terminals worker (`waitMs` ≤ 1 s: held until some listed session has output past its offset or exited; each answer is cut to a 64 KB `budget`), and `lib/terminal-poll.ts` makes the next request only after xterm has parsed the last output, so the request is the acknowledgement and an idle shell costs nothing; a desktop window sends neither field and keeps its 80 ms poll. PTY size lease (`main/terminal/lease.ts`, the S11 decision): a PTY has one size, so one viewer sizes it. A lone viewer holds it implicitly, the first `resize` or an explicit `claim` takes it, typing takes it only when the holder has been idle 15 s, a holder with no request for 10 s has let go. Every snapshot carries `lease: you | other | free` and the PTY's `cols`/`rows`; a viewer that is `other` draws the PTY at those columns × rows (xterm `resize`, scrolling sideways) and neither fits nor sends `resize`, and `TerminalPanel` shows a banner (ko "다른 기기가 크기를 정하고 있어요 · 여기서 맞추기") whose button sends `claim`. The key bar (`TerminalKeyBar.tsx`, touch only, keys from `lib/terminal-keys.ts`: Esc, Tab, sticky Ctrl/Alt for the next key from the bar or the soft keyboard, repeating arrows, punctuation, ^C/^D) and the text size 50–200 % (`localStorage["omp.terminalFontScale"]`) are renderer-only. A phone's Changes view shows the unified diff only (no split toggle), and Changes and Files are a list first, then one item; both poll only while mounted and the page is visible (the panel's sheet unmounts on close). `e2e/preview-stream.e2e.ts` (a real Electron OSR page and a fake WS client; measured ~10 fps, ~107 KB a frame, ~12 % of one core busy, 0 frames idle) and `e2e/mobile-panels.e2e.ts` (the dev harness's fixture frames, terminal, git and file data; iPhone and iPad × Chromium and WebKit; `OMP_GUI_MOBILE_PANELS=<dir>` writes captures) cover it.
- Mobile web's Tailscale side (`src/main/tailscale/`; contract `src/shared/mobile-web.ts`; created in `index.ts`, pushes `mobile-web:state` to desktop windows only, handlers `mobile-web:get-state` / `mobile-web:command` on the `IpcRegistry`): `MobileWebService` (`service.ts`) derives its `MobileWebPhase` from the world on every poll tick (15 s; 2 s while Settings watches or a step waits on the user or the OS) — `tailscale status --json` and `serve status --json`, never the human text (only a `login.tailscale.com` link is taken from stderr, and `openExternal` gets only that host or the control server's). `locate.ts` finds the CLI (env `OMP_GUI_TAILSCALE`, which never falls through to a real install, pref `mobileWeb.tailscaleBin`, the macOS app binary run with `TAILSCALE_BE_CLI=1`, `/usr/local/bin`, Homebrew, login-shell PATH; Windows Program Files, PATH) and the variant (bundle id), `cli.ts` runs it through an injectable executor over `spawn.ts` (arg arrays, 10 s), `status.ts`/`serve.ts`/`whois.ts` parse with zod keeping only the needed keys. Publishing is only `serve --bg --https=<port> http://127.0.0.1:<local>/<secret>` (the per-install secret path of `web/serve-secret.ts`, the only thing that tells serve's traffic from a local process's; see the Mobile web server's threat model), from 47831 up to the first port nothing uses, recorded in pref `mobileWeb.serve` (`{host, port, target}`, `target` the local address **without** the secret, which never reaches the prefs); turning off runs `serve --https=<port> off` only when that record and the handler (one `/` proxy to exactly the current secret target, or to the bare recorded target an earlier release published for the one-time cutover: `ownProxy`; any other path on that address is the user's and is neither overwritten nor removed) still match exactly, then checks the user's other handlers are unchanged, else only the record is dropped. A handler an earlier release published without the secret is still ours and is published again over itself on the same port (`planPublish` reuses a port only when the handler already proxies to exactly the new target). There is no `serve reset` and no Funnel command in the source (`service.test.ts` greps for both); an `AllowFunnel` flag on our port is `funnelExposed` and stops the server. `allowedUsers` (pref `mobileWeb.allowedUsers`, default this computer's login) is read by the web server through `allowedUsers()`; `confirmNewDevices` (pref `mobileWeb.confirmNewDevices`, default **off**, request `set-confirm-new-devices`, `MobileWebState.confirmNewDevices`) through `confirmNewDevices()`; `whois(address)` (`tailscale whois --json <ip>`: the CLI is only ever given an IP address, read-only, 4 s, `parseWhois` keeps the stable ID, node name and owner login) answers the server's lookups while Mobile web is on. Tailscale is the optional setup item `tailscale` (`setupItemAutomatic` is false: never installed at launch or in the background pass, no once-per-launch rule, no back-off ledger; only `installForConnection` and Retry): macOS = the Standalone zip from `pkgs.tailscale.com/stable/?mode=json` plus its `.sha256`, then `codesign --verify --deep --strict`, bundle id and team `W5364U7YZB` before `ditto` to /Applications; Windows = winget, else the arch's MSI plus `.sha256` plus a Valid `Tailscale Inc.` Authenticode signature, then elevated `msiexec /qn`. A run with `snapshot.readOnly` (screenshots, `capabilities`) never waits; the first acting run takes the slot (`desktop_slot_acquire` → main grants through the `desktop_slot_bridge` command), and the session keeps it across its whole observe → act → verify span until its turn ends (`agent_end`), `DESKTOP_SLOT_IDLE_MS` (20 s) pass without a computer run, Stop, abort, tab close or crash, or the lease (`DESKTOP_SLOT_LEASE_MS`, 120 s without `desktop_slot_touch`) runs out. Waiters queue first come, first served; an acting run that had to wait does **not** run once granted: it returns `DESKTOP_SLOT_STALE_NOTICE` so the agent takes a fresh screenshot and repeats. **Handoff order:** abort the holder's in-flight input run, await stock `ComputerController.revokeControl()` on every controller the bridge saw, and only then grant the next session. **The slot is never handed on unconfirmed:** a `revokeControl()` that rejects (the bridge's `revokeControllers` fails if any controller does, and the holder's acting runs are refused with "input is blocked" meanwhile) or does not answer within `DESKTOP_SLOT_REVOKE_TIMEOUT_MS` (10 s) leaves the holder in a `revoke-failed` state (`DesktopSlotState.holder.revokeFailed`): nobody is granted, main retries the revoke every `DESKTOP_SLOT_REVOKE_RETRY_MS` (5 s; an answer that arrives late still counts), and the indicator offers "다시 시도" (`desktop_slot_retry`) and "그 세션 중지" (`desktop_slot_kill`: abort plus `restart()` of its omp, SIGTERM only). The slot is freed only by a confirmed revoke, a confirmed exit of the holder's process (the host re-reads `whenExited()` while the sidecar is ready and acts on a non-ready status only after that exit; a failed grant proves nothing and is not treated as a crash), or a kill whose process exited within 5 s (`KILL_CONFIRM_MS`); a bridge `desktop_slot_release` follows only a revoke it confirmed. Pinned by fail-first tests in `desktop-slot.test.ts`, `desktop-slot-host.test.ts` and `bridge-desktop-slot.test.ts` (rejecting revoke, revoke that never answers, holder death after a failed revoke, kill). The UI is an app-wide indicator "화면 사용 중: <title> · 대기 N" with Stop (`desktop_slot_stop`: aborts the holder's turn and hands off), and a waiting `eval` card says "화면 차례를 기다리는 중 (N번째)". Hosted tabs this computer runs for a paired device join this slot; tabs on a remote host use that host's own slot (main skips `sidecar.device` tabs). Autopilot never takes it (its `eval` is off). Not built: a "run marked done" release, because stock has no such marker; idle and turn end cover it. Pinned by `desktop-slot.test.ts`, `desktop-slot-host.test.ts`, `bridge-desktop-slot.test.ts` and `e2e/desktop-slot.e2e.ts`.

Three rules, all in `viewAfterPick`, and every way of picking a session goes through `switchTab`: ① a pane of the split on screen only takes focus, the layout stays; ② a session outside the split leaves it and shows alone, full width, and the split on screen is remembered — it never replaces or opens into a pane; ③ a member of a remembered split brings that split back exactly as it was (sessions, positions, sizes) with the picked session focused, and the split that was on screen is remembered in turn. ### Where a new feature goes

1. Stock RPC already has it (`omp://rpc.md`) → call it; add a local handler only to reshape.
2. Stock implements it (an exported function or class in `@oh-my-pi/*`, an `omp <subcommand>`) → reuse that implementation through the bridge or the CLI; never port or re-derive its rules in OMPdesk.
3. Data the GUI can get on its own (git, files, `omp <subcommand>`) → local handler in main.
4. Needs the live session → bridge method + thin local handler.
5. Needs a change inside omp → contribute upstream; never fork.

**No duplicate of stock logic.** Before adding domain logic, search the stock packages (`~/.bun/install/global/node_modules/@oh-my-pi/`) for an implementation. If one exists, call it, even when that means a bridge method, and add its internals to `capabilities.ts`. Keep an OMPdesk copy only in two cases, and say why in a comment that names the stock counterpart:
- the copy is measurably better and stock cannot be used as is;
- it must run where stock cannot: the renderer, main before omp starts, or a remote client.

A test pins such a copy to stock behaviour: it compares against the stock function where the test can import it (bridge tests on a machine with omp), and otherwise uses the same cases stock's own tests use. Two OMPdesk copies of the same logic are never acceptable; merge them into one shared module.

When an omp update breaks a bridge method, fix the method against the new internals and raise `MIN_OMP_VERSION` if the fix requires it.

## Change workflow

Changes are committed and pushed as they land, and released in small batches without waiting to be asked (the repo is public, so CI and releases cost nothing):

1. Each finished fix or feature: run its own checks (`bun run check:changed`), commit it with a normal descriptive message (no version bump, no CHANGELOG release section) and push it to `main`. ci.yml's `check` runs on the push; a red `check` is fixed before anything else lands.
2. Release when a few user-visible fixes or features have gathered, about once or twice a day, never several times an hour: every release prompts every user to update and restart. A defect in the released version that makes the app unusable ships right away on its own. No local gate: release.yml is the gate (types, biome, surface policy, vitest, `mac` and `win` packaging with `@smoke` and real-core); the full sharded Playwright suite runs alongside and is informational until it is stable on hosted runners.
3. Release with the steps below: one dated `CHANGELOG.md` section (Korean summary plus English summary) covering every commit since the last release, bump the version once, commit `release: vX.Y.Z`, push, and watch the release run to the end (rerun only the failed jobs). Tell the user when a release went out.

A release run takes about 7 minutes to `publish` (measured on v0.34.0: build 1:25, check 2:56, win 3:55, mac 4:31). Never leave an `Unreleased` section behind on `main`. Do not reinstall the local app unless the user asks — the in-app updater picks the release up.

## Release

- Version `X.Y.Z` semver; tag `vX.Y.Z`; release commit `release: vX.Y.Z`. Commit messages carry no AI attribution trailers.

Update README version mentions. Confirm `MIN_OMP_VERSION` is current.

The repo is public, so the in-app updater works without credentials (`src/main/update-auth.ts`): the release lookup and the asset download carry no Authorization header. A token is optional and only added when one is configured (`GH_TOKEN`/`GITHUB_TOKEN` → `gh auth token` → a safeStorage-encrypted token from Settings › Updates): it raises GitHub's rate limit (anonymous is 60 requests an hour per address; a check is one request every 5 minutes, 12 an hour) and keeps updates working if the repo is ever private again. A token GitHub answers 401 (expired `GH_TOKEN`, stale `gh` login) is dropped and the check retried anonymously, since 401 fails even public reads; only an anonymous request answered "not found" (the repo is private again) ends in the `auth-required` state, and a 403 with `x-ratelimit-remaining: 0` reads as a failed request, not as missing access. Each check reads the latest release (`/releases/latest`, or `/releases` with pre-releases on) through the API, and `src/main/update-release.ts` validates the metadata comment with zod against the release itself (tag = version, asset present with that size) exactly the same with or without a token. A missing or malformed comment, or one that contradicts the release, means no update and an error state ("no valid update information"); a release without this platform's file reports a missing installer. `src/main/update-provider.ts` hands electron-updater a custom provider (`setFeedURL({ provider: "custom", updateProvider })`) whose UpdateInfo points at the API asset endpoint (plus the token when there is one; `githubApiHeaders` in `updater-state.ts` builds both header sets); differential download is off (no blockmaps). Never bundle a token. Exercise it unpackaged with `OMP_DEV_UPDATE_CHECK=1 OMP_DEV_UPDATE_MODE=manual` (plus `OMP_DEV_UPDATE_PRERELEASE=1` to accept a throwaway pre-release), launching Electron on the repo root so the version is `package.json`'s. `OMP_DEV_UPDATE_MODE=relaunch OMP_DEV_UPDATE_BUNDLE=<writable copy of OMPdesk.app>` runs the relaunch path instead, staging the release against that stand-in bundle and swapping it on quit (unpackaged only).

Install modes (`src/main/updater.ts`): Windows uses electron-updater's NSIS flow (background download, SHA-512 checked, applied on restart or quit). Every macOS build, ad-hoc or certificate-signed, avoids Squirrel, which would need the ZIP the release no longer ships. When the bundle sits in a writable location it runs **relaunch** mode: download `ompdesk-mac-arm64.dmg` in the background into `<userData>/updates/ompdesk-X.Y.Z-arm64.dmg`, verify its SHA-512, `hdiutil attach -nobrowse -readonly` it, copy the `.app` out with `ditto`, detach, check the bundle's `codesign --verify --deep --strict`, bundle id and version (`stageBundleFromDmg` in `updater-state.ts`), then on "Restart & install" (or any approved quit) a detached `/bin/bash` helper (`SWAP_SCRIPT`) waits for the app to exit, swaps the bundle with rollback, and reopens it on restart. Read-only locations (DMG, App Translocation) fall back to the same DMG, verified and opened in Finder from Downloads (**manual** mode).

OMPdesk installs its own update by itself only when the user turns on Settings › Updates & about › Install updates automatically (pref `appAutoUpdate`, `APP_AUTO_UPDATE_PREF`, default off; `AppAutoUpdateRow.tsx`). Off, everything above stays as it is: check, background download, "Restart & install", applied on the click or any approved quit. On, once a verified update is downloaded and `restartableUpdate()` (relaunch mode or Windows NSIS; never the manual DMG, whose switch is disabled with the reason, `updater:installMode`), `AutoInstallScheduler` (`src/main/app-auto-update.ts`, electron-free, injected clock, ticked every second by `updater.ts`) decides: a quiet moment is no tab running a turn or compacting and no ask open (`resumeFacts`/`tabInventory`, this computer's tabs and the ones it hosts) and either every window unfocused or no user input for 2 min (`powerMonitor.getSystemIdleTime`). Still not quiet after 30 min: with Continue interrupted work (`resumeInterrupted`) on it goes ahead anyway, with it off it never forces the restart and keeps waiting for idle. It then announces the restart: `UpdateStatus.downloaded.restartAt` (epoch ms, 60 s ahead) shows one quiet line with a countdown and "Now / Later" in the sidebar update card and Settings › Updates & about — never a modal; "Later" (`updater:postpone`) postpones to the next idle window and restarts the 30 min wait. At the deadline it calls `restartIntoUpdate()` — the existing quit path (`requestQuit`/`quitAndInstall`, so drafts, layout and resume markers survive) — except that with resume off and work that started during the countdown it withdraws the notice instead of asking. Dev seams (unpackaged only): `OMP_DEV_UPDATE_STAGED` (+ `OMP_DEV_UPDATE_STAGED_VERSION`) treats a bundle as the verified staged update in relaunch mode (with `OMP_DEV_UPDATE_MODE=relaunch`, `OMP_DEV_UPDATE_BUNDLE`), `OMP_DEV_UPDATE_AUTO_COUNTDOWN_MS` shortens the countdown; `e2e/app-auto-update.e2e.ts` covers pref on (installs unclicked) and off (waits).

macOS signing: `scripts/mac-sign.cjs` (electron-builder `mac.sign`) signs every bundle with OMPdesk's own self-signed certificate, pinned by SHA-1 in `scripts/mac-signing.json`, so the designated requirement (`identifier "com.seuput.ompdesk" and certificate root = H"…"`) is the same in every release and macOS keeps its privacy grants (folders, local network, microphone) across updates; an ad-hoc signature's requirement is the build's cdhash, so each update re-asked them all. The identity comes from the repository secrets `MAC_SIGNING_P12_BASE64` / `MAC_SIGNING_PASSWORD` (release.yml sets `OMPDESK_MAC_SIGNING_REQUIRED=1` and checks the requirement), else the maintainer's local copy in `~/.ompdesk-signing/` (p12 + password; the only backup — losing it means a new certificate and one more round of prompts for every user), else an ad-hoc fallback with a warning. It is imported into a throwaway keychain passed to codesign with `--keychain`; the user's keychain search list is never touched. Never replace the certificate. Builds carry no Apple Team ID, so keychain items still bind to the cdhash (hence safeStorage stays untouched unless a stored token exists), and nothing is notarized: downloaded DMGs need right-click → Open once, locally built apps run without Gatekeeper prompts.

## Code conventions

- TypeScript: no `any`, no inline `import("…")` types, `#private` fields, Bun APIs where cleaner.
- i18n: the UI ships English and Korean only (`UI_LANGUAGES` in `src/shared/ui-language.ts`). Every user-visible string goes through `useT()` with the same key in `src/renderer/locales/en.ts` and `ko.ts` (`locales.test.ts` enforces identical key sets). Settings-schema text lives in `src/renderer/components/settings/schema-ko.ts` and `schema-option-ko.ts`; main-process strings in `src/main/i18n.ts` and `tray-labels.ts`.
- Model output renders through `MarkdownRenderer` (`src/renderer/lib/markdown.tsx`, rehype-sanitize) — never `dangerouslySetInnerHTML` with model text. Text a person typed (prompt bubbles) passes `userText`: single-dollar math stays literal and HTML tags show as typed (`remark-html-text.ts`).
- A path a reply or tool card links is never handed to `shell.openPath` when opening it would run something: `openLocalPath` (`src/main/open-path.ts`) reveals launcher types (`.app .command .sh .jar .exe .bat .cmd .ps1 .lnk .url .msi`, scripts an interpreter's install may run on open on either platform — `.py .pyw .pyz .pl .rb`, python.org's Python Launcher runs a `.py` on macOS —, the Windows script, scriptlet, shortcut, help, add-in and theme types (`.chm .xll .wsc .sct .theme .settingcontent-ms` and the like), macOS `.terminal .workflow .pkg .dmg .scpt .webloc` and the like), anything an executable bit marks on POSIX, and any symlink to either, in Finder/Explorer instead. A new caller that opens a model-supplied path goes through it.
- Tool-rendered text uses the helpers in `src/renderer/lib/format.ts`; preview ceilings come from `src/renderer/lib/preview.ts`; subprocess output renders through `AnsiText` (`src/renderer/lib/ansi.tsx`).
- Component tests use the linkedom harness (see `src/renderer/components/chat/ThinkingBlock.test.tsx`): mount through `I18nProvider`, reset zustand stores in `afterEach` via their `reset()`/setters — never `mock.module()`.
