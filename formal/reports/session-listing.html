Findings

F3 · A device keeps listing a session as held by a host tab after the tab is gone

medium fixed violated property: HeldConverges

A window on the host holds session s1; the host re-announces a change only when #listing() differs from #listingSnapshot, which every sessions.list from any device overwrites. Device d2 lists the sessions (it sees s1 held). The window's omp reports another sessionId: sidecar-pool.ts's sessionInfoUpdate handler unregisters the file (entry.sessionFile = undefined) and calls no listingChanged(), so windowSessionFiles() no longer holds s1 but nothing was announced. Device d1 reads the list in that gap: the rows say s1 is not held and the host records that listing as its snapshot. The tab then closes: #releaseEntry notifies, listingChanged() finds the listing equal to d1's snapshot and sends nothing. Device d2 keeps the row as held on the host until something else makes it read again (a journal change, a reconnect). The same device with its two feeds (local and global scope) is enough: the snapshot is shared by every read.

Abstracted

  • two devices, one window tab, one hosted tab opened by the window tab, two sessions, at most 3 host changes; a device's two feeds are two devices
  • only the overlay the property is about (heldOnHost, openedBySession): the index rows are not modeled

Out of scope

  • deleting and renaming sessions, the snapshot cache, several windows of one device
