F1 · A new tab whose omp crashed before naming its session could come back on another conversation

low fixed violated property: NeverAnother

A new tab starts: its omp boots on a new session (n1). The ready frame clears #isNew (a10eb6877 did it in #handleReady). The omp crashes before the ready status's get_state answer reaches #observeResponse, so #sessionPath is still empty. The crash restart's sessionOpen then sees no session and a tab that is not new, and passes neither --session nor --config fresh-launch.yml: with the person's autoResume on, stock reopens the folder's most recent session (s1) in the tab that showed a new one. Fix: #isNew is cleared where get_state names the session, not at ready.

F2 · An omp that crashed right after an in-tab switch_session or new_session came back on the session before it

low fixed violated property: NeverAnother

A tab is on session s1. The person starts a new session in it (new_session) or opens another one in the same tab (switch_session). Stock's answer names no file, so #sessionPath stays s1 until the next get_state; the pool already shows the switched-to session. The omp crashes before that get_state: the crash restart reopens s1, and the tab silently goes back to the conversation the person left (after new_session: the old one instead of the new empty one). Fix: #observeResponse takes switch_session's requested path, and after new_session clears the path and marks the tab new, so the restart starts a new session.

Model scope and assumptions

Modeled

  • sessionOpen and #spawn
  • ready
  • the ready status's get_state answer
  • crash restart
  • restart with no session, a stored session, another folder
  • stock writing a session and its autoResume (environment)
  • the start gate's restart into a worktree
  • switch_session and new_session inside the running omp

Abstracted

  • one tab, one folder
  • the pool's view of the session is the ghost `shown`
  • an omp update's restart is Restart

Out of scope

  • session ownership wait
  • start gate
  • remote tabs
  • extensions and settings of a spawn
  • fork/branch/handoff inside a running omp (A5)

Assumptions

  • A1: start()'s awaits do not change #sessionPath or #isNew
  • A2: get_state names the session the running omp is on
  • A3: autoResume picks only a written session of the folder
  • A4: the pool's sessionFile equals #sessionPath after the same get_state
  • A5: a fork, branch or handoff keeps #sessionPath on its parent until get_state names the copy; a crash in between reopens the parent, which is written and intact
