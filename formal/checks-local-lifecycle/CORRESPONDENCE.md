# Correspondence: ChecksLocalLifecycle

| Model | Implementation | Boundary |
|---|---|---|
| `Admit`, `Refuse`, `TogglePause` | `checks/hub_local.rs` `Core::run_here`; `checks/hub.rs` `Core::pause`. | Admission's pause read is the model's linearization point. A pause arriving after that read does not retroactively refuse an accepted request. |
| `TakeA`, `TakeCoreB` | `checks/local_run.rs` `CheckRunner::checkout_lock`, `LocalRunner::run`. | A and B are OS file locks for the actual checkout path. Each acquisition is a separate action. |
| `Reserve`, `DamageEpoch`, `FailEpoch` | `checks/local_run.rs` epoch read, increment and `disk::tree::write_atomic_if` under B. | The atomic replacement is modeled as one step; a damaged or unexpectedly missing existing epoch fails closed. The model does not introduce a reservation journal. |
| `Launch`, `TakeWorkerB`, `BeginWork`, `RejectStale` | `checks/local_run.rs` `git_step`, `guarded_command`, `setup` and check spawn; `checks/src/check.rs` `checkout_guard`, `guarded_setup`, `start`, `run_runner`. | A spawned child and its later B acquisition are separate actions. Its captured epoch must match; setup and check also validate SHA. A Git child represents one command, not the whole checkout sequence. |
| `ObserveId`, `RequestCancel`, `SendCancel`, `CancelWaiting` | `checks/local_run.rs` `run_id_of` and the stderr/cancel loop; `checks/src/check.rs` `checkout_guard` and cancellation file. | The id can arrive after the request is cancelled. Cancellation can remain pending; no fairness is assumed. |
| `BeginCleanup`, `EndCleanup` | `checks/src/check.rs` `guarded_setup`, `stop_tree`, `run_runner`; `checks/local_run.rs` `await_checkout_idle`. | Cleanup is explicit and B remains held until its end. This abstracts process-tree termination and is conditional on the OS containment limitation in SCOPE. |
| `ReturnCancelled` | `checks/local_run.rs` waits for the child and active journal; `checks/hub_local.rs` `run_here` cancels the child scope and joins its future. | The request cannot return while the modeled child is pending, active, or cleaning up. |
| `Stop`, `Crash` | `checks/hub.rs` `Hub::drop`; `CheckRunner::guarded_command` starts the B-owning supervisor outside the POSIX core group. | Core group death closes supervisor stdin, so it joins its child cleanup while retaining B. The actual core-group-kill regression observes the cleanup barrier and B exclusion. A separately killed supervisor remains excluded. |
| `PrepareFallback`, `Fallback` | `checks/hub_local.rs` `fall_back`; root-owned `checks/hub.rs` admission/pump/dispatch stop fence. | The model separates preparation from the network write so a stop may interleave. The source fence must be checked after the root's changes land; `fall_back`'s initial check alone is insufficient. |

`TypeOK` checks the finite shapes. Sticky bad-event fields encode action properties as invariants so mutations can remove one guard without changing a frozen property. Worker identities stand for distinct requested commits. The model promises no recovery from an unavailable or damaged epoch. Local SANY and the first two-worker runner baseline passed; the full matrix/mutation set has no passing verdict yet. The `core-group-kills-b-owning-supervisor` mutation releases B during surviving child work and was detected as `NoCheckoutOverlap`.

`WorkerBusyInit` is a targeted reachable prefix, not a new production transition. Epoch 1 launches a delayed starter and crashes; epoch 2 starts active work and crashes; epoch 3 has acquired A but not B. Under the unchanged B guard it cannot overlap epoch 2. Removing only the worker-B guard first lets the stale epoch-1 worker replace and release epoch 2's lock; a third worker can then overlap it. Two workers alone did not expose that mutation because generation fencing rejected the delayed worker. The full three-worker initial-state run remains in the matrix.
