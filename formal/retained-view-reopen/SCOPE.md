# Retained execution reopen scope

Status: draft. No parse, TLC, mutation run, source test, build, or stamp has been run by the model author. The parent owns manifest integration, a SANY parse, and hosted formal execution. The model and its source correspondence must not be described as verified.

The scenario starts immediately after attachment A closed while one busy execution and one saved identity remain. The execution has zero views and no visible `ControlTab`. A is retired and its first close is still awaiting a result. A normal reopen may attach B to the same execution. Two attachment tokens, A and B, distinguish views with the same tab ID. There is one saved path and one retained execution. The join mode varies exact path, current runtime, hidden status, and control permission independently.

The list mode has two independent read slots. A read captures its result and revision before its await, and finishes afterward. A result may contain old A while B is absent. The close mode has the pending A close and at most one B close. A failed close has separate pre-reconcile and post-reconcile actions, so B can be adopted and closed while A's reconcile waits. The frame mode sends one delayed A starting frame or a frame with missing metadata after B is adopted. The four modes are separate state spaces, not a combined end-to-end interleaving. No fairness or liveness property is claimed.

The model excludes OS process behavior, disk durability, actual path canonicalization, transport and network failure, stock or omp internals, real permission revocation during an await, other saved identities and devices, extra views, and full close rollback UI reconstruction. It abstracts the underlying execution as permanently busy unless erroneous cleanup stops it. It does not model arbitrary incoming frames or prove metadata exists in production.

The full-stream frame metadata boundary and native web coalescer handoff are approved. The coalescer fix remains pending the reported RED 43581965514. Strict TypeScript producers include native hidden-plan events, synthetic mode and name events, and desktop broadcasts. The phone consumer's serialized frame is abstracted as an immutable token or missing token, not a model of the entire transport. Missing metadata produces an explicit protocol error without an older-peer fallback. Correspondence to the model remains pending formal execution. The native join and source mapping remain subject to review against the final candidate. The relay exact-close model addresses a different protocol and does not establish these consumer properties.
