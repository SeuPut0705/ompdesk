# Frozen properties: session listing

Protocol-level: any correct implementation of "a device's list follows the host's list" must hold them. They are defined next to the model in `tla/SessionListing.tla` (a TLA+ property needs the model's variables, so it cannot live in a separate module without a refinement mapping; see the skill gaps in `formal/findings.json`). Do not weaken or drop one without the user's explicit OK; a change is reported as a model change.

| Name | Statement | Source |
|---|---|---|
| `HeldConverges` | Whenever nothing is in flight (no pending read, request, reply, event, debounce, retry, link drop or id-change handoff), every window's rows say `heldOnHost` for exactly the listed sessions a tab on the host holds. | `src/shared/ipc-types.ts:1773-1778` (`heldOnHost`: "a tab on that host holds [the session]"), `src/main/remote/host-services.ts:1327-1331` (listingChanged doc: "the devices read the list again when that changed what their last read said, since no journal moved"), the existing test `host-services.test.ts` "tells devices to read the list again when a tab here takes or lets go of a session, and only then". |
| `OpenersConverge` | Under the same condition, every window's `openedBySession` equals the host's opener map (tab opener files and the closed-child record) for the listed sessions. | `src/shared/ipc-types.ts:1760-1766` (`openedBySession`), `host-services.ts:1364-1368` (`#listing`), `host-services.test.ts` "names who opened each session it lists to a device". |
| `ListConverges` | Under the same condition, every window's rows equal the host's list: a row exactly for each session the index lists (so a delete, a move and a rename show), with its `heldOnHost` and `openedBySession`. | `src/main/session-list-share.ts:1-8` ("a change reads the list once, numbers it, and hands on what changed"), `src/shared/session-list-delta.ts:1-6` ("asks for the whole list only when it holds no copy or missed a change"), `host-session-list.test.ts`, `session-lists-report.test.ts`. |
| `NoReappear` | A session the host deleted (or moved away) that a receiver's copy dropped never comes back in that copy: not in the paired computer's copy of the host's list (`goneD`), not in a window's numbered copy (`goneF`). | `src/main/session-index.ts:164-175` ("A file a stray writer put back after its session was deleted is not that session coming back"), `src/renderer/stores/session-list.ts:255-273` (a delete drops the row from every list of the device). |
| `SameVersionSameRows` | A copy that holds the version the host (or the computer's copy) numbered holds the rows of that version: a change was never applied against another base. | `src/shared/session-list-delta.ts:1-6`, `host-session-list.ts:59-62` ("a change of the version the copy holds is applied here; anything else ... is read once"), `session-list.ts:129-132`. |
| `FreshAfterRequest` | The ask a window makes after a delete, rename or move through a paired host shows what that request did: not the copy from before it, whatever other changes were applied in between. | `src/main/ipc.ts:472-484` ("The deleter reads the list next: from the host, not this computer's copy from before"), `:1458-1463` (rename: "the next read of the list (the renamer's own) reads it, not the copy before"), `devices.ts:561-564`. |
| `OneAsk` | A read of the host under way is the window's ask: a window never has two asks at its computer's copy. A check of the model's assumption A4, not a promise of the code. | `session-list.ts:164-170` (`inFlight`, `queued`). |
| `TypeOK` | Shape of the model's variables. Waived in the mutation set (shape only). | model |

Sanity (must FAIL, in `matrix.json`): `NeverHeld`, `NeverOpener`, `NeverGone`: a window can show a held row and an opener row and a copy can drop a deleted session, so the convergence properties are not vacuous. `NoHslApply`, `NoHslGap`, `NoHslNote`, `NoFeedApply`, `NoFeedGap`, `NoFeedNote`, `NoFeedRaced` (run with `Track = TRUE`): each branch of the two receivers' guard (apply at the held version, a change it cannot apply, a change named during a read, an answer older than a named version) is reachable, so the mutations that break them have something to break.

Model toggles (constants, not properties): `LinkMode` ("fifo": the host's messages reach a computer in the order they were sent, which one counted encrypted socket guarantees; "gap": a later event may pass a reply), `IpcMode` ("free": events in order, a reply at any position between a computer and its windows). `LinkMode = "gap"` is a run that is expected to fail `ListConverges` (matrix `link-reorder-regresses-hsl`): it records what a reordering link would do (F5), and it is not a promise of the code.

## Model changes

- 30 Oct 2026, with the delta path (`b53551176`): the model followed the code from "a device reads an overlay value after each event" to the numbered copies and changes. `HeldConverges` and `OpenersConverge` keep their promise but are now stated on rows: `Held(file)` became the listed sessions a tab holds (the same set while every session is listed, which the `MC.cfg` runs keep), and a window's `view` became the rows it shows. `Ordered` became `LinkMode` and `IpcMode`; `IdChangeAnnounces` stayed gone (F3). `ListConverges`, `NoReappear`, `SameVersionSameRows`, `FreshAfterRequest` and `OneAsk` are new; no property was weakened. `NoReappear` is stated on the receivers' copies, not on the window's optimistic view of its own delete (F6): the view is held to `ListConverges` once events settle.
- 28 Oct 2026: the F3 toggle `IdChangeAnnounces` is gone: the pool announces every take and let-go of a session file (`SidecarPool.onSessionFilesChanged` → `LocalHostServices.listingChanged`), so `IdChange` always announces; the bug stays as the mutation `id-change-silent` (breaks `HeldConverges`). No property changed.
