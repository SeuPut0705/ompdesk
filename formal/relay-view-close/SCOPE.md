# Relay exact view close

Status: draft, not checked, not an acceptance result. `syncCommit` is null. The candidate source is 9deb production plus the comment-only c3338 change, identified as at64616b0d7 in the assignment. Any later production change requires a new correspondence review.

The bounded scenario has two view identities, two generations, one source caller, one native receipt and one close request. It abstracts host, window, tab and saved identity into a view atom and keeps incarnation separately. Two generations distinguish a replaced attachment from the original. `Expire` represents crossing the native 30-second deadline without a real clock. No state count, trace or passing result has been measured.

The target is a close-only request, not deletion of the saved session or termination of its execution. It checks safety rather than liveness. It does not model semantic authorization decisions, cryptographic randomness, network authentication, OS durability, arbitrary failures, every renderer, or saved-session deletion. In particular, it does not establish the user's exact resurrection target.

The model represents target core generation independently from view incarnation, with two values for each. It includes adversarial final nonce and view responses, receipt replay attempts, source snapshot changes across modeled awaits, unsafe target facts, and commit replay after target core loss. A failed synchronous hub call permits either an applied or unapplied commit, reports an unknown outcome and ends the request without replay. Upstream send, hosted exit and local exact exit are distinct from finishing effects. A protected remaining view or run does not wait for the selected execution to exit. The selected last idle execution may exit; `runAlive` describes the other execution. Mutations describe observable damage to that execution, its saved record, or its view, but have not run. Local exit capture and failure propagation now exist in the working tree, but any subsequent source change requires correspondence review before stamping. The provenance answer is abstract and authenticated caller binding is assumed. Individual local effects and their internal awaits are aggregated. OS persistence internals and initial-challenge forgery are outside the model.

No test, parse, TLC, mutation or build was run by the model author. The parent reported one failed SANY parse for the subset relation and the model author corrected it; the corrected model has not been parsed here. The parent owns manifest integration, the verify skill, and GitHub matrix and mutation runs. Trace validation against the real code remains required before a counterexample can be called a bug.
