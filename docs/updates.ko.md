# 업데이트

[English](updates.md) · [README로 돌아가기](../README.ko.md)

모든 것이 스스로 업데이트돼요. 계정은 필요 없어요.

## OMPdesk

앱 메뉴의 **업데이트 확인…** 또는 **설정 › 업데이트 및 정보**에서 받아요. macOS는 응용 프로그램 폴더처럼 쓰기 가능한 위치에 설치해 두면 재시작만으로 업데이트돼요.

**다시 열 때 중단된 작업 이어서 하기**(기본값 켜짐)가 켜져 있으면 업데이트로 재시작할 때 묻지 않고, 실행 중인 작업이 업데이트 뒤 첫 실행에서 이어져요. 꺼져 있으면 작업이 있을 때 확인 창이 먼저 떠요.

설치가 시작되면(**재시작 및 설치**, 또는 자동 설치 알림의 **지금**) 사이드바와 설정에 **X 업데이트 설치 중…**이 뜨고 버튼은 멈춰요. OMPdesk가 저절로 닫히고 업데이트를 설치한 뒤 다시 열리며, 한 번 더 눌러도 아무 일도 일어나지 않아요. Windows에서는 새 설치 파일을 검사하느라 설치 프로그램이 시작되기까지 몇 초 걸릴 수 있는데, 그동안에도 창은 멈추지 않아요.

**업데이트 자동 설치**(설정 › 업데이트 및 정보, 기본값 켜짐)는 받아 둔 업데이트를 알아서 설치하고 다시 시작해요. **다시 열 때 중단된 작업 이어서 하기**가 켜져 있으면 답을 기다리는 질문이나 승인이 없고 압축 중이 아닐 때 바로 다시 시작하고, 실행 중이던 작업은 다시 열린 뒤 이어져요. 그 설정이 꺼져 있거나 **나중에**를 누르면 한가한 때를 기다려요. 작업(턴)이 도는 탭이 없고, 답을 기다리는 질문도 없고, 창이 포커스를 잃었거나 2분 동안 입력이 없을 때예요. 다시 시작하기 1분 전에 사이드바와 설정에 조용한 한 줄로 알려 주고 **지금** / **나중에**를 고를 수 있어요. 대화상자는 뜨지 않아요. 작성 중인 글과 화면 배치는 다른 재시작처럼 그대로 돌아와요. 읽기 전용 위치나 App Translocation처럼 OMPdesk가 스스로 교체할 수 없는 곳에서는 스위치가 꺼진 채 이유를 알려 줘요. 앱을 응용 프로그램 폴더로 옮겨 주세요.

GitHub 계정이나 토큰 없이 받을 수 있어요. 저장소가 공개라서 앱이 GitHub 릴리스를 바로 읽고, 내려받은 파일은 릴리스 메타데이터의 SHA-512와 맞는지 확인해요.

GitHub 요청 한도에 자주 걸리면 **선택 사항**으로 토큰을 줄 수 있어요. 토큰은 한도만 늘려 주고, 없어도 업데이트는 동작해요. 위에서부터 차례로 찾아 써요.

1. 환경 변수 `GH_TOKEN` 또는 `GITHUB_TOKEN`
2. GitHub CLI 로그인 (`gh auth login`)
3. **설정 › 업데이트 및 정보**의 **GitHub 토큰(선택)** 칸에 저장한 [토큰](https://github.com/settings/tokens). 토큰은 OS의 안전한 저장소로 암호화해 보관해요.

## omp

omp는 스스로 업데이트해요. OMPdesk를 켜 두는 동안 npm의 최신 `@oh-my-pi/pi-coding-agent`를 실행할 때와 그 뒤 4시간마다 확인하고, 더 새로운 버전이 있으면 백그라운드에서 `omp update`를 실행해요.

- **하던 일은 끊기지 않아요.** 실행 중인 omp는 이미 불러온 코드를 그대로 쓰기 때문에 작업 중인 세션도 계속 돌아가요. 쉬고 있는 탭은 새 omp로 바로 다시 시작하고, 작업 중인 탭은 그 작업이 끝난 뒤 다시 시작해요. 세션 기록과 입력 중인 글은 그대로 남아요.
- **조용히 알려요.** 끝나면 "omp를 업데이트했어요" 알림이 한 번 떠요. 새 omp에서 OMPdesk의 어떤 기능이 지원되지 않으면 그 기능 이름과 함께 경고가 떠요.
- **실패하면** 이유가 **설정 › 업데이트 및 정보 › 이 컴퓨터**에 남고 다음 확인 때 다시 시도해요. 네트워크 오류가 이어지면 확인 간격을 늘려요. Windows는 실행 중인 omp의 파일이 잠겨 있으면 설치가 실패할 수 있고, 이때도 다음 확인 때 다시 시도해요.
- **끄거나 직접 실행하려면** 같은 곳의 **도구 최신으로 유지** 스위치(기본값 켜짐, omp·도구 CLI·확장을 함께 다뤄요)와 **지금 업데이트** 버튼을 쓰세요. 터미널에서 `omp update`를 실행해도 돼요.
- **원격 기기는 각자 업데이트해요.** 연결한 컴퓨터의 omp는 그 컴퓨터의 OMPdesk가 자기 설정에 따라 업데이트하고, 이 컴퓨터가 다른 기기의 omp를 업데이트하지 않아요.
- 개발 실행과 테스트 실행은 자동으로 업데이트하지 않아요.

## 도구 CLI

연결한 계정의 명령줄 도구(Claude Code, Codex CLI, Gemini CLI, Cursor Agent, GitHub Copilot CLI, GitHub CLI)와 OMPdesk가 설치한 Node.js도 스스로 최신으로 유지해요. 실행할 때와 그 뒤 4시간마다 확인해요.

- **설치된 것만 업데이트해요.** 새로 설치하지 않고, 관리자 권한도 쓰지 않아요. 운영체제가 관리하는 사본, 다른 앱 안에 들어 있는 사본, 관리자만 쓸 수 있는 폴더의 사본은 그대로 둬요. 다른 방식으로 설치한 사본(버전 관리자, 직접 놓아 둔 것)은 건드리지 않는 이유와 함께 목록에 보여요.
- **그 도구를 관리하는 방식으로 업데이트해요.** 자체 업데이터, npm 또는 Bun, Homebrew, winget, OMPdesk 도구 폴더 중 하나예요. 실행 중인 도구는 종료한 뒤 다음 확인 때 업데이트해요.
- **끄거나 직접 실행하려면** **설정 › 업데이트 및 정보 › 이 컴퓨터**의 **도구 최신으로 유지** 스위치(기본값 켜짐)와 도구별 **지금 업데이트** 버튼을 쓰세요. 실패한 이유도 거기에 남고 다음 확인 때 다시 시도해요.
- **원격 기기는 각자 업데이트해요.**

## 플러그인·마켓플레이스·스킬·MCP 서버

omp가 불러오는 확장도 스스로 최신으로 유지해요. OMPdesk를 켜 두는 동안 실행할 때와 그 뒤 4시간마다 확인해요. 설치된 것만 업데이트하고, 새로 설치하거나 설정 파일을 고치지는 않아요.

- **마켓플레이스**는 카탈로그를 새로 받아요. **플러그인**은 마켓플레이스나 npm·git으로 설치한 것이 대상이고, 새 버전이 있으면 omp의 업그레이드 방식 그대로 올려요.
- **고정한 버전은 건드리지 않아요.** npm 플러그인을 `pkg@1.2.3`처럼 정확한 버전이나 범위로 설치했거나, git 플러그인이 커밋·버전 태그에 묶여 있거나, MCP 서버가 `pkg@1.2.3`으로 실행되면 새 버전이 있는지만 알려 주고 그대로 둬요. 로컬 폴더에 연결한 플러그인도 그대로 둬요.
- **스킬**은 스킬 레지스트리에서 설치한 것만 업데이트해요. 플러그인이 주는 스킬은 그 플러그인을 따라가고, 그냥 로컬 파일은 "로컬, 업데이트 안 함"으로 보여 줘요. 스크립트가 들어 있는 새 버전은 직접 허락해야 해서 자동으로 설치하지 않아요.
- **MCP 서버**: 버전을 정하지 않은 `npx`·`bunx`·`uvx` 패키지는 시작할 때마다 최신을 받아서 따로 할 일이 없어요. `npm`·`bun`·`brew`·`pipx`·`uv`·`pip`로 전역 설치한 실행 파일은 설치한 도구로 업데이트하고, 시스템·관리자 권한이 필요한 설치는 건드리지 않아요. 내장 REA는 OMPdesk 버전에 맞춰 고정돼 있어요. MCP 설정 파일은 OMPdesk가 수정하지 않아요.
- **하던 일은 끊기지 않아요.** 쉬고 있는 탭은 바로 `/reload-plugins`와 같은 방식으로 다시 불러오고, 작업 중인 탭은 그 턴이 끝난 뒤에 해요. 실행 중인 MCP 서버의 파일을 바꾸면 깨질 수 있는 업데이트는 서버가 멈출 때까지 미뤄요.
- **끄거나 직접 실행하려면** **설정 › 업데이트 및 정보 › 이 컴퓨터 › 확장**의 **도구 최신으로 유지** 스위치(기본값 켜짐)와 항목별 **지금 업데이트** 버튼을 쓰세요. 실패한 이유와 건너뛴 이유도 거기에 남아요.
- **원격 기기는 각자 업데이트해요.**
